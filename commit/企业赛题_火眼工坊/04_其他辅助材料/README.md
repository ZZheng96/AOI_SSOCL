# 其他辅助材料说明

本压缩包为"可自学习的AOI实时在线AI质检系统"的辅助材料，按"**一主干一树枝 + 复现包**"三层组织：

| 路径 | 定位 | 内容 |
|------|------|------|
| `code/AOI_Core/` | **参赛主系统** | 反馈驱动的 AI 质检原型：PySide6 桌面端 + FastAPI 后端 + SQLite + Docker |
| `code/PCB_Dual/` | **工程扩展原型** | 传统 CV 资产接入与双引擎编排；算法目录按六组登记，SPC/CAD/双坐标为本地实现，MES 为 Mock 网关 |
| `code/research/` | **算法复现包** | 算法研究源码、实验脚本与配置、关键结果 JSON、设计文档；用于核查本地实验，不替代官方隐藏测试集评分 |

> **系统运行截图**：`code/AOI_Core/tests/_wo1_shots/` 保存了一次完整工单流程（建单→备模→检测→反馈→学习→回队）的桌面实录截图，与项目文档 §3.2.13 图3-图8 一一对应。

## 复现环境与材料边界

### 环境与安装

- **桌面端 / 本机后端**：Windows 10/11 或主流 Linux，推荐 Python 3.10/3.11；依赖最低版本见各目录 `requirements.txt`。建议创建独立虚拟环境后，在目标目录执行 `pip install -r requirements.txt`。PyTorch 需按本机 CPU 或 CUDA 版本选用官方匹配轮子；主要 GPU 实测环境为 GTX 1660 SUPER，未配 GPU 时使用 CPU 降配工作点。
- **Docker 后端**：进入 `code/AOI_Core/` 执行 `docker compose up -d`。Compose 默认仅将后端发布到宿主机 `127.0.0.1:8017`，避免无鉴权接口直接暴露到局域网或公网；如需远程工位接入，应先配置鉴权与防火墙/反向代理，再显式修改端口绑定。现有 Dockerfile 基于 Python 3.11、默认安装 CPU 版 PyTorch，且只启动 FastAPI 后端，不包含 PySide6 桌面界面；GPU 容器部署需自行改用匹配的 CUDA/NVIDIA 运行时。
- **算法实验**：进入 `code/research/` 安装其 `requirements.txt` 后运行脚本。包内依赖文件给出最低版本而非完全锁定环境，因此不同 PyTorch/CUDA 或硬件组合的末位指标和耗时可能略有差异。
- **离线权重**：提交材料已包含 DINOv2 ViT-S/14 主干权重及实验所需的判别头/分类器等关键权重，默认无需首次联网下载；只有权重缺失、主动更换模型或重新取得第三方资产时才需要联网。依赖安装本身仍需可用的软件源或预先准备的离线轮子。

### 包内可核查与包外数据

| 材料 | 是否随包 | 复现边界 |
|---|---|---|
| 系统/算法源码、配置、关键结果 JSON、关键权重 | 是 | 可离线审查实现、配置和既有结果；安装依赖后可启动系统并执行不依赖完整数据集的接口/冒烟检查 |
| PCB 模板、测试/联调图及部分结果图 | 少量随包 | 仅用于作品演示、接口联调、冒烟或小样本基线，不构成公开数据集，也不代表完整指标数据 |
| MVTec AD、BTAD、MPDD、GYU-DET | 否 | 公开数据集体量较大且受各自原始许可/下载条款约束，不在本提交包中再分发；完整指标复跑须由复现者从官方渠道取得并按脚本约定配置路径 |
| 完整 `data_local` | 否 | 团队自建工业场景数据涉及原始采集图与使用范围，未随包公开；依赖该数据的命令不能仅凭提交包完成全量重跑 |

因此，本包所称“可复现”是指代码、配置、协议、必要权重与结果证据可核查，并不表示全部原始数据随包提供。缺少包外数据时，仍可检查源码、数据隔离逻辑、配置、结果 JSON、权重清单、运行截图和包内小样本冒烟；MVTec/BTAD/MPDD/GYU-DET 或 `data_local` 的完整精度复测须先合法取得对应数据。

## AOI_Core（主干系统）

- **四源实时监控**：上传 / 图库 / 视频 / RTSP 逐帧检测
- **数据集适配（2026-08-31）**：非标准数据集自动识别（MVTec/BTAD/MPDD/GYU-DET/data_local/test_images 的 OK/NG/模板/良品/误报 等约定）→ 确认弹窗 → 批量入库；识别结论自动回写数据源声明与工单数据条件（`backend/core/dataset_adapter.py` + `docs/数据条件与数据集适配指南.md` §7）
- **人工反馈驱动的受控更新**：三类反馈可进入样例库、重校准或候选小步更新，并配套独立评估、版本管理、审计与回滚；不承诺每次反馈即时改善
- **产线能力**：API 鉴权（operator/engineer/admin 三角色）、PLC 触发、缺陷自动归档、产线日报 / 审计导出、对位偏移预警、工作台首页、新建品类向导
- **数据生命周期管理**：`tools/cleanup_data.py` + `docs/数据生命周期与清理策略.md`
- **启动**：`pip install -r requirements.txt` → `python main.py`（单机一体）；或 `docker compose up -d`（产线后端）；详见 `docs/用户手册.md`
- **文档定位**：`docs/用户手册.md`（面向用户/评委的完整操作手册）为主入口；`docs/重构设计_*.md`、`docs/UI审计报告.md`、`docs/首用质检发现_*.md` 为**研发过程文档**（架构决策记录与实测发现，供追溯，非交付承诺）

## PCB_Dual（树枝系统）

- 传统 CV 算法仓库按六组登记多个检测项；当前仅 SMT、金手指少量带 GT 样本形成量化基线，其余“可注册/可运行”不表述为已通过 20 项准确率验证
- 可调用特征引擎与追溯接口；SPC/CAD/双坐标为本地实现，MES 仅 Mock 出站 JSON，尚无真实 MES 协议或外部系统联调证据
- **启动**：`pip install -r requirements.txt` → `python main.py`；详见 `README.md`、`docs/架构与设计.md`

## 关键实测指标（无泄漏口径，详见 research/docs）

- MVTec AD 平均 AUROC **0.9793**（15 品类全部 ≥0.9，U99 决策阈值修复）
- BTAD **0.9609** / MPDD **0.9851**（全部品类 ≥0.9）
- **五类缺陷归因**（U96 有监督判别器，跨品类 508 张 init_defect 训练）：缺件 0.857 / 色彩 0.750 / 尺寸 0.787 / 逻辑 0.562 / 外观 0.836
- **跨域在线学习**：0.60 → 0.72（大锚定诚实口径，U121 拦截伪框化）
- **L3 模板覆盖实验（额外数据条件，不纳入官方默认协议成绩）**：gold_finger AUROC 1.0000（17 张）、latency p50=484ms 使用了包含 `test/good` 的模板库，模板与评测正常样本同源，只能视为闭集覆盖实验；仅用隔离的 `train/good` 68 张模板时 AUROC 为 0.27。不得以 1.0000 证明无模板跨域泛化、官方准确率或“金手指已解决”
- **反馈更新实验**：screw 在特定多轮实验中由 0.878 提升到 0.938，但末轮略有回落；另有 MPDD bracket_brown −0.3422 等负增益记录，因此不概括为所有品类单调提升
- **鲁棒性 TTA 三维修复**：平移 / 光照 / 亮度误报显著下降、扰动下漏检归零（U100/U101/U104）
- 速度：算法推理 2500² GPU 模型段 **p50 58 / mean 102 / p95 183ms**（n=30 复测 2026-08-31，`research/outputs/m0/bench_2500_fast.json`，<200ms 达标）；CPU 降配 e2e mean 351ms / p95 368ms（n=15，`bench_2500_cpu.json`，<2s 达标）；可训练参数 **<0.5M**（DINOv2 22M 主干永冻）
- **系统级本地实测（`docs/用户手册.md` + `test/results/`）**：MPDD 1346 图实验完成，所测品类 AUROC 0.974-1.000、引擎段 mean 162ms；4096×3000 零拷贝串行 e2e mean 131 / p95 172 / max 224ms，磁盘路径 mean 292 / p95 333 / max 483ms。4 并发 800 次的服务内部处理统计为 p95 344 / max 560ms，但客户端含排队墙钟为 p95 597 / max 1740ms，已出现 >1s 请求；并发仅作工程观察，正式演示采用串行/限流，不作为官方单图检测时间证据
- 同协议 SOTA 复测：本系统 0.9441 vs EfficientAD-fs 0.8748（+0.069）、PatchCore-fs 0.9514（同级，`research/scripts/sota_compare/`）

## 官方评分对账与验证边界

- **方案完整度 50%**：以 AOI_Core 可运行流程、反馈/回滚/追溯和提交材料为证；PCB_Dual、Mock MES 不表述为已完成真实产线集成
- **准确率 20%**：最终只认官方测试集结果；本地公开数据与同协议复测是预估证据，L3 模板实验和 20 项注册数不计入
- **检测时间 30%**：主报 2500² 模型运行口径，同时披露端到端与排队墙钟；并发压测不替代官方单图计时
- 代码级数据隔离断言：test 域路径 / 未声明元信息进入拟合流程即报错
- 子集 / 参数选择在独立验证集，test 只验不选
- 全部指标无泄漏口径，阴性结果在设计文档中如实登记
