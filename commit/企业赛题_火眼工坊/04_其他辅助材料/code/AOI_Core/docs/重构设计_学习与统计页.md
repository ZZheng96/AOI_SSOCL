# 重构设计：学习效果页与统计报表页（2026-08-30）

> 起源：用户要求「从 algo 出发评估学习曲线/统计报表两页是否合理并重新设计」，
> 随后按建议全部实施。本文档记录问题诊断、重设计方案与实施要点，
> 供后续改进参考。

## 一、问题诊断（改造前）

### 学习曲线页
1. **主次颠倒**：离线模拟（回放）占主 Tab，真实在线学习证据在配角位。
2. **在线判对率是有偏指标**：反馈样本由操作员选样（偏向难例/误判例），
   反馈越多"判对率"越低，产生"越学越差"假象——不能直接当学习效果。
3. **后端只调单轮流 `simulate_learning`**：反馈锁死 ~53 条即饱和、早期饱和；
   algo 已有的多轮版 `simulate_learning_rounds`（U67/U68）未暴露到 API。
4. **贡献档案只展示 ablation 一层**：algo 产出 univariate（槽位×缺陷类型 AUROC）
   与 redundancy（Spearman 相关矩阵）被丢弃。
5. **权重只有静态快照**：无演化曲线，多层门控（U106-U110）的否决事件不可见。
6. **裸暴露调参旋钮**给最终用户（n_stream/eval_every/feedback_ratio 等）。

### 统计报表页
1. **口径错误**：按"今日+品类"统计，而前端反馈.txt 明确要求**工单口径**
   （后端 `_scope_categories` 已支持 workorder_id，前端没接）。
2. **用"系统判定"口径**：复核后的真值（Feedback.operator_label）零利用，
   StatsDaily 已累积的 FP/FN 不展示——用户看不到"误报率/漏检率"。
3. **algo 每图产出的灰区/open_alert/align_warn/缺陷类型信号零利用**。
4. **无缺陷帕累托、无批次对比**。
5. **操作日志占半页**：审计功能混在生产报表里。

## 二、重设计方案

### 学习效果页：三层证据结构
| 层 | 回答的问题 | 证据 |
|---|---|---|
| 学过就会 | 反馈过的样本学会了吗 | 翻案曲线（自反馈页迁入）+ 已反馈重测 acc |
| 举一反三 | 没见过的样本也变准了吗 | 多轮回放锚定集 AUROC + **不学习基线**（定义性：不学习=模型不变=AUROC 恒为初始值，零成本对照） |
| 线上生效 | 生产上误判在减少吗 | 误判率趋势（复核口径 FP/FN 率）+ 权重演化（含门控否决事件标记） |

- Tab1「线上学习证据」（默认）：KPI（翻案率/错检数/最新日误判率/权重学习
  通过/否决）+ 2x2 图（翻案曲线、误判率趋势、权重演化、滚动判对率——
  保留但附"选择偏差"提示文案，不再当主指标）。
- Tab2「离线回放验证」：预设档位代替裸旋钮——
  `快速(3轮×15) / 标准(4轮×25) / 深度(6轮×30)`；
  曲线 x 轴=累计反馈数；贡献档案三区（消融条形图 | 单槽位×缺陷类型表 |
  Spearman 相关矩阵）+ 融合对照（fused vs 最强单槽，差距>0.01 提示
  "融合被弱槽稀释"）。

### 统计报表页：工单质检报表（复核后口径）
- 范围：工单（主窗口注入 `_get_workorder_id`）+ 全部/近7天/近30天（默认30d）。
- KPI：检测数/复核覆盖率/**真实不良率**（复核确认）/**误报率 FP/(FP+TN)**/
  **漏检率 FN/(FN+TP)**/平均延迟；无复核显示"暂无复核"。
- 图：误判率趋势（FP率橙/FN率红）、缺陷帕累托（top8）、批次对比表、
  产线健康（灰区率/未解释信号 open_alert/对位预警 + 延迟趋势）。
- CSV 导出（utf-8-sig BOM）。操作日志移至系统设置页（审计归位）。

## 三、实施记录（2026-08-30 完成）

### 后端
- `algo/ssocl/learning_curve.py`：`simulate_learning_rounds` 增加
  `eval_per_sample`（每轮锚定评估用抽样子集，初始/末次仍用全集）与
  `progress_cb`；**assert 软化为轮数自适应** `n_rounds = min(n_rounds,
  len(pool)//round_size)`——小数据集品类不再必崩，不足一轮才 raise。
- `algo/ssocl/feedback.py`：新增 `weight_history`（滚动上限 300）；
  首条带真值反馈落 initial 点（n_fb=0）；`_maybe_apply_weights` 三处落点：
  margin 否决 `reject_margin`、gate 否决 `reject_gate`（记旧权重）、
  写回成功 `apply`（记新权重）。
- `algo/persist.py`：快照存取 `weight_history.json`（旧快照无此文件保持空，
  异常仅打印跳过）。
- `backend/engine/__init__.py`：`simulate_learning_rounds` 包装 +
  `weight_history(category)` 查询。
- `backend/evaluation/service.py`：`evaluate_learning_curve` 支持
  mode="rounds"（默认）；轮池=锚定集外全部有标注图（异常/正常交错），
  learned 指标（learned_accs/flip_rates/defect_recalls）落 EvalRun.metrics。
- `backend/api/routes_learning.py`：latest 端点返回 mode/rounds/learned 等
  多轮字段；新增 `GET /learning/weight_history/{category}`。
- `backend/api/routes_stats.py`：新增 5 个**纯 DB 聚合零前向**端点
  （不破 1s 红线）：`/stats/quality_overview`、`/stats/mistake_trend`、
  `/stats/defect_types`、`/stats/batch_summary`、`/stats/health`；
  复核四象限辅助 `_scope_fb_rows`（剔除 invalidated、operator_label∈{0,1}）
  + `_quadrants`。

### 前端
- `ui/api_client.py`：`learning_curve` 透传 rounds 参数；新增
  `weight_history` 与 5 个 stats 方法（`_scope_params` 统一 scope）。
- `ui/pages/learning_page.py`：全量重写（线上证据 Tab 默认 + 离线回放 Tab +
  贡献档案三区）。**flip_curve 后台任务完成时直接用 task.result 渲染，
  不重新 GET**——反馈数仍 >50 会再次转后台造成死循环（反馈页既有教训）。

- `ui/pages/feedback_page.py`：移除「追溯与提升」Tab（翻案曲线迁入学习页），
  donut 反馈类型占比移到顶部；清理 `_on_tab_changed`/`reload_trace`/
  flip_curve 分支与未用导入（pyqtgraph、LineChart）。
- `ui/pages/settings_page.py`：新增「操作日志（审计）」区（动作过滤 +
  表格 + 刷新 + CSV 导出，走 `/api/logs`、`/api/logs/export`）。
- `ui/main_window.py`：导航「学习曲线」→「学习效果」；

## 四、踩坑与发现（重要）

1. **查询参数命名遮蔽内建函数**：新端点用 `range: str` 作查询参数名，
   `mistake_trend` 内部又调 `range(days-1,-1,-1)` → 500
   `TypeError: 'str' object is not callable`。修复：5 个新端点统一改名
   `range_name`（前端 `_scope_params` 同步）。旧 `/stats/overview` 保留
   `range` 不动（内部未用内建 range）。
2. **并行编辑同一文件会丢更新**：同一轮对 routes_stats.py 发 8 个
   SearchReplace，部分修改被并发写覆盖，且一次误删函数签名行。
   教训：**同一文件的多处编辑必须串行**，每处带足够上下文。
3. **冒烟环境数据前提**：rounds 回放要求 test 锚定集同时含正常/异常标注图；
   当前库只剩 archive 拆分 anomaly 图（演示工单/数据源已被删），
   错误路径验证通过（ValueError 信息明确、任务 failed 状态干净），
   全链路验证需在含 test 拆分标注数据的品类上补做。
4. **不学习基线是定义性基线**：不学习=模型不变，锚定 AUROC 恒为初始值，
   前端画灰色虚线即可，零额外前向成本——不要在后端再跑一遍"不学习模拟"。
5. **性能红线自查**：5 个新统计端点全部纯 DB 聚合（health 端点上限 10000 条
   n_tiles JSON 解析），无模型前向；rounds 回放走后台任务 + progress_cb，
   不阻塞 UI。
