# 用户视角 · Demo5 简易操作流程
（你是使用这套缺陷检测工具的人，不用管内部代码细节）

## 前置准备
1. 准备好你的图片数据集，放到文档规定的文件夹路径
2. 修改配置文件 `configs/m0.yaml`
   - 设置数据集路径
   - 选分块粒度：single快精度低 / tiles9折中 / tiles36准但慢
   - 开启/关闭各个检测槽位、调阈值、是否打开在线学习SSOCL

## 第1步：冷启动（离线训练，只做一次初始化）
运行脚本：`scripts/m0_baseline.py`
- 工具自动拿训练集：最多100张正常图、最多30张缺陷图做学习
- ❗测试集只用来测试效果，不会参与训练，代码会保护
- 跑完所有报告、中间模型全部自动保存到 `outputs/m0`
- 看输出的json报告，确认初始检测精度、速度是否符合预期

> 这一步产出基础模型，后面用来做实际检测。

## 第2步：上线推理（真正检测图片/视频）
喂新的图片或者视频帧给系统：
1. 系统输出每张图判定结果：**正常 / 灰区(拿不准) / 缺陷**
2. 同时输出：缺陷框、掩码、是什么缺陷类型
3. 所有图片的推理记录自动落盘：`outputs/m0/trace_api/inferences.jsonl`
> 有问题可以查这份日志，回溯当时算法为什么这么判。
> 灰区样本机器拿不准，留给人工复核。

## 第3步（可选）：给反馈，开启在线学习 SSOCL
人工看检测结果，告诉系统对错：correct / wrong / none，可以标注框和标签
1. 判错的缺陷样本入库：下次遇到相似图片更容易识别出来
2. 判对的正常样本回流更新正常样本库
3. 系统自动重新校准打分；如果学习后效果变差会自动回滚旧版本
4. 灰区难例会生成待标注清单交给人处理
5. 学习的效果曲线图表同样保存在 `outputs/m0`

## 第4步：查看结果 & 排查问题
1. 看json/markdown汇总报告：整体准确率、速度
2. 看png曲线图：在线拦截、持续学习效果
3. 出问题：打开 trace_api 的日志，回看每一张图片完整推理过程

## 用户极简记忆版
> 配配置 → 跑基线做冷启动得到模型 → 跑推理检测图片 → 人工给反馈让模型越用越好 → 在outputs/m0看报告、查日志
