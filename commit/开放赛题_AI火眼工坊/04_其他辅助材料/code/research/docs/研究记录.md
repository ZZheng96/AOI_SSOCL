# Demo5 项目记忆

## 核心设计原则（用户明确指示，2026-08-16）

### 持续学习是核心，不是初始 AUC
- **重点 = 持续学习的学习曲线（学习提升 + 学习效率）和学习后的 AUC**，不是学习前的静态 AUC
- 赛题定位"一开始错检没事，后续能提升"——胜负手是一条随反馈单调提升、可追溯的学习曲线
- **教训（已吸取）**：持续优化学习前 AUC 是误区，必然走向数据泄露/作弊（demo4 的 0.9983 靠 test 域配对差分 + 文件名配对，无泄漏口径仅 0.09-0.65）。demo5 必须保持诚实：初始 AUC 如实报告（不作弊），用合法在线学习（M3 三类反馈/双库制/拦截通道）证明学习提升

### 诚信红线
- 任何优化不得引入隐式泄漏（test/good 入库、文件名配对、ref 隐式配对）
- 子集选择/调参必须在验证集（GYU-DET val），test 只验不选（U15 诚实协议）
- 阴性结果如实登记（U 登记簿），不粉饰

## 关键技术结论（简版）
- 裁剪弱槽是合法且可泛化的精度杠杆：GYU-DET val 选 → test +0.19；data_local 四品类 0.464→0.683（--slots）
- blob cv2 DoG 全分辨率是 gold_finger 微缺陷关键，任何实现变更（降采样/fp16/GPU 化）均伤精度（U21/U22）
- 共识增益只适用于全槽位（U14）；CPU 3 槽位反噬（U19）；硬门控救不回（U20）
- 缺陷样例拦截实测 F1 +0.37~0.48（"这批错检下批检对"）
- PDN 蒸馏不采纳（U9）；DINO fp16 无收益（U21）
- **学习曲线攻坚（U24-U26，2026-08-16）**：
  - fit 可复现根因：demo4 traditional.py 用全局 np.random.choice（未固定 numpy seed）→ `Pipeline.fit` 入口 `np.random.seed(seed)` + torch seed + cudnn deterministic + TF32 关闭 → 进程间可复现（solder 0.4815 两进程一致）
  - **拦截加分 v2 相对相似**：加分 ∝（缺陷库相似−正常库相似），替代绝对相似（U24 实测绝对相似污染 AUROC 排序）
  - **solder_smt 学习后 AUROC 正增益**：0.5 组 0.4815→0.5185（+0.037，27 反馈）、0.2 组→0.4938（+0.012，11 反馈）——学习曲线成立（反馈越多提升越大）
  - **gold_finger 基线反向 + 学习负增益（诊断闭环）**：sem/layout/trad 在 test 域反向（域差 + CDF 校准饱和，sem AUROC=0.124，正常样本 sem 分 0.97>缺陷 0.66），默认融合 fused 全量 test 仅 0.2524（<0.5 系统性反向）；feedback trace：回流 0 accepted（pending + 熔断——流缺陷率 76% 触发熔断），sem/CDF 从不更新；拦截加分 26/42 样本非零（test 正常与 train 正常库不相似 → 相对相似退化，误伤正常）。曾试 v3a/v3b（pending 也 CDF 重估 + 校准放行）→ gold 更差（0.199→0.188→0.176），**已回退 v2**。solder 正增益为学习曲线主要证据，gold 反向如实登记（不优化初始 AUC，用户红线）
  - 学习曲线评测协议：每组 ratio 独立 fit（SSOCL 更新污染 sem/CDF，共用 pipe 不可比）；stream=test[:-eval_n] 与 eval 不重叠；router_finetune trigger 10→6

## 竞品调研：reference5/pcbdetect 工业级 PCB 检测系统对比（2026-08-28）

**pcbdetect 定位**：金样板比对范式的产线系统（gRPC :50055 服务上位机），能力 = 全景拼接 + Mark 识板定位 + 模板管理 + 器件级检测（ECC 模板匹配 / ORB-LBP-HOG 相似度 / YOLOv11 OBB 器件定位 / PaddleOCR+CRNN 丝印 OCR）。算法层是固定传统+检测模型组合，无自学习、无校准融合方法论。

**它强于我们的（工程骨架，我们的短板）**：
1. 标准化服务接口：约 20 个 gRPC RPC + 流式结果推送（submitFov 快返回 + subscribeDetectResults 长连接）；我们 Pipeline 是离线函数调用，AOI_sys 仅有设计
2. 进程治理：CV/Model 双引擎常驻 Worker（双队列 priority+batch）+ 短命任务 BaseTask、崩溃自动重建、哨兵优雅停机、整组停止；我们单进程无队列无优先级无恢复
3. 数据面零拷贝：三级共享内存（相机环形 10 帧 → Part 512 槽 → 模板资产）+ write_seq/generation 代数校验防脏读；我们磁盘读大图 IO 277ms 是热路径开销（U56 实测）
4. 模板生命周期：模板制作→SHM 存储→算法路由（_PART_TYPE_ALGORITHM）→EngineSnapshot 快照推送热更新（generation 递增）；我们 fit 产物无"产品包"概念，换品类需重跑 fit
5. 识板对位：Mark 点 ECC 匹配拟合 panorama_transform，器件绝对坐标→FOV 局部坐标三步换算；我们无对位概念（数据集假设已对齐）
6. 产线状态机：IDLE/ACTIVE 约束 RPC 时序合法性 + 单板会话（IDENTIFIED/STREAMING/FINISHED）
7. 运维可观测：按"通道.进程名-PID.log"命名 + 小时轮转 + listTaskRegistry 在线查进程组；我们仅 TraceLogger JSONL
8. 测试体系：test_src 与 src 逐层镜像 + gRPC 四组集成测试；我们仅 smoke + 评测脚本
9. 量测语义：结果含 currentValue/standardValue/PASS/NG；我们输出三态+boxes+归因，无量测值对比语义

**我们强于它的（算法能力，要保住）**：多槽位专家+融合校准（CDF/共识/门控）、SSOCL 在线自学习（双库/重校准/分级冻结/回滚）、三态决策+主动学习、L0 零样本兜底（它强依赖金样板与 Mark 点，无模板即瘫痪）、协议诚实+可回滚、双工作点性能（69/399ms）、U1-U121 实验文化。检测范式互补：它解决"有没有/位置对不对/丝印对不对"，我们解决"外观是否异常/能不能越用越准"。

**对 AOI_sys 的落地启发（按性价比排序）**：
1. fit 产物序列化为"产品模板包"（对标 EngineSnapshot：fit 完成即落盘快照 + generation 校验 + 热切换），换品类免重跑——低成本高收益，与现有 fit 流程兼容
2. 服务层采用 submit 异步 + 结果流式订阅模式（FastAPI WebSocket 或 gRPC stream），检测请求快返回
3. 常驻检测 Worker + 双队列（人工复检优先级 / 批量兜底）；配合 1s 红线：服务化层开销（队列+序列化）预留 <100ms，算法侧 69/399ms 仍有余量
4. 对接相机时引入共享内存零拷贝（大图 IO 277ms 占 fast 工作点预算大头）
5. 产线状态机 + pause/resume/learn 会话（AOI_sys v10 已有设计，可对齐 pcbdetect 的 IDLE/ACTIVE 校验模式）
6. Worker 崩溃自动重建 + 哨兵停机 + 进程级日志轮转
7. 服务层集成测试镜像 src 结构

## 首次用户视角 MPDD 全流程评测（2026-08-30，AOI_sys 真实操作）

**方式**：清空 DB + 保留 storage → 启动 AOI_sys → 以"第一次使用的质检员"身份走完 MPDD 全流程（建源即导入→建工单→准备模型→评估→自动检测→复核→反馈即学→学习效果）。客观指标（评估/延迟/翻案/引擎内部状态）全部走后端 API 核对。

**结论先行**：工程骨架和 UI 编排已达演示/验收级，但"反馈即学"在 MPDD 高缺陷率流上实际被熔断锁死（stats 全 0），自学习叙事在本数据集上未成立；决策层对正常图分数虚高（排序好≠决策好，U95 同族）。整体**未达"越用越准"的工业承诺**，属"漂亮的演示壳 + 部分失效的算法心脏"。

### 客观成绩（bracket_black，fast 工作点，GTX 1660S）
- prepare 18s 出 v24（100 正常+30 异常）；评估 AUROC 0.969 / AP 0.959 / F1 0.979（79 张 test）；延迟基准 mean 81.6ms / p95 214ms / max 393ms（<200ms mean 达标、<1s 红线满足）
- 缺陷图（test/hole）正确检出 score 1.0；自动化检测 522 次、14 条反馈全部落库消费

### 重大发现（按严重度）
1. **反馈即学被熔断锁死（P0，核心叙事失效）**：11 条正常反馈 + 缺陷反馈提交后，`learning_insight` stats 全 0——reflow=0、height_recal=0、weight_apply=0、defect_bank.samples=0；翻案曲线 pre_score==post_score 逐条相等（flipped=false）。根因 = banks.py 回流熔断：在线缺陷率估计超阈（流异常率 40-55% >> 阈值）→ fuse_blocked=true → sem/CDF/权重全部拒更新。**UI 却显示"判正常 ✓ 反馈已提交并在线学习（114ms）"——对操作员是静默失败**，无法感知"学了但没学进去"。这是 U26 gold_finger 熔断现象在 MPDD 的复现，且比 U26 更隐蔽（U26 至少有 pending/熔断痕迹可查，UI 这里无任何提示）。
2. **决策层正常图分数虚高（P0）**：检测流大量 train/good 正常图落在灰区 0.93-0.97（正常面右移，U95 同族）；加上 L0 兜底阶段误报，工单统计"不良率 55.6%"（290/522）——真实缺陷率仅 ~21%。质检员看到 55.6% 不良率会误判产线报废；排序好（AUROC 0.969）救不了决策层。
3. **工单创建即自动检测 = L0 兜底误报源（P1）**：无模型时工单挂源即跑检测（L0 零样本兜底），准备模型前已积累 ~200 条高误报检测并计入不良率统计，无法区分/回滚。新用户按"先建工单再准备模型"的引导走，先吃一波误报。建议：无激活模型时阻止自动检测或显著标注"试运行（未校准）"。
4. **storage 残留快照污染（P1）**：清 DB 但 storage/demo5/snapshots 残留 64 个旧快照，启动自动扫描注册并激活残留品类（bottle v4/zipper v15/component v9 等与 MPDD 无关），模型管理/反馈页/学习效果页默认品类=残留的 bottle，首次用户困惑"哪来的 bottle"。建议：快照注册加"品类是否在任一数据源中"校验，孤儿快照标记"历史残留"不自动激活。
5. **两处 UI/行为矛盾（P2）**：①准备对话框说"下一步到评估看板验收后再激活"，实际 prepare 后自动"⑤已投产"；②精度评估返回 latency_pass=false（p95 口径）但 UI 显示"✓ 通过"（mean 口径）——口径不一致无提示。
6. **版本号全局累加（P2）**：bracket_black 首版即 v24（storage 有 v1-23 旧快照），版本历史"24 个版本"与用户预期"第一个版本"不符。

### 改进建议（按性价比）
1. 熔断降级必须可感知：fuse_blocked 时 UI 反馈摘要返回"已学习（熔断保护：缺陷率高，正常回流暂停）"并给出解封条件（缺陷率回落/人工确认）；或对高缺陷率流（MPDD 类）默认关熔断改用"阈值门控"（只回流分数<阈值的正常样本）。
2. 自动检测前置条件：无激活模型时产线自动检测改为"待命"状态 + 工作台显著引导"准备模型后启动"。
3. 决策层：正常面虚高是 fused 分布右移（CDF 外推 + 拦截加分饱和）——U69 已证阈值重估在饱和下失效，需先解 fused cap 饱和（不 cap 决策分/boost 按框内纯度重调）。
4. storage 快照注册加数据源校验 + "历史残留"标记。
5. 版本号改为品类内从 v1 递增（新 DB 时），或 prepare 时忽略无血缘旧快照。

## P0 修复（2026-08-30，算法根因分析与修复，已端到端验证）

**根因链复盘**（评测两个 P0 的真正根因，逐层实证）：

1. **反馈即学静默失效（P0）= 三层叠加**：
   - 主根因 **verdict 语义断层**：灰区复核（review，UI 主流程）经 `map_verdict_label` → `("none", label)`，而 `FeedbackHandler.feedback` 的 verdict=none 分支只走 `_unlabeled`（缓存/选样，零学习）——map 注释承诺"以人工 label 为准学习"，实现从未兑现。评测 9 条正常复核 + 1 条缺陷确认全落此死路（实测：`_reflow`/`_add_defect_sample` 零进入）。未知 feedback_type（correct/misdetection）也静默落入同一死路。
   - 次根因 **fuse 口径 bug**：`_finalize` 里 `_observe_decision(decision != "normal")` 把 gray 当缺陷计数（`engine._to_result` 的 is_anomaly 口径却是 `== "anomaly"`，两处不一致）→ 虚高下灰区积压推高 defect_ratio → fuse_blocked 锁死正常回流；且 blocked 路径无 stats、无透出（静默）。
   - 放大器 **快照传播 + UI 死键**：NormalBank 整体 pickle，污染窗口随快照传播；`engine.submit_feedback` 只透传 entry 里从不存在的 `triggered_*` 键（死代码），UI 恒显"已学习"。
2. **决策层分数虚高（P0）= 在线纠偏被门控误杀**：CDF test 域右移（U61/U95 族已知）本应由 U62 height_recal 在线纠偏，但 RegressGate 非定向判据（|drift|>0.05 拒）把"有意图的向下修正"当回归误杀（评测实测 gate_reject=1 后冷却锁死）。U65/U66 的 head_ft/disc_ft 早已改定向门控，height_recal 漏改（设计不一致）；且重估若成功不同步门控基准会连锁锁死后续所有门控。
