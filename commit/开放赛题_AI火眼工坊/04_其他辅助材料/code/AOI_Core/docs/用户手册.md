# AOI 实时在线 AI 质检系统 · 用户手册

版本：v2.0　适用代码库：`AOI_sys/`　算法核心：demo5 槽位融合引擎

---

## 一、系统简介

本系统是一套**可自学习的 AOI（自动光学检测）实时在线质检系统**，面向制造业组装过程中屏幕、电池、中框等组件的缺陷检测。算法核心为 **demo5 槽位融合引擎**：DINOv2 视觉主干 + 13 个可插拔检测槽位（默认 fast 工作点启用 sem 语义记忆 / disc 判别头 / shead 判别头三槽）+ CDF 在线自动校准 + 槽位融合（等权 / 共识加权），输出三态决策：**normal（正常）/ anomaly（异常）/ gray（灰区待复核）**。

系统围绕三大核心能力组织：

| 核心能力 | 系统支撑 |
|---|---|
| ① 实时视频/图片异常检测 | 单图检测严格控制在 1 秒红线内（冷缓存实测 108-483ms 全链路；相机帧零拷贝直入 4096×3000 实测均值 131ms/max 224ms，详见 §六）；2500² 大图 fast 工作点 <200ms 预算对照考核；热力图 + 缺陷框 + 缺陷类型归因可解释输出 |
| ② 少样本快速部署 | 场景分层 L0-L3：L1a 少样本场景仅需 10 张正常 + 3 张缺陷样本即可上线；配合 4 种伪异常生成（CutPaste/划痕/噪声/色偏）+ 3 档数据增强，冷启动成本极低 |
| ③ 反馈驱动持续学习 | 操作员标记误检/漏检（可框选漏检区域）→ **反馈即学，秒级生效**（缺陷拦截通道 1-2 张即拦截、正常回流、在线权重学习、虚高重校准）→ 巩固版本落盘成新快照 → 学习曲线可视化证明"越用越准" |

系统形态：**PySide6 桌面客户端 + FastAPI 后端 + SQLite 数据库**，支持单机一体运行（开发/演示）与 Docker 部署后端 + 远程桌面端接入（产线模式）。

### 功能地图

```
实时监控 ── 视频/文件夹/相机RTSP 逐帧检测推流（三态决策 + 槽位分数）
数据管理 ── MVTec/DAGM/文件夹/视频导入，标注、筛选、缩略图浏览
伪异常与增强 ── 少样本冷启动的数据工厂
反馈与自学习 ── 反馈汇总、当前版本与未巩固反馈数、巩固版本
学习曲线 ── 离线回放：AUROC/F1 随反馈数上升曲线 + 槽位消融贡献
模型管理 ── 版本快照注册表/激活/回滚/A-B 版本对比
评估中心 ── AUROC/F1/混淆矩阵 + 延迟基准（对照 200ms 预算）
统计面板 ── 检出率、误检率、延迟趋势等看板
```

## 二、安装与启动

### 2.1 环境要求

- Windows / Linux，Python 3.10+
- GPU 可选（CUDA）；无 GPU 时自动回落 CPU（cpu 工作点）
- 依赖：`pip install -r requirements.txt`（torch、fastapi、uvicorn、PySide6、SQLAlchemy、opencv、sklearn 等）
- DINOv2 主干权重走本地 hub 缓存，首次使用需联网下载一次

### 2.2 单机一体模式（推荐开发/演示）

```bash
cd AOI_sys
python main.py
```

自动完成：内嵌启动后端（默认 `http://127.0.0.1:8017`）→ 初始化数据库 → 打开桌面客户端。

### 2.3 产线分离模式（Docker 后端 + 远程客户端）

```bash
# 产线服务器（CPU 即可；有 GPU 时取消 docker-compose.yml 中 gpus 注释）
cd AOI_sys
docker compose up -d        # 后端 8017 端口

# 质检工位电脑：修改 configs/default.yaml 的 system.host 指向服务器
python main.py
```

### 2.4 关键配置（configs/default.yaml）

| 配置项 | 说明 | 典型值 |
|---|---|---|
| `system.host / system.port` | 后端监听地址与端口 | `127.0.0.1 / 8017` |
| `system.demo5_storage` | demo5 快照根目录（版本快照存放处） | `storage/demo5` |
| `system.demo5_base_cfg` | demo5 引擎基础配置（工作点、融合参数等） | `../demo5/configs/m0_fast.yaml` |
| `pipeline.tile_size / input_size` | 检测分块与输入参数 | 512 / 256 |
| `pipeline.latency_budget_ms` | 延迟考核预算（对应 2060 GPU 2500²） | 200 |
| `evaluation.benchmark_n_images / benchmark_warmup` | 延迟基准计数量与预热数 | 30 / 5 |
| `notify.webhook_url` | webhook 推送地址（MES/PLC 对接），**空=禁用** | `http://mes.example.com/aoi/hook` |
| `notify.events` | 订阅事件：`anomaly`（检出异常）/ `gray`（灰区待复核）/ `feedback`（反馈即学成功）/ `consolidate`（巩固落盘成功）/ `alarm`（连续异常告警）/ `open_set`（开放集未知模式） | `["anomaly"]` |
| `notify.timeout_s` | 推送超时秒数（异步线程推送，不阻塞检测） | 3 |
| `notify.alarm_window / alarm_k / alarm_cooldown_s` | 连续异常告警参数：滑窗帧数 / 窗口内异常帧数阈值 / 触发冷却秒数 | `20 / 5 / 60` |

webhook 推送为异步 POST JSON，载荷形如 `{event, ts, category, detection_id, score, decision, image_path, defect_boxes, latency_ms}`（feedback/consolidate 事件相应带 feedback_type/version 字段；`alarm` 事件带 `window_hits/window/k`；`open_set` 事件为开放集哨兵命中帧）。推送失败不影响检测与反馈，仅记入操作日志（webhook_error）。

## 三、快速上手：十分钟完整流程

以自建数据集 `data_local` 的 **gold_finger（金手指组件）** 品类为例。

### 步骤 1：导入数据

打开【数据管理】页 →【导入数据】→ 选 **MVTec 格式** → 指向 `data_local/gold_finger`（目录含 `train/good`、`test/good`、`test/defect`、`ground_truth/defect`）。

- 系统自动识别正常/异常标签、训练/测试划分，图像与元数据入库
- 也支持：DAGM 格式、任意文件夹（按子目录名打标）、视频文件（自动抽帧）
- 导入是后台任务，右下角可看到进度推送

### 步骤 2：准备模型（选场景与工作点）

【模型管理】页点击【准备模型】→ 选择刚导入的品类 → 选择 **场景（scenario）** 与 **工作点（profile）** → 开始：

**场景分层**（按你手上可用的信息选层级，引擎自动激活对应槽位）：

| 场景 | 可用信息 | 说明 |
|---|---|---|
| L0 零样本 | 仅正常图 | 激活 sem/inp/trad/blob/layout 等无监督槽位，无判别头，阈值取正常分位数 |
| L1a 少样本 | 少量图像级标注（≤100 正常 + 30 缺陷，赛题标准协议） | **推荐快速上线**：全槽位，disc/shead 判别头用伪异常训练；10 张正常 + 3 张缺陷即可上线 |
| L1b | L1a + 缺陷定位标注 | 支持框级反馈（反馈框直接进缺陷库） |
| L2 | + 品类信息 | 品类级独立快照与记忆库（系统天然按品类隔离） |
| L3 | + 模板图 | 激活 tpl 模板比对槽位。**模板图需先在【数据管理】右键图像 →「设为模板图（L3 用）」**（split=template，可再右键取消）；选 L3 而无模板图时准备对话框会拦截提醒（tpl 槽位将空转） |

**工作点**（速度与精度的取舍）：

| 工作点 | 槽位组合 | 速度 | 适用 |
|---|---|---|---|
| fast（默认） | sem / disc / shead 三槽 | 2500² <200ms | 产线实时；标准数据集精度反而更高 |
| accuracy | 全部 13 槽位 | 2500² ~400ms（仍在 1s 红线内） | 精检复核、演示 |
| cpu | blob/trad/layout 等无 DINOv2 降配槽位 | CPU <2s 挑战目标 | 无 GPU 工位 |

完成后模型保存为 **v1 版本快照**并自动激活，顶栏品类下拉即可选用；已有激活版本时可勾选强制重备。

### 步骤 3：开始检测

【实时监控】页三种来源任选：

1. **单图/文件夹**：选文件夹逐张检测，适合批量验证
2. **视频**：导入的视频逐帧检测，模拟产线流
3. **相机/RTSP**：填 `rtsp://...` 或 `0`（本机摄像头），实时推流

每帧显示：异常分数、三态判定徽标（normal 绿 / anomaly 红 / gray 黄"待复核"）、各槽位校准分、触发槽位、热力图叠加、缺陷框、缺陷类型归因标签、耗时。超过延迟预算的帧会标红。

- **连续异常告警**：近期窗口（默认 20 帧）内异常帧数达到阈值（默认 5 帧）时，页面顶部出现红色横幅"⚠ 连续异常告警：近期窗口内 N 帧异常（建议停线检查）"，并通过 webhook 推送 `alarm` 事件；告警有冷却期（默认 60 秒）防刷屏，窗口滑出后自动解除
- **未知模式徽标**：开放集哨兵检出"不像任何已知正常模式"的帧（新型缺陷/光照突变/错料）时，判定徽标旁出现紫色"未知模式"标记，可配置 webhook `open_set` 事件推送

### 步骤 4：操作员反馈（反馈即学，秒级生效）

检测结果下方四个按钮：

| 按钮 | 场景 |
|---|---|
| 确认正确 | 模型判对，给予正反馈（正常样本回流记忆库） |
| 误检 | 正常品被判异常 → 引擎在线重校准，抑制虚高分数 |
| 漏检 | 异常品被判正常 → **可在图上框选缺陷区域**，缺陷拦截通道 1-2 张即生效 |
| 新缺陷类型 | 未见过的缺陷 → 作为新类样本进入缺陷库 |
| 无法确认（M15a） | 拿不准、暂不下结论 → 不定真值（登记 label=unknown，不计入判对率曲线），样本进入主动选样语义等待后续处理 |

提交后**立即在线学习**（实测 ~72-140ms），无需攒批、无需手动触发——"这批错检，下批检对"。提交成功的提示会附带本次引擎更新摘要（`engine_update`：拦截通道命中 / 正常回流 / 权重更新 / 校准重估 / 回滚 + 耗时）；若模型未就绪则反馈仅落库，待模型可用后再消化。

### 步骤 5：巩固版本

【反馈与自学习】页查看各品类**当前版本**与**未巩固反馈数**：

1. 反馈即学全部发生在内存中的当前引擎上，立即生效
2. 积累若干反馈后，点击【巩固版本】→ 引擎把当前状态落盘为**新版本快照**（`v2/v3...`，保留父版本血缘）
3. 巩固是显式的"存档"动作：让在线学习成果成为可激活、可回滚、可对比的正式版本

### 步骤 6：A/B 版本对比后上线

新巩固版本**不建议直接激活**。在模型表格找到该版本行 →【A/B 对比】：

- 选择对比版本（A 默认为当前激活版本，B 为候选版本）、测试集与样本上限 → 开始对比
- 系统在**同一批图像上**用两个版本的快照平行打分，输出双方 AUROC/AP/F1 与分歧样本列表
- 裁决为"更优"（AUROC 为主、F1 为辅）时可一键【激活】；不满意可【回滚】到上一版本

### 步骤 7：学习曲线与评估报告

- 【学习曲线】页：离线回放反馈学习过程，看 AUROC/F1 随反馈数的上升曲线与槽位贡献（详见 4.6）——这是"越用越准"的直接证据
- 【评估中心】页：
  - **精度评估**：对指定品类/划分计算 AUROC、AP、F1-max、最优阈值、混淆矩阵
  - **延迟基准**：预热 5 张 + 计时 30 张，输出 mean/p50/p95/max，自动对照 200ms 预算给出通过/不通过
  - **历史对比**：多次评估记录可勾选对比，观察模型迭代效果

## 四、各页面详解

> M16b 起导航按用户操作流分组排序：**工作台**（开机首屏）→ 准备期（数据管理 / 伪异常与增强 / 模型管理 / 评估看板）→ 投产期（实时监控 / 标注反馈）→ 复盘期（学习曲线 / 统计报表）→ 系统（系统设置）。

### 4.0 工作台（M16b，开机首屏）

- **今日 KPI 行**：今日检测 / 今日不良 / 待复核 / 待巩固反馈
- **待办卡片**：待复核队列、不完备预警（体系外缺陷信号持续出现的品类）、待巩固反馈——每张卡片带直达按钮，点击跳到对应处理页
- **品类上线状态表**：每个品类当前处于「① 数据未导入/不足 → ② 可训练 → ③ 已训练未验收 → ④ 已验收未激活 → ⑤ 已投产」哪一环（M16a 状态机），含数据构成、版本数、激活版本、最佳 AUROC；每行【下一步】按钮直接跳到该环节对应的操作页
- **能力开关状态条**：Webhook 告警 / PLC 触发 / 自动归档 / API 鉴权 / API 文档 的开闭状态（只读透出，修改去系统设置）

### 4.1 实时监控

- 左侧：来源配置（单图/文件夹/视频/相机）、品类选择、开始/停止
- 中间：当前帧 + 热力图叠加切换、缺陷框
- 右侧：分数仪表盘（分数/阈值裕度，阈值取后端真实决策阈值含灰区下限）、各槽位校准分动态条（随工作点自适应 fast/accuracy/cpu 的不同槽位集合）、融合权重、延迟、历史帧列表
- 三态决策徽标：normal（绿）/ anomaly（红）/ gray（黄，待复核——分数落在灰区，徽标下方提示"已入复核队列"，到反馈页→待复核 Tab 一键判定）
- 底部：四个反馈按钮（见步骤 4）
- **WS 实时推流**：检测在服务端进行，帧结果经 WebSocket 推送，UI 不卡死

### 4.2 数据管理

**批次（Dataset）概念（M8a）**：每一次导入/生成都会产生一个"数据集批次"——记录名称、品类、来源类型（folder/mvtec/upload/pseudo/augment/video/feedback）、来源路径、参数与图片数。所有图片都挂在某个批次下，来源可追溯：

- 文件夹/MVTec/视频导入、上传、伪异常生成、数据增强、视频抽帧都会自动建批次；导入接口可传 `name`/`note` 命名与备注（默认 `{来源类型}_{时间戳}`）；
- 上传默认挂按品类复用的 "uploads" 批次；反馈/复核中产生的新图自动登记（split=feedback）并挂按品类复用的"反馈回流"批次；
- M8a 之前的存量图片在服务启动时自动按品类归入"历史未分组"批次（幂等，不重复归组）；
- 新导入的图片文件统一存放 `storage/images/{品类}/ds{批次号}/`，文件名带 `ds{批次号}_` 前缀，同名文件不再互相吞掉。

**标注流转**：`POST /api/images/{id}/annotate` 可修改图片的 label（normal/anomaly/unknown）、split（train/test/val/feedback…）与 defect_type；每次修改都会写操作日志（含变更前后值，`GET /api/logs?action=annotate_image` 可查）。

**级联删除**：

- 删单图：`DELETE /api/images/{id}?delete_file=true` 可同时删除磁盘文件（默认只删记录，保持旧行为）；
- 删批次：`DELETE /api/datasets/{id}?delete_files=true` 级联删除该批次全部图片行与磁盘文件；关联的检测记录默认保留（仅解除图片关联），`keep_detections=false` 时连带删除；返回 `{deleted_images, deleted_files, affected_detections}` 计数。

**孤儿文件清理**：`POST /api/maintenance/orphan_scan` 后台扫描 storage 下所有无 DB 引用的文件（预览残留、历史临时文件等），清单写入任务结果；确认后用 `POST /api/maintenance/orphan_clean` 传入清单删除（只允许删 storage 目录内文件，全程记日志）。

**UI 操作（数据管理页 → 图像 Tab）**：

- **四维数据树**：左侧导航树为「全部图像 → 品类 → 数据集批次（显示"批次名 (图片数)｜可支撑层级"）→ 划分 → 标签」四级，点击任意节点即按对应维度过滤右侧图像表格，并同步顶部筛选栏；老数据自动挂在"历史未分组"批次节点下。**批次分层徽章（M14d）**：批次节点显示该批次数据可支撑的场景层级（L0 有正常图 / L1a 有缺陷标注 / L1b 有掩膜图 / L2 有品类 / L3 有模板图），导入时即可判断"这批数据能支撑到哪一层"；
- **模板图标记（M14a，L3 用）**：右键图像行 →【设为模板图（L3 用）】（split=template，划分筛选栏与标注对话框同步支持），准备模型选 L3 时自动收集进引擎；
- **图像表格**：缩略图 / ID / 品类 / 批次 / 来源 / 划分 / 标签 / 缺陷类型 / 导入时间 / 路径，双击行看大图；
- **标注流转**：右键图像行 →【标注…】，对话框中修改标签（normal/anomaly/unknown）、划分（train/val/test/feedback…）与缺陷类型，每次修改记操作日志；
- **删除**：右键图像行 →【删除该图像…】，可勾选"同时删除磁盘文件"；右键批次节点 →【删除批次…】，确认框显示级联范围，可勾选"同时删除磁盘文件"，检测记录默认保留（仅解除与图片的关联，可取消勾选改为连带删除），完成后弹出删除计数；
- **批次导出**：右键批次节点 →【导出清单（CSV）】，导出该批次全部图片的 id/path/split/label/defect_type；
- **孤儿文件清理**：工具栏【孤儿文件清理】→ 后台扫描 storage 下无数据库引用的文件 → 弹出清单对话框（显示文件大小，默认全选，可逐个取消）→【删除选中】执行清理（仅限 storage 目录内文件，全程记日志）；
- **导入即建档**：【导入文件夹 / 导入MVTec / 上传图片】对话框均可填批次名（留空自动按"来源_时间戳"命名）与备注。

其余既有能力不变：

- **树状导航**：左侧数据树（全部图像 → 品类 → 划分 → 标签，节点带数量），点击节点即过滤右侧图像表格；与顶部筛选栏双向联动。接口 `GET /api/images/tree` 新增第四维 `datasets`（品类 → 批次 → 划分 → 标签），原三维结构保留
- 导入：MVTec / DAGM / 文件夹 / 视频四种模式（批量事务 + 快速指纹去重，GB 级数据集秒级入册，进度条为真实百分比）
- 筛选：品类 × 标签（正常/异常/未知）× 划分（train/test）
- 浏览：缩略图网格 + 大图预览（缩放/平移）+ 元数据（尺寸/路径/来源）
- 统计：每品类的样本分布一目了然；`GET /api/stats/overview?category=` 与 `/api/stats/timeseries?category=` 支持按品类过滤检测量/异常数/缺陷率

### 4.3 伪异常与增强

- **伪异常生成**：选品类与正常图 → 选类型（CutPaste/划痕/噪声/色偏）→ 生成数量 → 后台批量生成，产物带掩码入库，可作为 L1a 场景的判别头训练素材
- **数据增强**：轻/中/重三档（翻转/旋转/亮度/对比度/高斯噪声等组合），用于扩充正常样本多样性
- **预处理**：尺寸归一、去噪、直方图均衡化等，处理结果另存不影响原图

### 4.4 反馈与自学习

两段式语义：**反馈即学（秒级生效）+ 巩固版本（落盘成新快照）**。

- **反馈汇总**：全部反馈记录列表（关联检测缩略图、类型、操作员、学习状态：已学习/仅落库）
- **各品类状态卡片**：当前版本号 / 未巩固反馈数 / 备注 / 【巩固版本】按钮 /【内部状态…】按钮（M14b：弹出引擎内部状态对话框——正常锚定库 patch 数、扩展库回流量、缺陷样例库规模与拦截命中下限、孵育头进度（攒够 8 张同类缺陷样例孵育专属拦截头）、主动选样队列长度、权重写回门控通过/否决计数、初始权重质量 train AUROC）
- **不完备预警横幅（M14c）**：某品类最近 100 帧内"未知模式"（open 哨兵）命中 ≥3 次且占比 ≥15% 时，页面顶部出现红色横幅"不完备预警：疑似体系外缺陷信号持续出现，现有特征组无法解释"，提示复核这些样本或补充模板图/扩充缺陷定义（接口 `GET /api/review/incomplete_report`）
- 反馈提交即触发引擎在线更新（`pipe.feedback()` 内自动完成正常回流 / 缺陷拦截 / 权重学习 / 重校准，全程走回归门控 + 自动回滚保护）；巩固版本把内存中的学习成果落盘为可管理的版本快照
- **反馈前判定自动记录（M7a）**：每次提交反馈（含复核结论）时，系统在即学前先用当前引擎对该图打一次分，把"反馈前判定"（分数/三态决策/槽位分）随反馈一并落库；反馈与复核接口的响应体会附带 `pre` 字段。有了"学习前 vs 学习后"两个点，才能画出翻案曲线（`GET /api/learning/flip_curve/{cat}`）与单帧追溯链（`GET /api/detections/{id}/trace`）；M7a 之前的老反馈没有该记录，曲线自动跳过并计入 `legacy_count`

**待复核队列（灰区闭环）**：检测判定为"灰区"（分数落在灰区下限与判定阈值之间）的帧不会直接放行，而是进入待复核队列。操作员在队列中逐张判定"正常/缺陷"后，系统立即把复核结论作为反馈即学（feedback_type=review）——灰区帧恰是边界样本，学习价值最高；已复核的帧自动出队。接口：`GET /api/review/queue`（队列）、`POST /api/review/{id}`（提交复核）、`GET /api/review/stats`（待复核规模/今日已复核数）。

UI 操作（反馈页 →「待复核」Tab）：

- 顶部 KPI 行实时显示**待复核数**与**今日已复核数**；
- Tab 内可按**品类筛选**、翻页浏览；点击任意一行，右侧即显示该帧大图（可缩放/平移）；
- 看图后点【判正常】（快捷键 Enter）或【判缺陷】（快捷键 D），顶部绿色提示条显示即学摘要（3 秒自动消失，不打断流水作业），该帧随即出队并**自动选中下一条**，可连续快速复核；
- **框选缺陷区（复核即标注）**：在预览图上直接**拖拽框出缺陷区域**（单击或 Esc 清除框选），再点【判缺陷】——系统自动换算归一化坐标直接喂给引擎**缺陷拦截通道**（"1-2 张带框缺陷样本即拦截同类"），价值远高于整图标签；判正常时忽略框选；
- 若提示"该记录已被复核"，说明其他操作员已处理，列表自动刷新；
- **系统推荐复核（M15b 主动选样，赛题点名"主动学习"）**：点【系统推荐复核…】，引擎从灰区积累中挑"最不确定 × 最有代表性"的样本清单（每张只问一次，防止重复打扰），点「载入复核」后该样本进入右侧预览区，走同一套判正常/判缺陷流程——把有限的复核预算花在信息价值最高的样本上。接口：`GET /api/review/active_suggestions?category=`。

**追溯与提升（反馈页 →「追溯与提升」Tab）**：错检追溯→学习→翻案的可视化闭环。

- **KPI 行**：错检数 / 已翻案数 / 翻案率 / 老反馈数（M7a 之前无判定记录的反馈）；
- **翻案曲线**：每张被反馈的图有两个判定点——灰线"学习前判定分"（反馈时自动记录）与蓝线"当前引擎重判定分"（实时重打分）；**绿色大圆点 = 已翻案**（当前判定已纠正为人工结论），曲线整体向人工标签收敛即"越用越准"的直接证据；
- **错检列表**：所有被标为误检/漏检/新缺陷的检测（时间/品类/当时判定/反馈类型/反馈前分数），**双击行**打开追溯详情对话框：大图（叠加热力图）、当时模型版本、判定现场（分数/槽位分/触发槽位）、当前引擎重判定与翻案标注、完整反馈时间线（每次反馈的类型/人工标签/是否框选/反馈前分数）；
- 错检集支持 CSV 导出（`GET /api/detections/misjudged?format=csv`），供质量会议/复判使用。

### 4.5 模型管理

- **准备模型**：新品类冷启动入口——选品类 → 选场景（L0-L3，默认 L1a）与工作点（fast/accuracy/cpu）→ 拟合并保存 v1 快照；已有激活版本时幂等跳过，可勾选强制重备
- **数据体检（precheck）**：准备模型对话框打开/切换品类时自动统计图库：各分组图片数、分辨率分布、建议场景分层（如"正常图不足 10 张→建议 L0 零样本"）与警告（分辨率不一致等），并按建议自动预选场景——接口 `GET /api/models/precheck/{category}`
- **架构图**：demo5 槽位融合示意（sem/disc/shead 三槽 + 加权融合）
- **版本快照表**：所有版本（初始拟合 / 在线学习 / 巩固）的名称、版本号、品类、来源、指标、激活状态
- **操作**：扫描快照目录注册 / 按版本激活 / 回滚到次新版本 / A/B 版本对比
- **激活质量门控**：点击【激活选中】（或 A/B 对比后的【激活该版本】）时，系统**自动先用品类锚定集对候选版本与当前版本做回归对比**再决定是否放行：
  - 门控通过 → 弹出双方 AUROC/F1 对比表，确认即完成（此时已激活）；
  - 候选版本 AUROC 显著劣化（低于当前版本 −0.02）→ 激活被拒绝，弹窗展示对比数据与分歧样本数，可点【强制激活】跳过门控，或【取消】放弃；
  - 锚定集标注样本不足（<4 张）时门控自动跳过并提示，直接激活。门控评估约需数秒（锚定集 40 张双版本打分），请稍候
- **校准说明**：demo5 引擎在线 CDF 自动校准，无需手动管理校准集（旧版校准集管理功能已移除）

### 4.6 学习曲线

分两个 Tab：**「离线回放」**模拟"如果重来"的学习过程；**「在线曲线」**展示本机真实反馈以来的判对率变化。

**「在线曲线」Tab（真实反馈流）**：

- **判对率折线**：横轴为反馈序号 k，纵轴为最近 10 条的滚动判对率（判对 = 系统判定与操作员结论一致）——曲线抬升即"每复核/反馈一次，下一帧更准"的直接证据；每条反馈（含待复核队列的复核结论）都会实时追加一个点
- **KPI 卡片**：累计反馈 / 判对率 / 近 7 日反馈
- **当前融合权重**：引擎实时快照（该品类引擎未加载时显示"引擎未加载"）
- 顶部可切换品类与手动刷新；尚无反馈时显示引导文案"提交反馈或完成复核后这里会出现曲线"

**「离线回放」Tab**：回放"反馈驱动学习"的全过程，直观展示模型越用越准。**回放在当前激活快照的独立副本上进行，不影响线上模型**。

- **回放参数**：`n_stream`（反馈流样本数）、`n_eval`（每评估点锚定集样本数）、`max_feedback`（最大反馈步数），默认均为 20；点击【开始回放】后作为后台任务执行，进度条跟踪，完成自动加载结果
- **AUROC/F1 曲线**：横轴为反馈步数，纵轴为锚定评估集上的 AUROC 与 F1——曲线随反馈数上升即"越用越准"的直接证据
- **KPI 卡片**：
  - `initial_auroc`：零反馈时的初始 AUROC（冷启动基线）
  - `final_auroc`：回放结束时的 AUROC
  - `auroc_gain`：增益 = final − initial
  - `efficiency`：学习效率（每单位反馈带来的增益）
  - `n_feedback`：本次回放总反馈数
- **槽位消融贡献图**：每个槽位"单独使用 AUROC" vs "剔除该槽位后的融合 AUROC"，叠加全量融合参考线——单独高且剔除后明显掉分的槽位是核心贡献者；剔除后几乎不掉分的槽位说明冗余
- **融合权重图**：当前引擎各槽位的融合权重快照（取自该品类最近一次检测记录）
- 提示：锚定集很小时 AUROC 会出现 ±0.5 级别的统计抖动，属小样本噪声而非引擎缺陷

### 4.7 评估中心

- 精度评估 / 延迟基准的触发与历史记录
- 指标表格 + 多次评估对比视图（学习曲线/贡献档案等时序型指标自动取终值展示）
- 延迟基准对照赛题 200ms 预算自动判定
- 贡献档案（槽位单变量/冗余度/消融三层评价）也可在此查看历史记录

### 4.8 统计面板

- 检测总量、异常检出数、检出率、误检率（来自反馈汇总）
- 品类分布、延迟趋势、每日检测量等图表
- **品类过滤（M8）**：顶部品类下拉（默认"全部（全局）"）切换后，KPI、近 14 天趋势图与操作日志全部按该品类刷新（`GET /api/stats/overview?category=` 与 `/api/stats/timeseries?category=`）；"今日"段为全局口径，"累计"段按品类实时统计
- **CSV 导出（M15d）**：工具栏【产线日报 CSV】（近 30 天，随品类过滤）与【审计日志 CSV】按钮，弹保存对话框直接下载（BOM 头，Excel 直开；交付/举证用）
- **操作日志过滤（M8）**：日志表格右上的"动作"下拉可按动作类型过滤（detect / feedback / review / alarm / consolidate / import / annotate_image / delete_image / delete_dataset / orphan_clean 等），与品类过滤叠加生效

### 4.9 系统设置（M16d/M16e）

- **白名单参数热修改**：延迟预算、反馈触发门槛、评估基准样本数、Webhook 地址/告警窗口、自动归档、PLC 触发目录、日志滚动等 14 项按分组表单展示（数字框/勾选框/文本框），【保存修改】只回传改动项，写回 yaml 立即生效无需重启；非白名单高危项（引擎槽位参数、安全密钥）不接受修改，仍需手改配置文件；每次保存记 `config_update` 操作日志
- **新建品类向导（M16e）**：【新建品类向导】按钮打开引导对话框，按操作流列出「① 定品类 → ② 定数据 → ③ 定功能 → ④ 冷启动训练 → ⑤ 评估验收 → ⑥ 投产」六步，每步附说明与"去××页执行"直达按钮
- 批次右键菜单新增【批次详情与数据谱系…】（M16f）：显示该批次参与了哪些模型版本的训练（含当前激活标记），数据 → 模型可追溯

## 五、典型案例

### 案例 A：新品类上线，只有少量缺陷样本

1. 【数据管理】导入 60 张正常图（train/good）+ 手头的几张缺陷图
2. 缺陷不足 3 张时，先到【伪异常与增强】对正常图生成伪异常（CutPaste + 划痕各半）
3. 【模型管理】→【准备模型】：场景选 **L1a**、工作点 **fast**（10 张正常 + 3 张缺陷即可上线）
4. 【评估中心】跑精度评估看 AUROC；不达标则调整伪异常类型配比重备
5. 【实时监控】接入产线视频试运行

### 案例 B：换了一个视野（FOV），正常品频繁误报

**现象**：同一组件换了相机工位，新视野下正常图分数普遍偏高，误检率飙升。

1. 监控中对误报帧点【误检】——引擎立即在线重校准，后续帧的虚高分数即被抑制，**无需攒批等待**
2. 连续观察若干帧确认误报消除
3. 【反馈与自学习】页点【巩固版本】，把校准成果落盘为新版本快照

### 案例 C：漏检了一种细微划痕

1. 对漏检帧点【漏检】，**在弹出对话框的图上框选划痕区域**后提交（框选让缺陷拦截通道精确定位）
2. 缺陷拦截通道 1-2 张即生效，同类划痕下批即被拦下
3. 积累若干条后【巩固版本】生成 v2 →【A/B 对比】→ 漏检样本召回提升且 AUROC 不退化 →【激活】
4. 到【学习曲线】页回放一遍学习过程，用 AUROC 增益与效率 KPI 佐证效果

### 案例 D：验收测试（对照赛题指标）

1. 【评估中心】延迟基准：n=30、预热 5 → 查看 mean 是否 < 200ms
2. 精度评估：test 划分全量 → AUROC / F1 / 混淆矩阵
3. 【学习曲线】回放 → 截图 initial/final/gain KPI 作为持续学习能力证据
4. 【统计面板】截图看板数据
5. 命令行回归：`python -m test.run_all` 全量测试

## 六、性能指标

实测环境：GTX 1660S，fast 工作点（sem/disc/shead），冷缓存口径（每图首检，2026-08-31 全链路重测）。

| 环节 | 实测耗时 | 红线/预算 |
|---|---|---|
| 单图检测 1024²（磁盘路径，含读盘+推理） | e2e 均值 108ms / p95 149ms / max 284ms | <1s（单图红线） |
| 单图检测 4096×3000（磁盘路径，含 ~277ms 级读盘） | e2e 均值 292ms / p95 333ms / max 483ms | <1s（单图红线） |
| 单图检测 4096×3000（**相机帧零拷贝直入** `POST /api/detect/frame`） | e2e 均值 131ms / p95 172ms / max 224ms | <1s（单图红线）；较磁盘路径省 55% |
| 单图检测 4096×3000（零拷贝 + 热力图渲染存盘） | e2e 399ms | <1s（单图红线） |
| 复检同图（特征缓存命中） | e2e ~92-109ms | 复检工位口径 |
| 反馈即学（提交反馈后的引擎在线更新） | ~72-140ms | 秒级生效 |
| 准备模型（L1a 全量 fit，10+2 样本） | ≈8s | 一次性离线操作 |
| 学习曲线回放（默认 20 反馈 + 评估点） | 数秒~30s（视锚定集大小） | 后台任务，不阻塞操作 |
| A/B 版本对比（约 6 次前向 + 快照加载） | ≈4s | 后台任务 |

> 口径说明（2026-08-31 重测）：旧文档"52-348ms"混合了热缓存样本（引擎特征缓存命中时跳过读盘/前向），产线每图只检一次必为冷缓存，现统一按冷缓存报告；`latency_ms`=引擎段（赛题检测时间口径）、`latency_e2e_ms`=接口内全链路（解码+推理+热力图），二者均落库。压测脚本：`test/bench_fullchain.py`（磁盘 vs 零拷贝双口径）、`test/bench_stability.py`（并发长稳+内存监控，200 轮×4 并发=800 次实测 e2e p95 344/max 560ms）。相机/上位机对接用 `POST /api/detect/frame`（帧 bytes 直入，不落盘）。

## 八、常见问题

**Q：检测很慢？**
确认后端是否用上 GPU（评估页延迟基准会显示设备）；确认当前工作点是 fast（accuracy 全槽位约 400ms，cpu 工作点更慢）。本系统单图红线为 1 秒，实测 fast 工作点单图 52-348ms。

**Q：激活新版本后效果变差？**
【模型管理】→【回滚】一键回到次新版本快照；下次先用 A/B 版本对比验证再激活。反馈即学本身也带回归门控，检测到性能退化会自动回滚当次更新。

**Q：反馈提交了，模型什么时候生效？**
立即生效。反馈即学在提交后 ~72-140ms 内完成引擎在线更新，后续检测帧即使用更新后的模型。反馈页的"未巩固反馈数"只是提示还有多少学习成果未落盘成正式版本，不影响在线生效。

**Q：在线学习会遗忘旧知识吗？**
有双重保护：引擎侧的回归门控（每次更新后在锚定集上校验，退化即自动回滚）+ 系统侧的版本快照制（巩固前自动留痕，任何时候可回滚到任一历史版本）。

**Q：gray（待复核）是什么意思？**
分数落在正常阈值与异常阈值之间的灰区，引擎不强行二分类，标记为待复核。建议人工确认后提交反馈——这正是引擎校准最有价值的学习信号。

**Q：数据安全吗？**
所有数据（图像、视频、检测记录、反馈、版本快照）都在本地 `storage/` 与 SQLite 中，无任何外网依赖（DINOv2 权重首次下载后走本地缓存）。

## 九、工业级验收

仓库根目录的 `_acceptance_m9.py` 是端到端工业级可用性验收脚本，用 demo5 已测过的 MVTec 数据集（默认 bottle/cable/tile/screw，可命令行指定子集）在**隔离临时环境**（不污染生产库与 storage）中对每个品类走完真实工业全流程：

```
python _acceptance_m9.py            # 全品类
python _acceptance_m9.py bottle     # 单品类
```

每品类验收七个维度：**数据登记**（100 正常 + 5 缺陷锚定入库，30 张评估集不入库防泄漏）→ **部署效率**（prepare 计时，红线 <120s）→ **检测质量**（30 图 AUROC 对照 demo5 基线 -0.05 容差）→ **延迟红线**（峰值 <1s）→ **反馈学习**（错检图反馈即学，断言反馈前判定 pre 已记录）→ **翻案曲线** → **版本固化**（巩固 v2）→ **数据治理**（批次建档 + 四维数据树）。每品类输出一张验收表，最后输出总表与 PASS/FAIL 结论（exit 0/1）。

2026-08-23 实测（GTX 1660S，fast 工作点）：bottle AUROC 1.0000 / cable 0.9644 / tile 0.9667 / screw 0.8444，全部达到 demo5 基线 -0.05 容差线；prepare 均 18s；单图延迟均值 56-72ms、峰值 212ms——**工业级可用性验收 PASS**。详细数据与发现见 `docs/重构设计_demo5引擎.md` §6.18。

验收口径提示：AUROC 验收线对齐 demo5 基线协议（sanity 加权 + 100 正常图）。若自行把正常图降到 20 张级别，CDF 校准粒度变粗会使 AUROC 系统性偏低约 0.1——这反映的是少样本部署的真实精度边界，不是系统故障（正式上线建议正常图 ≥50-100 张）。

### 多数据集扩展验收（M9b，2026-08-23）

`_acceptance_m9.py` 支持 demo5 实测过的全部数据集，命令行用 `--datasets` 选择（缺省 mvtec）：

```
python _acceptance_m9.py --datasets btad,mpdd,data_local   # 扩展数据集
python _acceptance_m9.py --datasets all                    # 全部静态数据集（10 品类）
python _acceptance_m9.py --gyudet-learn                    # 仅 gyudet 跨域学习增益专项
```

各数据集结构差异（BTAD 正常目录叫 ok、缺陷统一 ko、图片含 .bmp；MPDD 缺陷目录按类型命名不统一；data_local 缺陷分四类目录）已由脚本内数据集配置层自动适配。总表按数据集分组打印。

2026-08-23 实测：BTAD 0.9244/0.8489/1.0000、MPDD tubes 0.8889 / bracket_white 0.9867，均过验收线；data_local solder_smt 0.3889 未过线——其 0.683 基线是 equal 权重口径，本系统全局 sanity 加权在域差场景不可外推（已知边界，详见设计文档 §6.19 发现 2）。

### gyudet 跨域学习增益专项（反馈驱动持续学习的直接证据）

`--gyudet-learn` 验证跨域场景下"静态失效 → 反馈即学 → 持续提升"：train 域 100 正常 + 5 缺陷锚定部署，valid 域初始评估后把错检逐张反馈（cap 20），每 5 条反馈在 30 张未反馈 holdout 上重估 AUROC，输出学习曲线 k=0→5→10→…。验收标准为学习增益 ≥+0.05 且延迟峰值 <1s（静态 AUROC 不参与判定）。

2026-08-23 实测：初始 0.6889 → 14 条反馈后 0.7533（**+0.0644**），延迟峰值 251ms，PASS。这条"初始 → 反馈后"增益曲线是赛题"反馈驱动持续学习"叙事的核心证据。

## 十、产线部署（M10：安全与集成）

### API 鉴权

`configs/default.yaml` 的 `security.api_key` 默认空（关闭，开发用）。**产线部署必须设置**：

```yaml
security:
  api_key: "换成足够长的随机串"
```

开启后除 `/api/health`（负载探活豁免）外所有 REST 接口需请求头 `X-API-Key`。桌面端 UI 自动读取（环境变量 `AOI_API_KEY` 优先，其次同机 configs），无需手工配置。`/api/file` 本地文件读取接口带白名单：仅 storage 目录内与已登记入库的图片/热力图路径放行，其余 403。

### 多角色权限（M11c）

产线多岗位共用时，用 `security.keys` 给不同岗位发不同密钥（角色 operator < engineer < admin）：

```yaml
security:
  keys:
    "产线操作员的key": operator     # 检测/反馈/查询
    "工艺工程师的key": engineer     # + 模型准备/扫描、自学习巩固、删图、孤儿清理
    "质量负责人的key": admin        # + 激活/回滚、删数据集批次
```

角色不足的请求返回 403 并注明所需角色。`keys` 非空即视为开启鉴权；单 `api_key` 命中者视为 admin（兼容 M10 旧配置）。

**UI 角色化（M15c）**：桌面端用哪个 key 启动（`AOI_API_KEY` 或 default.yaml），主窗口顶栏即显示对应角色徽标，并按角色裁剪左侧导航——operator 只保留「实时监控 / 标注反馈 / 统计报表」三个日常页，engineer/admin 全量。产线给操作员发 operator key 即可获得极简操作界面，管理层页面不会误入。

### 对位偏移预警（M11d）

模型准备时系统自动锚定首张训练正常图为对位参考（随快照持久化）。检测每帧用相位相关估算当前图相对参考的平移量，超过阈值（`alignment.warn_px`，默认 4.0，256 参考分辨率像素）时：

- 响应带 `align_warn: true` 与 `align_offset: [dx, dy]`；
- 监控页出现橙色"对位偏移"徽标；
- 推送 webhook `align_warn` 事件并落库（Detection.n_tiles）。

用于治具松动/传送带漂移的早期提醒，不影响正常检测判定；预警通道自身异常不会中断检测。

### 平移误报抑制（TTA，默认关）

若产线存在难以消除的对位抖动且节拍允许（复检工位），可在引擎配置开 TTA 平移搜索：

```yaml
decision:
  tta: { enabled: true, shift: 10 }   # 判 anomaly/gray 时 ±10px 四向重打分，找到对齐低分则改判 normal
```

代价：触发时额外 4 次完整推理（fast 工作点最坏 ~1.6s），**在线 1s 节拍下不要开启**。demo5 实测平移 10px 误报率 93%→27%。

### 服务日志轮转（M11e）

服务端日志自动落盘 `storage/logs/server.log`，单文件超 `logging.max_mb`（默认 10MB）自动轮转，保留 `logging.backups`（默认 5）份历史。

### 长稳/并发压测

后端运行中执行（需已完成模型准备）：

```bash
python test/bench_stability.py --category bottle --rounds 200 --concurrency 4
```

随机取样少量图并发轮询检测，输出延迟 p50/p95/max、错误数与超 1s 红线次数，报告写 `storage/logs/bench_stability_*.json`。用于验收前长稳验证（24h 连续运行可将 rounds 调大后挂机）。

### PLC 触发拍照检测（AOI 上产线标准形态）

```yaml
plc:
  trigger_dir: "D:/aoi_trigger"   # 光电信号触发相机后的落图目录
```

产线对接流程：PLC 光电信号 → 相机拍照落图到 `trigger_dir` → 上位机/MES 调 `POST /api/detect/trigger`（form 参数 category）→ FIFO 取最早一张同步检测，节拍内返回 `{decision: normal/gray/anomaly, final_score, latency_ms, defect_boxes...}` → 已检图自动移入 `trigger_dir/processed/`。每次触发记 `plc_trigger` 审计日志。

### 缺陷自动归档

`archive.enabled: true`（默认开）时，判定为 anomaly 的帧**不经人工反馈**自动拷贝到 `storage/archive/{品类}/{日期}/` 并登记入数据页（split=archive，挂当日"自动归档"批次）——用于证据留存、质量复盘与训练回流。可在 `archive.decisions` 里加 `"gray"` 把待复核帧也归档。

### 产线日报与审计导出

- `GET /api/stats/export?days=30&category=bottle` → 产线日报 CSV（Excel 直开）
- `GET /api/logs/export?action=feedback` → 审计日志 CSV

### 无头部署（无显示器产线服务器）

系统后端不依赖桌面 UI，可纯 API 运行：

```bash
docker compose up -d            # 或 python server.py
curl -H "X-API-Key: <key>" http://<server>:8017/api/health
```

全部操作（导入/prepare/检测/反馈/导出）均可由上位机经 REST 完成；UI 仅用于配置与复盘，可装在任意能访问服务器的工位电脑上。
