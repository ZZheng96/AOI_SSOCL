# AOI 系统用户视角审查（2026-08-26）

> 视角：**只有自己数据集（MPDD）的新用户**，首次使用 AOI_sys 桌面端。
> 方法：按 demo5 用户操作流（数据管理 → 准备模型 → 评估 → 实时监控 → 反馈 → 报表）在真实界面上逐步操作，以"用户会怎么想/怎么问"为标准逐页审查。
> 结论先行：功能全通，但存在三类"用户看不懂/会误会"的问题——**内部代号泄漏（demo4/demo5/mvtec）、工程师黑话（L0-L3/sem/disc/shead/AUROC）、他人历史数据混入（demo4 模型、2060 GPU 文案）**。

---

## 一、逐页评价

### 1. 顶栏
| 项 | 评价 |
|----|------|
| "AOI 实时在线 AI 质检" / 当前品类 | ✅ 清楚 |
| "延迟预算 <200ms" | ⚠️ 用户不懂"预算"含义，会想"是限制我吗" |
| 角色徽标 admin | ⚠️ 无意义（用户不知道角色体系） |

### 2. 工作台（首屏）
| 项 | 评价 |
|----|------|
| 今日检测/不良/待复核 KPI | ✅ 好 |
| "数据→训练→验收→投产" 阶段条 | ✅ 好（有流程感） |
| "最佳AUROC" 列 | ❌ 用户不知 AUROC 是什么，不知道"多高算好" |

### 3. 数据管理页（困惑重灾区）
| 项 | 评价 |
|----|------|
| **"导入MVTec"按钮** | ❌ 用户只有 MPDD：`我没有 MVTec 数据，我的 MPDD 怎么导？` |
| 批次名 `mvtec_bracket_black_20260826_...` | ❌ 明明自己的数据，名字却带 `mvtec` |
| 树节点提示 "可支撑层级（demo5 §0 分层契约）：L0/L1a/L1b/L2/L3" | ❌ 用户看到 `demo5` 一头雾水；L0-L3 完全不懂 |
| 划分下拉 `train/val/test/template/feedback`、标签下拉 `normal/anomaly` | ❌ 全英文术语，用户要猜 |
| "孤儿文件清理" | ⚠️ 不懂"孤儿文件"是什么 |
| 表格"来源"列（mvtec/demo5/…） | ⚠️ 内部值泄漏 |

### 4. 模型管理页（困惑最重）
| 项 | 评价 |
|----|------|
| 窗口标题 "准备模型（**Demo5** 少样本冷启动）" | ❌ 用户看到 Demo5 再懵 |
| "场景分层 L0/L1a/L1b/L2/L3"（描述含"图像级标注 ≤100+30（赛题标准）"） | ❌ 不懂"≤100+30""赛题标准"；系统还自动预选 L1b，用户不知为何 |
| "工作点 fast/accuracy/cpu"（描述含 sem/disc/shead、blob/trad/layout） | ❌ 一堆英文缩写 |
| "强制重备（覆盖已有版本）"默认勾选 | ❌ 新用户：`我还没建过版本，哪来的"已有版本"？` |
| 模型版本表混入 **`demo4-solder_smt` / `demo4-gold_finger`** | ❌ `demo4 是谁？为什么别人的模型在我的系统里？` |
| **v1/v2 多版本无说明** | ❌ `v2 是 v1 的什么？哪个在用？` |
| 指标列显示 `slot_names=['sem','disc','shead']` 原始字段 | ❌ 纯内部数据 |
| "A/B 对比""巩固版本""回滚到上一版本" | ⚠️ 术语无解释 |

### 5. 评估看板
| 项 | 评价 |
|----|------|
| 表头 AUROC / AP / F1 | ❌ 用户不懂指标，不知道"多高算通过" |
| "延迟明细（**2060** GPU · 2500×2500…）" | ❌ 用户机器是 1660 SUPER——文案写别人的显卡，会怀疑准确性 |
| "流程引导"（✓ 通过→去激活 / ✗ →补数据） | ✅ 好 |

### 6. 实时监控
| 项 | 评价 |
|----|------|
| 判定 正常/待复核（灰区）/异常 + 归因 + 框 + 热力图 | ✅ 好，有中文 |
| 槽位条 `sem/disc/shead` + "触发槽位：无（加权融合判定）" + 权重 `sem=0.18…` | ❌ 不懂"槽位"和三个缩写 |
| "对位偏移""开放集未知模式""灰区 ≥0.732" | ⚠️ 专业词 |

### 7. 标注反馈
| 项 | 评价 |
|----|------|
| "误检（实为正常）/漏检（实为异常）/确认正确/新缺陷" | ✅ 用户能懂 |
| "学习状态：已学习 / 仅落库" | ❌ 不懂"落库"和"系统自动学习"的概念 |
| "巩固版本""内部状态…"（normal_bank/defect_bank） | ⚠️ 纯工程师语言 |

### 8. 统计报表 / 学习曲线 / 系统设置
| 项 | 评价 |
|----|------|
| 报表 KPI、CSV 导出、新建品类向导 | ✅ 基本可懂 |
| 学习曲线无导语 | ⚠️ "学习"概念未解释 |

## 二、问题归类（按用户伤害排序）

| 类别 | 实例 | 用户真实反应 |
|------|------|-------------|
| **A. 内部代号泄漏** | `demo5`/`demo4`/`mvtec_*` 批次名、`导入MVTec`、树节点 demo5 契约 | "这是什么？我的数据怎么会叫 mvtec/demo？" |
| **B. 工程师黑话** | `L0-L3`、`sem/disc/shead`、`AUROC/AP/F1`、`normal/anomaly`、`train/val/test`、`孤儿文件`、`槽位`、`快照`、`巩固`、`落库` | "每个字都认识，连起来不知道干嘛" |
| **C. 他人数据/配置混入** | 模型表混入 `demo4-*` 模型、多版本无说明、评估页写 2060 GPU | "这是别人的数据/配置吗？我能信吗？" |

**C 类最伤信任**（怀疑系统不干净）；**A 类最直接**（看到就懵）；**B 类可通过中文化+一句话解释缓解。

## 三、改进建议（按优先级）

| # | 改进 | 对应问题 |
|---|------|---------|
| 1 | 导入按钮改"导入数据集"，支持 MVTec/MPDD/BTAD/自采文件夹选择 | A |
| 2 | 批次名去掉 `mvtec_/folder_` 内部前缀，显示用户可读名 | A |
| 3 | 模型表按当前品类过滤，隐藏 demo 历史模型（或"仅显示本品类"开关） | C |
| 4 | 版本（v1/v2）加列说明：首次训练 / 在线巩固 / 当前使用 | C |
| 5 | 评估页硬件文案改为实际设备（读 /api/health），指标 AUROC/AP/F1 加 tooltip 人话解释 | B/C |
| 6 | 场景分层下拉改人话（"只有正常图 / 有正常+缺陷标签 / 有缺陷框标注"），去掉 L0-L3 代号前置 | B |
| 7 | 槽位 sem/disc/shead 中文化（语义相似 / 判别器 / 伪异常判别）+ 一行说明 | B |
| 8 | 划分/标签下拉中文化（训练/验证/测试/反馈；正常/异常） | B |
| 9 | 术语提示统一："孤儿文件"→"无归属图片"；"巩固"→"把反馈学进模型"；"落库"→"已记录" | B |
| 10 | 新用户首启导语：解释"系统会用你的反馈自动提升检测" | B |

---

## 四、结论

系统功能完整、流程走得通，但"面向工程师交付"的味道过重：内部代号、历史演示数据、英文术语直接暴露给只有自己数据的普通用户。**优先做 1/3/5 三项**（导入通用化、模型表隔离、硬件/指标人话化），即可消除用户"我的系统不干净/看不懂"的主要体感。
