> 本文只覆盖 `D:\CGAIC\data_local` 下的本地数据：`gold_finger`、`solder_smt`、`component`、`extra_part`、`throughole`。
> `data_origin` 下的公开基准数据不属于本文流程。PCB Dual 的传统引擎、AOI Core 特征引擎和 `dual` 融合模式是三条可选择的检测路径，不能把模板/ROI 配置误认为特征模型已经训练完成。

## 2. 启动与页面顺序

在 `PCB_Dual` 目录启动应用：

```powershell
python main.py
```

页面顺序为：

```text
算法调试 → 预处理 → 自动检测 → 历史 → 模板建模 → 特征学习（AOI Core）
```

建议首次使用按以下顺序操作：

```text
选择本地数据 → 模板建模/标定 → 配置传统算法 → 特征学习（可选）
→ 自动检测 → 历史追溯 → 反馈与复盘
```

## 3. 选择本地数据

1. 在「预处理」或「特征学习」页面选择本地数据根目录或具体品类。
2. 普通 AOI Core 数据集推荐选择已经整理成以下结构的根目录：

```text
<品类>/
├── train/good/
├── test/good/
└── test/<缺陷类型>/
```

3. `component`、`extra_part`、`gold_finger`、`solder_smt` 可按各自标准目录进入 AOI Core 特征学习。
4. `throughole` 虽已增加标准化副本，但它的主价值仍是 PCB Dual 插件算法资源，不应只靠普通图片导入替代模板和 ROI 标定。

## 4. 模板建模与 ROI 标定

### 4.1 普通品类

对 `component`、`solder_smt` 等需要模板的品类：

1. 进入「模板建模」。
2. 加载标准图或模板命名图片。
3. 建立模板名称、基准区域和检测区域。
4. 保存模板后，在「自动检测」中选择对应模板。

### 4.2 throughole 通过孔

`data_local\throughole` 目录中以下资源各有不同用途：

```text
throughole/template/            # 13 张标准 ROI PNG 副本
throughole/template_resources/  # 配套 templ_*.json 标定信息
throughole/roi_resources/       # 原始焊点 ROI 小图
throughole/roi/                 # 原始 ROI 资源，保留
throughole/standard_roi/        # 原始标准 ROI 资源，保留
```

操作要求：

1. 在「模板建模」加载标准图，确认模板名称与对应 `templ_<编号>.json` 一致。
2. 在「标定」中使用对应 ROI；不要把 ROI 小图直接当成完整测试图。
3. 至少一个焊点 ROI 才能运行盘内通过孔缺陷；连锡需要至少两个焊点 ROI。
4. 多焊点配置主要运行连锡；孔洞、少锡、多锡（包锡）、不出脚应使用单焊点或自动锡面配置。
5. 保存模板/标定后再进入「自动检测」，不要只在算法调试页试跑就认为正式模板已经发布。

## 5. 三种检测模式

### traditional：传统引擎

适合通过孔、焊点、模板差分等有明确算法和标定约束的场景。检测前必须确认算法就绪、模板存在、ROI 数量满足要求。

### feature：AOI Core 特征引擎

适合使用本地数据集进行特征学习的场景。先在「特征学习」选择品类并准备/加载模型，再到「自动检测」选择 feature 模式。小样本数据只能用于流程演示或趋势观察。

### dual：双引擎融合

同一张图分别进入传统引擎和 AOI Core 特征引擎，再由融合规则统一判定：

1. 必需引擎缺失或报错 → `ERROR`；
2. 任一引擎判定 `NG` → `NG`；
3. 无 `NG` 但传统引擎要求复核 → `REVIEW`；
4. 无 `NG` 但特征引擎处于灰区 → `GRAY`；
5. 两侧均正常 → `OK`。

`dual` 模式要求两侧依赖都准备好。传统模板/ROI 和 AOI Core 模型分别配置，不能用其中一侧的准备结果冒充另一侧已验收。

## 6. 自动检测

1. 进入「自动检测」。
2. 选择数据来源、检测模式、算法/模板和输入图片。
3. 确认通过孔场景的模板、标准图、ROI 已就绪。
4. 运行单张少量回放，查看统一判定、缺陷框、置信/分数及传统侧与特征侧明细。
5. `dual` 模式重点检查两侧结果是否同时返回、融合判定是否符合优先级，而不是只看最终颜色。
6. 通过孔的 `OK/NG` 输出图适合作为少量回放样本；它们不是带有可靠五类缺陷标签的完整测试集。

## 7. 历史与反馈

- 「历史」按检测记录查询原图、模式、算法、模板和最终结果。
- 通过孔异常若只能确认 NG、无法确认具体缺陷类型，反馈时使用通用异常说明，不要填写猜测的孔洞/少锡等类型。
- 对传统算法参数、模板或 ROI 的修改应重新保存版本并做少量回放；不要覆盖历史结果。
- 对 AOI Core 特征模型的反馈应回到 AOI Core 的标注反馈/学习提升链路，形成候选、验收和版本激活，不等同于直接修改 PCB Dual 传统规则。

## 8. 各本地数据的推荐流程

### gold_finger

```text
选择 gold_finger → 特征学习准备模型 → 少量评估 → 自动检测 feature/dual
→ 历史 → 反馈 → AOI Core 学习提升
```

有掩码且样本量相对适中，适合演示完整特征学习闭环。

### solder_smt

```text
选择 solder_smt → 模板/预处理配置 → traditional 回放
→ 特征学习（可选）→ dual 对照 → 自动检测 → 历史复盘
```

缺陷类型可按目录区分；正常训练图较少，评估时注意样本量。

### component

```text
选择 component → 模板建模 → traditional 模板差分
→ 特征学习（可选）→ 自动检测 → 历史
```

8 张模板图、训练正常图和检测图数量都很少，适合验证模板流程，不适合作为统计验收集。

### extra_part

```text
选择 extra_part → 预处理 → 特征学习准备模型
→ 自动检测 feature/dual → 历史
```

无标准模板；名称含 `*_temp.jpg` 的图片不会自动成为模板。

### throughole

```text
加载 template + ROI → 保存模板/标定 → traditional 通过孔回放
→ 准备 AOI Core feature（可选）→ dual（可选）→ 历史
```

优先验证传统插件算法是否满足模板与 ROI 约束。AOI Core 导入只作为辅助的标准目录演示，`test/anomaly` 不代表具体缺陷类型。

## 9. 常见误区

- 只导入 `roi` 小图就开始特征学习：错误，ROI 是传统算法的区域资源。
- 只有传统算法回放结果就宣布 `dual` 已验收：错误，必须让两侧引擎在同一张图上真实返回并核对融合结果。
- 把 `outputs/NG` 自动拆成五类缺陷：错误，当前文件名不足以可靠恢复逐图缺陷类型。
- 把模板建模、模型训练、模型激活当成一步：错误，三者分别属于模板资源、AOI Core 模型和正式投产版本。
- 用极少量 `component` 或 `throughole` 演示图报告生产性能：错误，只能报告流程是否跑通和少量样本现象。
