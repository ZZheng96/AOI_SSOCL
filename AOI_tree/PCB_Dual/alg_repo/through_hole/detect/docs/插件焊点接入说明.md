# 插件焊点接入说明

把本交付包的插件焊点缺陷检测接入 PCB 检测工程算法池。契约与样例包一致；算法为标准图对比 + 配准 + 五类缺陷规则。

**本次交付范围**：`src/`、`docs/`、`test_src/algorithms/pcb_through_hole/`。宿主已有真正的 `core`，无需契约替身。

## 一、交付清单

| 路径 | 作用 |
|------|------|
| `src/algorithms/pcb_through_hole/` | 算法入口 + 检测引擎（整目录拷贝） |
| `src/resources/config/alg/pcb_through_hole/pcb_through_hole_solder_alg.json` | 实例配置（`defaultParam`） |
| `src/resources/config/alg_pool/pcb_through_hole_algs.json` | 算法池注册示例 |
| `test_src/algorithms/pcb_through_hole/` | 单元测试（含「注册→执行」；无宿主池时 skip） |
| `docs/插件焊点接入说明.md` | 本文 |

## 二、接入契约

1. 继承 `core.entities.algorithms.IDetectionAlgorithm`。
2. `algorithm_code` 与实例 JSON 的 `algorithmCode` 一致：`pcb_through_hole_solder_defect`。
3. `__init__(self, config_path=None)` 必须 `super().__init__(config_path)`。
4. `default_config()`（`@classmethod`）返回默认参数 `dict`。
5. **唯一入口是 `run()`**：

   ```python
   def run(self, image, config,
           roi_bbox=None, original_template_image=None, multiple_roi_images=None
           ) -> AlgorithmResult:
   ```

   模板对比型：必须提供 `original_template_image`，否则 `code=1`。

6. `run()` 内不向外抛异常：错误一律 `code=1` + `ResultType.ERROR`。
7. 用 `merge_config(self._defaults, config)` 合并参数。

可选辅助（非池契约，供界面预生成 Mask / 预览配准框）：`prebuild_template`、`preview_roi`、`clear_template_cache`。

## 三、返回 `AlgorithmResult`

| 字段 | 说明 |
|------|------|
| `code` | `0` 成功 / 非 0 失败 |
| `message` | `"ok"` 或错误描述 |
| `algorithm_code` | `self.algorithm_code` |
| `cost_time` | 耗时（秒） |
| `result_type` | 成功 `PARTS`，失败 `ERROR` |
| `parts` | `List[DetectPartBox]`，相对输入图，左上角+宽高 |
| `metadata` | 可视化放 `metadata["output_image"]`；另有 `status`（OK/NG/REVIEW）、`defect_ids` 等 |

缺陷 `class_id`：`12` 孔洞、`13` 少锡、`14` 多锡、`15` 连锡、`16` 不出脚。

## 四、实例配置

```json
{
  "algorithmId": 9101,
  "algorithmCode": "pcb_through_hole_solder_defect",
  "version": 1,
  "remark": "插件焊点缺陷检测",
  "defaultParam": {
    "enable_review": true,
    "solder_mode": "ellipse",
    "enabled_defects": [12, 13, 14, 15, 16],
    "void_preset": "MED",
    "insuf_preset": "MED"
  }
}
```

完整字段以交付的 `pcb_through_hole_solder_alg.json` 为准；`algorithmId` 接入时按宿主规则改为真实 ID。

## 五、算法池注册

写入生产池（如 `cv_detect_algs.json` 的 `cv_algorithms`）：

```json
{
  "algorithm_code": "pcb_through_hole_solder_defect",
  "class_path": "algorithms.pcb_through_hole.pcb_through_hole_solder_alg.PcbThroughHoleSolderAlg",
  "description": "插件焊点缺陷检测（孔洞/少锡/多锡/连锡/不出脚）",
  "idle_timeout": 600,
  "timeout": 120,
  "config_path": "./resources/config/alg/pcb_through_hole/pcb_through_hole_solder_alg.json"
}
```

- 将 `src/algorithms/pcb_through_hole/` 拷入宿主 `src/algorithms/`。
- 将实例 JSON 拷入宿主 `src/resources/config/alg/pcb_through_hole/`。
- 运行时工作目录为宿主 `src`；`config_path` 相对 `src` 解析。

## 七、常见坑

- 入口是 `run()`，不是 `detect()`；必须传 `original_template_image`。
- `run()` 内不抛异常；可视化只放 `metadata["output_image"]`；框坐标相对输入 `image`。
- Windows 测试前 `set PYTHONUTF8=1`。
- 池返回 `None`：多半是抛异常、方法名错，或 `class_path`/`config_path` 不对。
