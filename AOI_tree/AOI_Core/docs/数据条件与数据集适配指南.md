# 数据条件与数据集适配指南

> 用途：明确「拿到一批数据 → 判断用哪个数据条件 → 如何处理导入」的完整路径。
> 适用范围：主干系统 AOI_Core（与算法引擎同源）与提交材料说明。
> 更新：2026-08-30（含 L3 模板链路落地后的实测结论）

---

## 1. 数据条件总览（L0-L3 分层）

系统不为单一数据条件设计，而是声明**可用信息分层模型**——同一套专家接口，按用户实际拥有的数据标注/素材激活不同槽位：

| 数据条件 | 用户需提供 | 激活能力 | 适用场景 |
|---------|-----------|---------|---------|
| **L0 零样本** | 无任何标注 | 正常分位数阈值基线（blob/trad/layout 兜底） | 新品类紧急上线、无历史数据 |
| **L1a 图像级标注**（赛题标准） | ≤100 正常图 + ≤30 缺陷图 | 全槽位（sem/disc/shead/…）+ 场景分层 | 标准协议评测、常规产线部署 |
| **L1b 定位标注** | 缺陷位置框/掩码 | + 判别头训练（更准的类型归因与定位） | 有标注体系的产线 |
| **L3 模板比对** | 金样板/标准 OK 板图 | + tpl 模板差分槽位（域不变） | 强配准品类（PCB）、对位稳定的产线 |

> 判定原则：**数据条件 = 你手上真实拥有的标注/素材**。系统在准备模型时按数据体检自动判定（无工单时）或按工单条件聚合（有工单时），无需手选代号。

## 2. 各数据集适配对照表

| 数据集 | 目录约定（文件系统） | 适配器 | 适用数据条件 | 处理要点 |
|--------|--------------------|-------|-------------|---------|
| **MVTec AD**（15 品类） | `{root}/{cat}/train/good/` + `test/{good|缺陷类}/` | mvtec_like | **L1a**（默认协议）；L0 | 直接导入即可，无需改造；预训练 + 泛化验证 |
| **BTAD**（3 品类） | `{root}/{cat}/train/ok/` + `test/{ok|ko}/` | mvtec_like（ok→good、ko→defect 自动映射） | **L1a**；L0 | 直接导入（MVTec 入口自动兼容） |
| **MPDD**（6 品类） | 同 MVTec | mvtec_like | **L1a**；L0 | 直接导入 |
| **GYU-DET** | `{root}/...`（train/test 真实跨域 + YOLO txt 框标注） | gyudet（box 标注） | **L1a + 在线学习**（学习曲线主验证集）；跨域（train 拟合/test 测试） | 缺陷框标注可提升定位；是"换线跨域适应"的标准测试 |
| **data_local**（自采 4 品类：component / extra_part / gold_finger / solder_smt） | `{cat}/train/good/` + `test/{good|defect/…}/` | datalocal | **L1a**（诚实域差基线 ≈0.40）；**L3 模板比对**（提供模板时 **AUROC 1.0**） | 正常图为"修复图"（repaired），可直接作训练样本；**模板图（金样板）需单独组织**（见 §4） |
| **自建/产线数据** | 见 §3 约定 | ingest 通用导入 | L0 / L1a / L1b / L3 视标注情况 | 按约定组织目录与命名，见 §3/§4 |

**为何 data_local 推荐 L3**：其正常图（repaired 修复图）天然可充当金样板模板；模板库覆盖产线正常样式后，tpl 差分（域不变）对跨域从 0.72（在线学习）提升到 **1.0（L3 静态，系统链路实测）**。若只按 L1a 处理，跨域静态仅 ≈0.40，需在线学习到 0.72。

## 3. 自建/产线数据的目录与命名约定（ingest）

系统导入时按以下规则自动识别 split 与 label：

```
{根目录}/{品类}/
├── train/good/           # 训练正常图 → split=train, label=normal
├── template/             # 金样板/标准 OK 板 → split=template（L3 用，可选）
├── test/defect/          # 缺陷图（子目录名=缺陷类型）→ split=test, label=anomaly
└── test/good/            # 评测正常图 → split=test, label=normal
```

**命名规则（自动识别为模板图）**：`A_tpl.png` / `A_template.png`（检测图 `A.png` 的同名模板），或放在 `template/` 目录。UI 也可右键图像 →「设为模板图（L3 用）」。

**三条识别规则**（`backend/core/ingest.py`）：
1. 路径含 `template` 目录 → `split=template`
2. 文件名以 `_tpl` / `_template` 结尾 → `split=template`
3. 子目录名含 `good`/`normal` → normal；其余子目录 → anomaly（子目录名记为缺陷类型）

**BTAD 兼容**：`train/ok`、`test/ko` 会被自动映射为 good/defect。

> 注意：普通「文件夹导入」不自动切分 train/test split（需在导入时指定 split，或分次导入）；「MVTec 标准目录导入」自动识别 `{cat}/train/{good}` 与 `test/{good|缺陷}`。

## 4. 按数据条件处理步骤（UI 全流程）

### 4.1 L0 零样本（无标注，应急）
1. 数据管理 → 导入正常图（任意目录，split 不限）
2. 模型管理 → 准备模型 → 数据条件自动判为 L0 → 开始准备
3. 检测：仅用正常分位数阈值基线，缺陷检出能力有限（适用于无任何数据的冷启动应急）

### 4.2 L1a 图像级标注（赛题标准 100+30，最常见）
1. 数据管理 → 新建数据源（选「标准数据集」或「文件夹」，标注档位 L1a）→ 导入
   - 标准数据集（MVTec/BTAD/MPDD）：选根目录，自动分品类
   - 自建数据：按 §3 组织，分次导入 train/good（split=train）、test/defect（split=test）
2. 模型管理 → 准备模型（数据条件自动判为 L1a，运行模式 fast/accuracy/cpu）→ 开始准备
3. 检测 + 反馈学习（错检即学 → 巩固 → 版本管理）

### 4.3 L3 模板比对（提供金样板，PCB/强配准品类）
1. 数据管理 → 新建数据源 → **勾选「提供模板图」**（数据源声明）→ 导入
2. 模板图组织：放 `template/` 目录，或用 `A_tpl.png` 命名，或右键「设为模板图（L3 用）」
3. 工作台 → 新建工单 → 挂该数据源 → 工单条件自动聚合出「模板比对」
4. 模型管理 → 准备模型 → 数据条件显示「模板比对（按工单条件自动判定）」→ 开始准备
5. 检测：tpl 槽位（模板差分，域不变）+ 在线学习保持

**模板注意事项**（2026-08-30 系统链路实测）：
- 模板收集上限 500 张（已放开）；**模板库需覆盖产线正常样式分布**——模板 68 张未覆盖 test 域样式时 tpl 反向（AUROC 0.27），全库覆盖时 1.0（详见 §5）
- tpl 相位相关配准默认开：对位漂移 ≤50px 场景自动校正（像素差 19.35→1.58），配对/无漂移场景自动跳过（不增加开销）
- 像素差分通道默认关（纯 DINO 特征差分，85 模板 p50=484ms，满足 <1s 红线）

### 4.4 在线学习（所有数据条件的共性能）
- 三类反馈（判对/判错/无反馈）驱动：缺陷样例拦截、正常回流校准、版本回滚
- 学习曲线页可量化"越用越准"；标准品类单调不退化（U110v2/U111）

## 5. 关键边界与红线（诚实登记）

| 红线/边界 | 说明 |
|-----------|------|
| **test 域不得进 fit** | 代码级数据隔离断言：test 域路径进入拟合即报错（红线 1） |
| **模板须显式提供**（红线 2，作用域仅 L1a） | L1a（不提供模板）下，靠文件名推断配对 = 泄漏，禁用；L3（提供模板）下，模板为显式契约，配对属数据条件合法组成，不受红线 2 约束 |
| **模板覆盖依赖** | 模板库需覆盖产线正常样式（金样板）；覆盖不足时 tpl 反向，靠配准 + 在线学习兜底（已量化：68 模板 0.27 vs 85 模板 1.0） |
| **CDF 只拟合 train/good** | 校准与阈值只用训练正常分布（红线 3） |
| **速度红线** | 单图推理 <1s（L3 全库模板 p50=484ms；TTA 默认关） |
| **诚实口径** | 所有指标无泄漏口径；跨域用大锚定（eval_n≥40）复核，阴性结果如实登记 |

> **「数据集」≠「数据条件」（关键区分，2026-08-30 明确）**：数据集是原始文件的组织方式，可能带特定命名（如 data_local gold_finger 的 `_repaired` 后缀，属用户自建数据的合法结构，与标准数据集目录约定不必完全一致）；数据条件是用户声明、系统实际拥有的标注/素材层次（L0-L3）。**红线按数据条件生效，而非按数据集目录结构一刀切**：红线 2（文件名配对禁止）只约束 L1a（不提供模板）——该条件下系统不得靠文件名推断"哪张是哪张的配对"来注入 test 域信息；在 L3（提供模板）下，模板图由用户显式提供（`template/` 目录 / `_tpl` 命名 / UI「设为模板图」），模板与检测图的对应关系是数据条件的合法组成，不属于红线 2 禁止的"隐式文件名推断配对"。**成绩必须按数据条件标注**：L3 的 AUROC 1.0 与 L1a 的 0.72 是不同数据条件下的结果，不可混用。

## 6. 速查：拿到数据第一步怎么判断

```
拿到一批图
├─ 有金样板/标准 OK 板？ ── 是 → 组织 template/ + train/good + test/ → 走 L3（§4.3）
│                        ── 否 ↓
├─ 有正常图 + 缺陷图（图像级）？ ── 是 → 组织 train/good + test/ → 走 L1a（§4.2）
│                        ── 否 ↓
├─ 只有正常图？ ── 是 → train/good → 走 L1a（判别头仅伪异常训练）或 L0
│                        ── 否 ↓
└─ 什么都没有 → L0 零样本应急（§4.1）
```

**数据集示例结论**：
- MVTec/BTAD/MPDD → **L1a**（标准目录直接导入）
- GYU-DET → **L1a + 在线学习**（跨域适应验证）
- data_local gold_finger/solder_smt → **L3 模板比对**（repaired 正常图作模板）+ 在线学习
- 用户产线（PCB 类）→ **L3**（金样板）+ L1a 并存（按品类/工单切换）

## 7. 数据集适配模块（自动识别 + 用户确认，2026-08-31 新增）

> 用途：**不要求数据集是标准形式**。系统只读扫描目录，识别数据集格式与内容构成，
> 产出确认报告给用户核对/修正，确认后按映射批量入库。
> 实现：`backend/core/dataset_adapter.py`；UI：数据管理 → 新建数据源/更新数据 → 导入方式选「智能识别适配」。

### 7.1 支持的格式（自动判定）

| 格式 | 判定条件 | 覆盖 |
|------|---------|------|
| **mvtec_like** | `{根}/{品类}/{train|test}` 结构（品类目录含 train/test） | mvtec、MPDD、BTAD（含 BTech_Dataset_transformed 包装目录）、data_local 全系、data_local/单品类子目录 |
| **yolo_split** | `{根}/train/{images,labels}` | GYU-DET（txt 非空=缺陷，缺失/空=正常） |
| **dir_rules** | 目录/命名规则识别（见 7.2） | test_images 全系（solder/shift/jump） |
| **plain** | 无任何结构/标记 | 兜底：全部待确认 |

### 7.2 识别规则（dir_rules，目录标记优先于文件名）

按 最深层目录标记 > 文件名标记 逐图分类，目录是用户组织语义，优先于文件名：

1. 目录标记：模板（template/样板/**模板**/模板小图）→ **模板图(L3)**；缺陷（NG/ko/bad/miss/missing/**漏检/不良**）→ **缺陷**；正常（ok/good/pass/**良品/误报**）→ **正常**（误报=AOI 假报警，实为正常）
2. 文件名模板标记：`templ_` 前缀 / `_tpl` / `_template` 后缀 → **模板图(L3)**
3. 文件名缺陷关键词：`_Shift_`/`_MissPart_`/`less_tin`/`over_tin`/`tombstone` 等 → **缺陷**（缺陷类型=关键词）
4. 文件名 `_OK` 后缀（X.png 缺陷 + X_OK.png 正常成对命名）→ **正常**
5. 其余 → **未识别**：默认按「缺陷」导入检测组，确认弹窗可逐分组改为 正常/跳过

关键点：**目录标记优先于文件名**——误报/ok 目录里带 ng/miss 字样的文件是假报警；NG 目录里的 `templ_*.jpg` 是缺陷样本。

### 7.3 确认弹窗（用户核对）

- **格式/品类/分组/计数** 一览：mvtec_like 按品类勾选导入；dir_rules 按分组逐行确认未识别图片处理方式
- **品类名**：单品类格式可改（默认根目录名）
- **正常图角色**：命名识别为正常的图片（`_OK`/ok/良品/误报）用作 预训练正常图(train) 或 模板图(L3)（`ok_role` 参数）
- 识别结论回写数据源声明：多品类 → `per_category`，含模板 → `has_template`（工单条件自动聚合）

### 7.4 实测覆盖（2026-08-31，probe 秒级）

| 数据根 | 识别结果 |
|--------|---------|
| data_origin/mvtec | mvtec_like 15 品类（bottle 209 正常 + 83 检测） |
| data_origin/BTAD | mvtec_like 01/02/03（ok→正常、ko→缺陷、掩码 49/200/41 计数） |
| data_origin/GYU-DET | yolo_split（train 584 正常/8314 缺陷——txt 内容判定） |

### 7.5 性能与红线

- probe 只做目录遍历 + 少量 txt 读取，**不解码图像**：mvtec 5354 图 ~1.1s、GYU-DET 11123 图 ~1.2s
- 导入复用 `ingest._register_batch`（快速指纹去重 + 逐图进度），后台任务带进度条
- 数据隔离红线不变：test 域正常图不进预训练组（`groups.py` `_pick` 守卫）；模板图仅由显式标记（模板目录/templ_ 命名/用户确认）产生

### 7.6 真实 UI 实测发现与修复（2026-08-31，非离屏操作）

按前端反馈第 84 行用真实桌面 UI 逐个导入 test_images_shift/电容底座（dir_rules）、
data_local（mvtec_like 4 品类）、test_images_solder（dir_rules 未识别分组），识别确认
弹窗、声明回写、预训练/检测分组全部走通。过程中发现并修复 3 处问题：

| 问题 | 现象 | 修复 |
|------|------|------|
| **统计批次对比 500** | `/api/stats/batch_summary` 500（`not enough values to unpack (expected 5, got 4)`），统计报表批次对比图表不显示 | [routes_stats.py](backend/api/routes_stats.py)：`det_q` 缺 `avg(Detection.latency_e2e_ms)` 列，补齐（检测记录本就带端到端延迟） |
| **模板图混进检测组** | 电容底座 16 张模板图全部被算进"检测组"（detect=16 恰等于模板图数），产线会把这些 L3 参考图当检测样本消费 | [groups.py](backend/core/groups.py)：`compute_groups` 过滤 `split=template` 行，模板图不参与预训练组/检测组（修复后 component detect 16→0、solder_smt 86→82） |
| **识别后标注档位不校正** | data_local 明显有 241 张缺陷图，但数据源声明 label_tier 仍为 L0（用户默认值），工单条件聚合被低估 | [data_page.py](ui/pages/data_page.py) `_sync_source_flags_after_adapt`：按识别结果提升 label_tier（有掩码→L1b、有缺陷图→L1a，只升不降），与 per_category/has_template 一并回写 |

> 教训：UI 实测比接口冒烟更能暴露"数据进产线"环节的语义错配（模板图误入检测批次
> 只有看到树节点分组数才会意识到）；新增模块后应至少走一遍 建源→识别确认→分组 的真实 UI 流程。
