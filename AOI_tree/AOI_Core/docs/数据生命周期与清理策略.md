# 数据生命周期与清理策略

> 2026-08-30 · 适用：AOI_sys（主干）/ PCB_Ins_v2（树枝）
> 回答的问题：**每类数据流向哪里、会不会无限增长、什么时候必须保存、什么时候可以清空、用什么工具清。**

---

## 1. 总原则

| 原则 | 说明 |
|------|------|
| 证据不可丢 | 检测记录（Detection）、复判反馈（Feedback）、审计日志（OperationLog）、模型版本快照——产线追溯与质量举证的依据，默认**只增不删**，按保留期滚动 |
| 派生物可再生 | 热力图、扰动评估图、训练暂存目录、缩略缓存——由原始图+模型随时可重建，**可安全清空** |
| 无界必设上限 | 任何"每次运行都新增"的数据必须有界：日志轮转、滚动条数、TTL 或版本数上限 |
| 清 DB 必配清盘 | 删除 API 只删数据库行；磁盘文件统一由孤儿清理/本工具回收，避免"行没了文件还在" |

---

## 2. AOI_sys 数据流清单

### 2.1 磁盘（storage/）

| 目录 | 内容 | 增长特性 | 保留策略 | 清理方式 |
|------|------|---------|---------|---------|
| `uploads/` | 上传图、单图检测暂存、视频抽帧 | 无界 | 孤儿即清 | 孤儿清理 API（数据页「孤儿文件扫描/清理」） |
| `raw_images/` `raw_videos/` | 导入的原始图/视频 | 随导入增长 | **须保留**（DB Image/Video 行引用其路径） | 删批次时可选删文件；其余靠孤儿清理 |
| `images/{品类}/ds{id}/` | 批次目录 | 随批次增长 | **须保留**（同上） | 删批次联动 |
| `archive/{品类}/{日期}/` | 缺陷自动归档（证据留存+训练回流原料） | 无界（每异常帧 1 张） | 建议按天数保留（如 90 天），超期归档转储 | 手工/计划任务删除过期日期目录 |
| `heatmaps/` | 检测热力图+叠加图（每帧 2 张） | **无界，最大增长点** | 派生物，可全清；产线模式默认不产出（`with_heatmap=False`） | `tools/cleanup_data.py --purge-heatmaps --days 7` |
| `tmp/` | 鲁棒性评估扰动图等临时产物 | 无界 | **随时可清空** | `tools/cleanup_data.py --purge-tmp` |
| `engine/snapshots/{品类}/v{n}/` | 模型版本快照（回滚/审计依据） | 版本单调递增，无界 | 保留 **激活版 + 最近 N 版**（建议 N=5）；孤儿品类整体移入 `_archive/`（可恢复，不硬删） | `tools/cleanup_data.py --snapshots-keep 5`；系统启动时自动孤儿归档 |
| `engine/.../weight_history` | 权重学习历史 | 有界（滚动 300 条） | 自动 | — |
| `pseudo/` | 伪异常合成图 | 无界 | 可再生，随批次删除级联 | 孤儿清理 |
| `models/` | 模型档案库：快照导出 zip（`{品类}_v{n}_snapshot.zip`，2026-08-30 起由导出 API 写入） | 有界（品类×版本数，同版本重导覆盖） | 交付/迁移原料，可手动清理 | 手动（无自动 TTL） |
| `logs/server.log` | 服务日志 | **有界** | 自动轮转 10MB×5 | 无需处理 |
| PLC `trigger_dir/processed/` | PLC 触发已检图（证据防重检） | 无界（只进不出） | 建议按天数保留 | 手工/计划任务 |

### 2.2 数据库（database/aoi.db）

| 表 | 内容 | 增长 | 保留策略 |
|----|------|------|---------|
| `detections` | 每次检测一行（判定/分数/热力图路径） | 无界，主增长点 | **长期保留**（追溯举证）；确需瘦身按工单/日期归档导出 CSV（`/api/stats/export`）后再清 |
| `feedback` | 复判反馈（含作废标志） | 无界 | **永不删**——学习链路的输入，删了学习不可复现 |
| `operation_logs` | 操作/告警审计 | 无界 | 建议保留 90~180 天 | 
| `tasks` | 后台任务记录 | 无界 | 建议保留 30 天 |
| `eval_runs` | 评估记录（per_image 已截断 200 条） | 慢增长 | 长期保留（验收证据） |
| `stats_daily` | 每日统计 | 有界（365 行/年） | 长期保留 |
| `images/videos/pseudo_anomalies` | 资产登记 | 随导入 | 随批次生命周期 |
| `models` | 版本登记（与快照目录对应） | 随版本 | 与快照同生命周期 |
| `datasets/data_sources/work_orders*` | 批次/数据源/工单 | 人工创建，有界 | 人工删除 |

DB 滚动清理：`tools/cleanup_data.py --db-trim --days 90`（只清 operation_logs/tasks）。

### 2.3 何时可以清空（场景速查）

| 场景 | 可以清什么 | 不能清什么 |
|------|-----------|-----------|
| 日常运维磁盘告急 | tmp、heatmaps、超期 archive、超版本数快照 | detections、feedback、激活版快照 |
| 交付/打包前 | tmp、heatmaps、logs、database 备份文件（*.bak）、`__pycache__` | 代码、配置、文档 |
| 换品类重新开始 | 该品类的批次/数据源/工单（UI 或 `--drop-datasource`）+ 快照归档 | 其他品类数据 |
| 彻底重置演示环境 | `tests/_reset_db.py` 清库 + 孤儿清理回收磁盘 | — |

## 3. PCB_Ins_v2 数据流差异

| 位置 | 内容 | 保留策略 |
|------|------|---------|
| `storage/train/{品类}/normal|defect/` | prepare 时整目录重建的训练暂存 | **随时可清**：`tools/cleanup_data.py --reset-train` |
| `storage/outputs/{日期}/` | 检测结果归档（result.json+vis） | 按天数保留：`--purge-outputs --days 30`；历史页也可手动删 |
| `storage/snapshots/{品类}/v{n}/` | 品类模型快照 | 同主干：`--snapshots-keep 5` |
| `templates/{id}/` | 模板（金样板+检测项+参数） | **须保留**（检测基准，删了模板检测即失效） |
| `storage/recipes/` `template_calib/` | 配方/标定参数 | **须保留**（有界） |
| `storage/mes_outbox/` | Mock MES 上报 JSON | 无界（仅 mes 开启时），可按天数清 |
| `inspects/defect_records/alarm_records` 表 | 板级检测/缺陷明细/告警 | 长期保留（证据）；不良过滤命中行物理删除是**设计行为**（原始判定仍在 detections.dual_json） |

## 4. 工具

两系统各带 `tools/cleanup_data.py`：

```powershell
# 报告（默认只读，不改任何数据）
python tools/cleanup_data.py --report
# 演练（dry-run：打印将删内容，不实际删）
python tools/cleanup_data.py --purge-tmp --dry-run
```

全部动作默认 dry 可预演；删除类操作仅影响"派生物/超期数据"，证据链数据（detections/feedback/快照激活版）不会被任何选项删除。

## 5. 已知边界（如实登记）

1. 删除类 API（删批次/清空数据源）只删 DB 行不删磁盘文件--须配合孤儿清理回收磁盘（安全冗余设计：防误删不可逆）。
2. ~~PCB_Ins_v2 删数据源不级联删批次/图片/检测~~ **2026-08-30 已补强**：`DELETE /api/datasources/{id}?purge_files=true` 级联删 DB 行（批次/图片/检测/反馈/缺陷明细/伪异常/视频）+ storage 根内系统文件；外部原始目录（用户数据）永不自动删，返回 `external_skipped` 供手动处理（冒烟：`tests/_smoke_ds_cascade.py`）。
3. `detections` 长期保留策略依赖人工执行（导出 CSV->清理），暂无自动 TTL；产线部署建议纳入运维计划任务。
4. `storage/models/` 内 demo4 时代遗留 `.pt` 文件已无任何读取方（demo4 适配层已随 引擎重构删除），属死文件，可手动清理；新写入方为快照导出 zip（见 §2.1）。
