# AOI 实时在线 AI 质检系统 —— 全流程操作手册

> 入口：在 `AOI_Core` 目录双击运行 `python main.py`（自动内嵌启动后端 8017 端口并打开桌面 GUI；若 8017 已被占用则直接复用已运行的后端）。
> 启动后默认进入**工作台**页面。
> 左侧导航按操作流分组（共 11 项 + 4 个分组标题）：
> **工作台** → **准备**（数据管理 / 数据增强 / 模型管理 / 特征工程 / 评估看板）→
> **投产**（实时监控 / 标注反馈）→ **复盘**（学习效果 / 存档统计）→ **系统**（系统设置）。
> 顶栏常驻（自左至右）：系统标题与副标题 → **当前工单**下拉 → **数据条件**徽标 →
> **算力**徽标 → **产线状态**徽标 → **角色**徽标 → **延迟预算** → **后端连接指示灯**。

## 0. 准备：新建数据源（数据管理）

工单必须挂数据源，故先建源（已有数据源可跳过）。

1. 左侧导航 →「数据管理」→ 点「**新建数据源**」
2. 弹窗填写：
   - **名称**、**模态**（图片/视频）
   - **源类型**：本地目录 / RTSP 实时流 / 视频文件（循环模拟实时流）
   - **标注档位**（L0 无标注 / L1a 图级标签 / L1b 缺陷位置标注）。
      L1b 的判定依据是掩码：`ground_truth/` 目录或 `*_mask` 后缀文件计为掩码
     （如 MPDD 的 ground_truth 掩码），**只计数不入库**；体检规则
     `有掩码且有缺陷图 → L1b`。注意（2026-09-13 修正口径）：**掩码标出的
     缺陷区域不作为"正常样本"参与训练**——判别模块的正常样本只取正常图块
     和缺陷图中经掩码核验为正常的图块；掩码缺陷区域仅作伪异常移植源
     （抠出来贴到基底上合成"异常"训练样本）。定位信息同时由反馈路径
     （框级反馈）消费
   - 勾选「数据已分品类」「提供模板图」（模板命名 `A_tpl.png` 自动配对）
   - **预训练正常图 100 / 预训练异常图 30 / 检测批次图数 30**（可调）
   - **导入数据**：智能识别适配（推荐，可识别 MVTec/BTAD/MPDD/data_local
     等目录结构）/ 文件夹导入 / 标准数据集 / 上传图片，选路径
3. 点「**创建并导入**」→ 探测结果弹确认窗核对 → 入库后自动分预训练组/检测组
   - 智能识别适配完成后，前端会把**识别结论回写数据源声明（只升不降）**：
     识别到掩码升 L1b、有缺陷图升 L1a，与分品类/模板标记一并回写
4. 数据源条目支持增删改查：右键菜单「编辑数据源」「更新数据」「删除数据源」；
   「另存为分组方案」在「编辑数据源」对话框内

### 声明与智能识别不一致的处理（体检机制）

档位/品类/模板三个开关是**用户声明**，智能识别只解析数据结构、不改声明；
入库后由「体检」比对声明 vs 实际支撑，规则为**警告 + 只降不升的自动校正**：

| 不一致情形 | 处理 |
|---|---|
| 声明档位高于实际（勾 L1b 但没掩码） | 警告；工单体检时**自动下调**数据源档位，提示"体检已自动校正" |
| 声明档位低于实际（有掩码但勾 L0） | 视为匹配，不自动升档，按声明走 |
| 勾了"提供模板"但没识别到模板图 | 只警告（提示重新导入），不改勾选 |
| 勾了"已分品类"但没识别出品类 | 只警告，数据归入「通用」品类，不改勾选 |

工单层条件 = 所挂源聚合（档位取最高），超支撑时同样警告，可一键自动校正。

## 1. 工作台：新建工单

1. 启动后默认在工作台，点右上角「**新建工单**」
2. 弹窗填写：
   - **工单名称**（如：3号线 SMT 质检）
   - **挂接数据源**（必选，勾选 ≥1 个；数据条件由数据源属性自动聚合）
   - **人工复判**开关（开启后全部检测进待复核队列，复核后才计入统计与学习）
   - 可选「复制工单配置」（从任务模板）、「同时保存为任务模板」
3. 点「**创建工单**」→ 后端自动体检并校正条件，顶栏工单下拉自动选中新工单

## 2. 模型管理：准备模型

> 可选（准备期）：缺陷样本不足时可先到「**数据增强**」页扩充——伪异常合成
> （真实缺陷移植 / CutPaste / 色斑）、图像预处理（灰度/CLAHE/中值去噪）、
> 训练增强（翻转/旋转/亮度）。

1. 导航 →「模型管理」，左侧树展开数据源 → 选目标**品类**节点
2. 点「**准备模型**」→ 弹窗自动数据体检（预训练组统计、数据条件判定）。
   若该品类已有激活模型，体检会追加**数据来源核验**警告：当前数据源与
   已有模型的训练数据是否同源（不同源=可能品类撞名，会明确提示）
3. 选运行模式（快速模式单图 <200ms）→ 点确定开始准备
4. 进度条为**分阶段百分比**（读取样本 → 特征提取 → 槽位拟合 → 校准打分 →
   融合权重计算 → 登记快照落盘激活），等待「准备完成，已生成新版本 v1」→ 点「完成」

### 该品类已有准备好的模型时

树节点状态会显示 `vN · 已投产`（而非"未准备"），「准备模型」按钮变为
「**重新准备模型**」。此时按需求选其一：

| 场景 | 操作 |
|---|---|
| 模型可直接用 | **跳过准备**，直接去「评估看板」验收或「实时监控」开检（已激活版本产线自动加载） |
| 换型 / 数据大改 | 点「重新准备模型」，弹窗勾选「**重新准备（覆盖已有版本，生成新版本号）**」→ 生成 v_n+1，旧版本保留可回滚 |
| 外部已有训练好的模型 | 点「**导入快照**」选 zip → 可填**不同品类名**跨品类复用 → 导入后为「未激活」状态，需到「版本历史」选中 →「激活选中版本」 |
| 日常使用中的模型更新 | 不点准备，用「**学习反馈并更新模型**」由反馈固化生成新版本（见第 6 步） |
| 查看学习成效 | 点「**学习效果**」→ 携带当前品类直达「学习效果」页（学习曲线回放、翻案率、贡献档案） |

注意：「激活选中版本」会触发**激活前自动验证**——新版本在验证图上明显劣于
当前版本时会被阻止激活（弹出对比报告，必要时可确认强制激活）；通过后产线
热切换，不需重启。版本间指标对比用版本历史的「**A/B 对比**」。
迁移模型可用「导出当前版本」（导出激活版本 zip）在另一台机器上「导入快照」。

## 3. 评估看板：验收激活

1. 导航 →「评估看板」，品类下拉选本次准备的品类
2. 点「**运行评估**」→ 进度条出现，等待评估记录落库（完成后列表自动刷新）
3. 查看指标（检出率/误检率等）；记录行首勾选框支持「**全选**」，
   勾选两行可「对比选中」；**双击「噪声鲁棒性」记录**可查看分档衰减曲线
4. 回到「模型管理」→「版本历史」→ 选中版本 →「**激活选中版本**」（不合格可「回滚」）

## 4. 实时监控：产线检测

1. 导航 →「实时监控」。**产线默认不自动开**（2026-09-13 起新建工单一律
   暂停态）：确认模型已在评估看板验收后，点「**恢复产线**」手动开检
   （监控页没有单独的「启动」按钮，首次开检也是点「恢复产线」）
2. **顶栏右侧有产线状态徽标**（绿=运行中 / 黄=已暂停 / 红=已停止），
   任何页面都能直接看到当前工单产线状态
3. 检测组按批次自动消费：画面滚动显示原图/热力图/叠加图、异常分数、判定条带
4. **画面右侧评分的含义**：
   - 大圆表 = **综合异常分**（0~1，越高越像缺陷），指针位置对应当前图分数，
     表盘刻度线 = 判定阈值（指针超过即判缺陷；判缺陷时弧线与判定文字变红）
   - 「各项评分依据」= 各检测模块对本次综合分的贡献，**黄色高亮 = 本次判定
     的主要依据模块**（复核反馈时可据此判断是哪路信号判错了）
5. 旁路调试（不进产线流、不影响统计）：「上传图片试检」/「从图库选图试检」。
   品类自动取当前工单品类；**多品类工单会弹窗让选一个品类**（试检必须明确
   用哪个品类的模型）
6. 「停止产线」= 彻底停流（需弹窗确认）；「暂停产线」= 临时挂起可恢复；
   另有「学习提升」（见第 6 步）、「导出报告CSV」按钮；左栏数据流队列
   支持「回队 / 取消回队」

## 5. 错检反馈（人工介入）

在监控页当前检测结果上：
- 「**标记误检**」（正常被判缺陷）/「**标记漏检**」（缺陷被判正常）→
  弹出反馈对话框，填操作员、缺陷类型 → 提交
- 「**确认正确**」直接确认
- 若工单开了人工复判：到「标注反馈」页逐条「判正常/判缺陷」复核
  （快捷键：Enter=判正常、D=判缺陷）

**反馈去了哪里（与第 6 步的联动）**：每条反馈连同图像、判定分数、真值标签
写入**学习日志**（落盘持久化，重启不丢）。反馈本身不立刻改模型——它先用于
在线小步调整（阈值/权重门控微调），积累后在「学习提升」固化成新版本。
反馈越多越准，学习提升的效果越好；误反馈（标错真值）会污染学习，提交前
请确认判定。

## 6. 学习提升（闭环关键）

1. 监控页点「暂停产线」（复判/学习不影响已暂停产线外的操作）
2. 点「**学习提升**」→ 系统把学习日志中的反馈**固化**：用反馈真值重训
   判别模块/重估阈值与融合权重，生成新模型版本（v_n+1）并自动激活；
   完成后若产线之前是运行态会**自动恢复运行**（暂停是学习前提，不是终止）
3. 若产线未自动恢复，手动点「恢复产线」→ 不重启不重新配置，继续检测
4. 错检率高的批次：到「数据管理」队列表选中 →「**回队（重新检测）**」插队再检
   （监控页左栏数据流队列同样支持「回队 / 取消回队」）
5. 学习成效验证：到「学习效果」页看**翻案率**（学习前判错、学习后判对的占比）
   与**误判率趋势**（应持续下降）；「学习效果」页第二个 Tab「离线回放验证」
   可预演学习能力、看消融贡献

## 7. 复盘：学习效果 + 存档统计

- 「**学习效果**」：Tab1 线上学习证据（翻案率 KPI、翻案曲线、误判率趋势、
  权重演化）；Tab2 离线回放验证（学习曲线回放、「生成贡献档案」——错检追溯
  → 学习提升的量化体现）
- 「**存档统计**」（原统计报表）：工单维度统计、缺陷帕累托、导出报表 CSV

## 8.1 本地数据集与通过孔数据的使用边界

AOI Core 的普通数据集流程适合把本地图片按 `train/good`、`test/good` 和
`test/<缺陷类型>` 导入，再进行特征学习、评估和反馈闭环。当前本机可用的本地品类包括
`gold_finger`、`solder_smt`、`component`、`extra_part` 和 `throughole`。

`throughole` 还包含 PCB Dual 传统通过孔算法所需的模板与 ROI 资源。其推荐操作顺序是：

1. 在 PCB Dual「模板建模」中加载 `data_local\\throughole\\template` 的标准图，
   并使用 `roi_resources` 中的 ROI 做标定；`template_resources` 中的 JSON 是配套标定信息，
   不作为普通训练图片导入。
2. 在 PCB Dual「自动检测」中先验证传统通过孔算法；该算法要求标准图和 ROI，且多个焊点
   ROI 时主要运行连锡检查，盘内孔洞/少锡/多锡/不出脚应使用单焊点或自动锡面配置。
3. 如需在 AOI Core 中演示普通特征学习，再选择整理后的 `data_local\\throughole` 根目录。
   其中 `train/good` 和 `test/*` 是由插件输出图整理的演示样本，`test/anomaly` 只表示异常，
   没有从输出图可靠恢复具体缺陷类型，不能据此宣称五类缺陷均已分别验收。
4. 传统引擎、AOI Core 特征引擎和 `dual` 融合模式分别验收；普通数据集导入不会替代
   PCB Dual 的模板/ROI 配置。

整理目录的原始 `roi`、`standard_roi` 和 `readme.md` 保留在 `throughole` 根下，便于追溯来源；
标准化目录只是在不删除原始资源的前提下增加的导入/演示副本。

## 9. 特征工程（可选：特征集贡献评估与候选配置）

位于「模型管理」与「评估看板」之间，面向工程师/管理员。**只读生产事实、候选配置隔离**
（实验配置不会直接替换生产状态）。

- **当前生产特征**（左）：按品类查看生产快照里的特征组（glcm / selfsim / edge /
  hog / shape / gray / gloss / color / fft / wavelet / logic / gabor / log / pc /
  surf）、维度、是否启用、来源（生产快照）；底部显示生产 revision / 签名 /
  group_spec / 生产维度。
- **候选分析与治理**（右）：填「候选说明」→「**生成当前档案**」（把现状固化成候选
  revision）→「**登记候选配置**」；下方「候选 revision」表只展示、**不自动激活**。
- 用途：评估"某一特征组到底贡献了多少"、把实验配置登记在案，正式替换生产特征仍需
  重新「准备模型」走版本流程。

## 10. 系统设置（可选）

阈值、延迟预算、通知、日志导出（审计日志可导出 CSV）等参数配置。
**角色说明**：顶栏角色徽标展示当前角色（由 API Key 决定，无界面切换入口）——
操作员（operator）仅保留 工作台/实时监控/标注反馈/存档统计 四个导航页，
工程师/管理员全量可见。

设置页分组（白名单参数，保存即写回 `configs/default.yaml`，免重启）：
**推理管线 / 数据目录 / 在线学习 / 评估 / 告警通知 / 自动归档 / PLC 触发 / 日志 /
业务预算与保留期 / 待决策事项**；引擎内部参数与安全密钥仍需手改配置文件。
设置页下部还有**系统自检**（一键清理数据残留/引用悬空）与**操作日志（审计）**。

## 11. 界面更新记录（2026-10-14，本次走查后改动）

本次对三个系统（AOI_Core / PCB_Dual / AOI_tree 交付树）的页面逐一操作走查后，
按「先保证功能正确、再改善布局美观」的顺序做了以下改动（均已重启实测生效）：

1. **顶栏「算力」徽标（专业口径，不显示显卡型号）**：显示
   `xx TOPS · 耗时 x.xx×`，例如本机实测 `11.8 TOPS · 耗时 1.09×`。
   - **TOPS**：估算 INT8 吞吐（峰值口径）；
   - **耗时系数**：**赛题基准硬件（RTX 2060）的耗时 × 该系数 ≈ 本机耗时**，
     >1 表示比基准慢、<1 表示比基准快（本机 1.09× = 比基准慢约 9%）。
     仅反映算力差异，实际耗时仍以「评估看板 → 延迟基准」实测为准。
   - **不显示显卡型号**；FP32 峰值、显存、CUDA 计算能力、SM 数、估算用主频
     等明细在鼠标悬停 tooltip（吞吐与占比为**估算值**，非厂商标称算力）。
   - 主频优先用 `nvidia-smi` 读最大 SM 主频（只读一次并缓存，不随健康检查起进程）。
   - CPU 环境显示 `未启用 GPU 加速`。
   - 接口 `/api/health`、`/api/system/info` 新增 `gpu_short` / `tops_int8` /
     `latency_factor` / `baseline_ratio_pct` / `tflops_fp32` / `vram_gb` /
     `compute_capability` / `sm_count` / `clock_ghz`。
2. **左侧导航**：分组标题收敛为两字 **准备 / 投产 / 复盘 / 系统**；关闭导航的
   水平滚动条；导航与页面之间的竖直分割线由 QSS `border-right` 改为独立 1px
   分隔条（前者会让列表视口少 1px，是多余滚动条的诱因）。
3. **数据管理**：左侧数据导航树加宽到 **240px**（先前收得太窄，树里的层级看不清），
   面板标题允许换行以免撑宽面板；右侧主列表列宽按"树 240 + 表格视口 ≈730"重排
   （**「缺陷类型」由 58 放宽到 76**，表头四个字不再被截断），并取消「路径」列
   （全路径改挂到序号单元格 tooltip）。下方**数据流队列**改为固定列宽、去掉每次
   刷新的 `resizeColumnsToContents()`（它会覆盖设计列宽，把**「品类」**等表头挤到
   显示不全），剩余宽度交给「数据源」列。
4. **工作台小面板按钮统一规格**：新增 `_panel_button()/_panel_button_row()`，
   工作台内面板操作按钮（去复核/查看/去巩固/编辑所选工单/存档所选工单/
   删除所选工单/去设置中心）统一为「最小宽 100 × 高 30」紧凑样式，
