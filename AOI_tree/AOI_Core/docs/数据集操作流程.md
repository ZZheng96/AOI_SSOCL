## 1. 通用导入动作（所有数据集共用）

1. 「数据管理」→「**新建数据源**」→ 填名称、模态选「图片」、源类型选「本地目录」
2. 按上表勾声明（档位 / 数据已分品类 / 提供模板图）；预训练正常图 100 /
   预训练异常图 30 / 检测批次图数 30 为默认值，样本不足的品类按需调低
3. 导入方式选「**智能识别适配（推荐）**」→ 选对应路径 →「创建并导入」
4. 探测（probe）只读扫描、秒级完成，**确认弹窗**核对：
   - mvtec_like：按品类勾选要导入的品类（可只选部分）
   - yolo_split / dir_rules：核对品类名、正常图角色（预训练 or 模板）、
     未识别分组的处理方式（默认跳过，可逐分组指定为正常/缺陷）
5. 入库后自动分预训练组/检测组 → 建工单挂源 → 准备模型 → 评估激活 → 开检
   （后续步骤见 [全流程操作.md](全流程操作.md)）

**通用注意**：

- **掩码只计数不入库**：`ground_truth/` 目录与 `*_mask` 后缀文件只用于判定
  L1b 档位，不进预训练组/检测组；缺陷图中被掩码标出的区域不作为正常样本
  参与训练，仅作伪异常移植源。
- 识别上限 60000 张图，超出截断并警告。
- 同一数据源后续补数据用右键「**更新数据**」，不要重复新建源。

## 2. data_origin（公开基准数据集）

### 2.1 MVTec AD —— `data_origin\mvtec`

- **结构**：15 个品类目录（bottle / cable / … / zipper），每个品类
  `train\good` + `test\{good | 缺陷类型}` + `ground_truth\{缺陷类型}`（掩码 png）。
- **导入**：选根目录 `data_origin\mvtec` → 识别为 mvtec_like 15 品类 →
  确认弹窗可按需勾选部分品类。
- **声明**：档位 L1b（有掩码）、勾「数据已分品类」、不勾模板。
- **注意**：多数品类 train/good 209~391 张，满足默认预训练配额；
  **toothbrush 仅 60 张正常图**，如导该品类，体检会提示预训练正常图不足，
  把「预训练正常图」配额调低（如 50）即可。

### 2.2 BTAD —— `data_origin\BTAD`

- **结构**：根下是单一包装目录 `BTech_Dataset_transformed\{01,02,03}`，
  每个品类 `train\ok` + `test\{ok|ko}` + `ground_truth\ko`。适配器会**自动
  下钻一层**识别包装目录；`ok→正常、ko→缺陷` 自动映射。
- **导入**：选根目录 `data_origin\BTAD` 即可（不用手动点到
  BTech_Dataset_transformed）。
- **声明**：同 MVTec（L1b + 分品类）。
- **规模**：01（train 400 / test 70）、02（train 399 / test 230，掩码 200 张）、
  03（train 1000 / test 441）。

### 2.3 MPDD —— `data_origin\MPDD`

- **结构**：6 品类（bracket_black / bracket_brown / bracket_white /
  connector / metal_plate / tubes），结构与 MVTec 相同（train/good +
  test/缺陷类型 + ground_truth 掩码）。
- **导入**：选根目录 `data_origin\MPDD`，mvtec_like 直接识别。
- **声明**：L1b + 分品类。

### 2.4 GYU-DET —— `data_origin\GYU-DET`

- **结构**：`{train,valid,test}\{images,labels}` + YOLO 标注 txt +
  `classes.txt`。识别为 **yolo_split**：**txt 存在且非空 → 缺陷，
  缺失/空 → 正常**；目录名 train/valid/test 直接映射 split（valid→val）。
- **导入**：选根目录 `data_origin\GYU-DET`；单品类，品类名默认取根目录名。
- **声明**：档位 **L1a**（框标注不入库，无掩码故不构成本系统的 L1b）、
  **不勾**「数据已分品类」（勾了体检会警告并归入「通用」品类）。
- **数据特点**（实测计数）：
  - train：8898 图（其中约 564 张正常 / 8334 张缺陷）——缺陷远多于正常，
    正常图仍够默认 100 的预训练配额；
  - valid：1112 图；test：1113 图——检测批次量大，可按需调「检测批次图数」。
- **用途**：真实跨域数据（train/test 分布有域差），是在线学习与跨域适应的
  主验证集；跑它时重点关注「学习效果」页的误判率趋势与翻案率。

## 3. data_local（自采 PCB 四品类）

`data_local\` 根下四个品类目录均带 `train\test` 结构，**选根目录
`E:\CPIPC\CGAIC\data_local` 可一次识别为 mvtec_like 4 品类**（`origin\`、
`scripts\` 无 train/test，不参与识别）。也可逐品类单独建源：选品类子目录
（根本身即单品类也会被识别）。

### 3.1 gold_finger —— `data_local\gold_finger`

- **结构**：`train\good` 68 张（`*_repaired` 修复图，作正常样本）、
  `test\defect` 85、`test\good` 17、`ground_truth\defect` 46 张掩码。
- **声明**：档位 **L1b**（有掩码）；不勾模板。
- **用途**：演示/验收主用品类；test 缺陷 85 张 + 掩码齐全，适合走完整闭环
  （准备 → 评估 → 开检 → 反馈 → 学习提升 → 看翻案率）。

### 3.2 solder_smt —— `data_local\solder_smt`

- **结构**：`train\good` 35、`test\{good 9 | bridge 63 | cold_solder 8 |
  excess 7 | insufficient 25}`、`ground_truth` 掩码 100 张（4 类缺陷）。
- **声明**：档位 **L1b**。
- **注意**：**正常图仅 35 张 < 默认预训练配额 100**——准备模型前把数据源
  「预训练正常图」调低（如 30），或先到「数据增强」页扩充后再准备。

### 3.3 component —— `data_local\component`

- **结构**：`train\good` 8（含 `shift1_template.png` 等 `*_template` 命名）、
  `test\{good | missing 4 | shift 7 | tombstone 1 | damage 2}`。
- **声明**：档位 **L1a** + **勾「提供模板图」**——`*_template` 后缀会被识别为
  模板图（split=template，不进预训练/检测组），激活 tpl 模板差分槽位（L3）。
- **注意**：数据量很小，适合验证模板链路和流程演示；模板命名约定是
  `_tpl` / `_template` 后缀或 `templ_` 前缀（`A.png` 配 `A_tpl.png`）。

### 3.4 extra_part —— `data_local\extra_part`

- **结构**：`train\good` 31、`test\{extra 39（缺陷：多料）| good 8}`。
- **声明**：档位 **L1a**；不勾模板。
- **注意**：文件名里的 `*_temp.jpg` 是「模板小图」语义的历史命名，但**不会**
  被识别为模板（模板标记是 `_tpl`/`_template`/`templ_` 前缀）——它们按
  good 目录归属为正常图。如需作模板，重命名为 `_tpl` 后缀或放入
  `template\` 目录后重新导入。

## 4. data_local\origin（原始素材归档，一般无需导入）

- `origin\data_\{component, extra_part, gold_finger, solder, solder_smt}`：
  四品类的**原始形态**（如 extra_part 的 `img/temp/info` 三元组、
  gold_finger 的 `image_repaired` / `image_test` + json 标注、
  solder 的 roi / standard_roi），是 §3 四个已整理品类的素材来源。
- `origin\test_images\{bridge, cold_solder, excess, insufficient, pics,
  *_pair}`：焊点缺陷原图与成对目录（pairN/groupN 为无语义目录）。
- **如确需导入**（例如重新整理一个新品类）：
  - 用「智能识别适配」**逐个子目录**导入（如 `origin\test_images\bridge`），
    识别为 dir_rules 格式，确认弹窗里逐分组指定处理方式；
  - **不要直接选 `origin` 根目录**——多品类混杂会被当作单品类 dir_rules，
    识别结果不可用；
  - 更推荐的做法：先在文件系统里按 §3 品类的 `{train\good, test\缺陷类型}`
    结构整理好，再按 mvtec_like 导入。

## 5. 导入后的下一步（指向主流程）

每个数据集导入后的操作完全相同，见 [全流程操作.md](全流程操作.md)：

1. 工作台「新建工单」挂该数据源（产线默认暂停）
2. 模型管理选品类「准备模型」（体检自动校正声明）
3. 评估看板「运行评估」→ 版本历史「激活选中版本」
4. 实时监控「恢复产线」开检 → 错检反馈 → 暂停 →「学习提升」→ 自动恢复
5. 学习效果 / 存档统计复盘
