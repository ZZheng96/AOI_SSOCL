## 本次更新要点（2026-10-14）

- **顶栏「算力」徽标（专业口径，不显示显卡型号）**：显示 `xx TOPS · 耗时 x.xx×`，
  本机实测为 `11.8 TOPS · 耗时 1.09×`。
  - **TOPS**：估算 INT8 吞吐（峰值口径）；
  - **耗时系数**：**赛题基准硬件（RTX 2060）的耗时 × 该系数 ≈ 本机耗时**，
    >1 表示比基准慢、<1 表示比基准快（本机 1.09× 即比基准慢约 9%）。
    该系数只反映算力差异，实际耗时请以「评估看板 → 延迟基准」实测为准。
  - 计算方式：`INT8 吞吐 ≈ SM 数 × 每 SM FP32 核心数 × 2 × 主频 × 2（INT8 打包）`；
    主频优先用 `nvidia-smi` 读最大 SM 主频（只读一次并缓存）。
  - 吞吐与系数均为**估算值，非厂商标称算力**；FP32 峰值 / 显存 / CUDA 计算能力 /
    SM 数 / 估算用主频在 tooltip。CPU 环境显示「未启用 GPU 加速」。
  - 接口 `/api/health` 与 `/api/system/info` 新增 `gpu_short` / `tops_int8` /
    `latency_factor` / `baseline_ratio_pct` / `tflops_fp32` / `vram_gb` /
    `compute_capability` / `sm_count` / `clock_ghz` 字段。

## 一、系统简介与功能地图

本系统是一套**可自学习的 AOI（自动光学检测）实时在线质检系统**，面向制造业组装过程中
屏幕、电池、中框、PCB 焊点、金手指等组件的缺陷检测。算法核心为**多槽位融合引擎**：
DINOv2 视觉主干 + 可插拔检测槽位 + 在线校准 + 槽位融合，输出三态决策：
**正常（normal） / 异常（anomaly） / 灰区待复核（gray）**。

系统围绕三大能力组织：

| 核心能力 | 系统支撑 |
|---|---|
| ① 实时异常检测 | 图片/视频/相机 RTSP/产线批次多来源检测，热力图 + 缺陷框 + 缺陷类型归因可解释输出；三态决策避免「硬二分类」误放行 |
| ② 少样本快速上线 | 按「数据条件」自动建模：仅正常图无需缺陷样本即可上线；缺陷样本不足可用数据增强合成伪异常 |
| ③ 反馈驱动持续学习 | 操作员标记误检/漏检/确认/复核 → 形成候选学习状态（候选与生产隔离）→ 「固化学习快照」固化已有内存学习状态 → 学习效果页可视化翻案率与误判率趋势 |

**系统形态**：PySide6 桌面客户端 + FastAPI 后端 + SQLite 数据库；支持单机一体运行、
独立后端 + 多工位客户端接入、以及 Docker 后端部署。

### 功能地图（左侧导航 11 项 + 分组）

```
工作台 ────────── 开机首屏：KPI、待办、工单运营表、能力开关状态
── 准备 ──
  数据管理 ────── 新建数据源、智能识别导入、四维数据树、标注、队列回队
  数据增强 ────── 伪异常合成 / 图像预处理 / 训练增强（保存后下次准备模型生效）
  模型管理 ────── 准备模型、版本历史、激活/回滚/A-B 对比、快照导入导出
  特征工程 ────── 生产特征只读展示 + 候选配置隔离试验
 评估看板 ────── 精度评估 / 延迟基准 / 噪声鲁棒性 / 评估记录对比 / 候选验收
── 投产 ──
  实时监控 ────── 产线启停、逐帧检测、三态判定、错检反馈
  标注反馈 ────── 反馈记录、待复核队列、错检追溯、开放告警样本
── 复盘 ──
  学习效果 ────── 线上学习证据、离线回放验证、槽位健康与更新审计
  存档统计 ────── 工单档案、存档/还原、复核后口径统计与 CSV 导出
```

### 顶栏（自左至右）

系统标题与副标题「少样本即可上线 · 反馈驱动候选学习」 → **当前工单**下拉 → **数据条件**徽标 →
**算力**徽标 → **产线**状态徽标 → **角色**徽标 → **延迟预算**标签 → **后端连接指示灯**。

> 顶栏已不设「品类下拉」：品类随当前工单推导（单品类工单自动取该品类，多品类工单为空/全局）。

### 术语表

| 术语 | 含义 |
|---|---|
| 数据条件（标注档位） | 界面只出中文：**仅正常图 / 图像级标注 / 缺陷位置标注**（内部对应 L0 / L1a / L1b，界面不显示代号），另可叠加两个开关：**品类独立 / 模板比对** |
| 综合异常分 | 0~1 的融合分数，越高越像缺陷；检视页大圆表指针位置即该分数 |
| 判定阈值 | 分数超过即判缺陷；大圆表刻度线即该阈值 |
| 三态决策 | 正常 / 异常 / 灰区待复核（灰区进入待复核队列，人工判定后再入统计，并形成候选学习状态） |
| 反馈学习状态 | 生产反馈先形成候选学习状态；`candidate_queued/consumed=False` 表示仅候选隔离，不即时更新生产模型 |
| 固化学习快照 | 调用 consolidate 固化已有内存学习状态；不自动消费所有候选反馈，不保证重训、激活或效果提升 |
| 工单 | 统计与产线的基本单元；工单挂接数据源，数据条件由所挂源聚合 |

## 二、安装与启动

### 2.1 环境要求

- Windows / Linux，**Python 3.11**（本机实测：`C:\Program Files\Python311\python.exe`）。
- GPU 可选（CUDA）；无 GPU 时自动回落 CPU，顶栏显示「CPU · 未启用 GPU 加速」。
- 依赖安装：`pip install -r requirements.txt`（含 torch 2.5.1+cu121、fastapi、uvicorn、
  PySide6、SQLAlchemy、opencv、scikit-learn、pyqtgraph 等）。
- DINOv2 主干权重随包放置于 `assets/dinov2/`（可放 `AOI_Core/assets/dinov2/` 或
  `AOI_tree/assets/dinov2/`，也可用环境变量 `DINOV2_LOCAL_DIR` 指定）；目录须含
  `hubconf.py` 与 `dinov2_vits14_pretrain.pth`，齐全时可完全离线加载；缺权重时回退到
  torch hub 缓存或在线下载。

### 2.2 单机一体模式（推荐：开发 / 演示 / 单工位）

在 `AOI_Core` 目录下执行：

```bash
cd AOI_Core
python main.py
```

自动完成：守护线程内嵌启动 FastAPI 后端（默认 `http://127.0.0.1:8017`）→ 初始化数据库 →
轮询 `/api/health` 就绪 → 打开 PySide6 桌面窗口。
**端口 8017 已被占用时不再起第二个后端，而是直接复用已有后端**（例如已单独跑过 `server.py`）。

### 2.3 独立后端模式（多工位，桌面端远程接入）

```bash
# 服务器端：前台启动后端（host/port 取自 configs/default.yaml）
cd AOI_Core
python server.py

# 质检工位电脑：把 configs/default.yaml 的 system.host 指向服务器，再启动桌面端
cd AOI_Core
python main.py
```

### 2.4 Docker 部署（后端容器化 + 宿主机桌面端）

```bash
cd AOI_Core
# 生产必须注入强随机密钥（compose 已内置 AOI_PRODUCTION=1 与强制 Key 检查）
set AOI_API_KEY=<强随机密钥>
docker compose up -d                 # CPU 默认；GPU 用 docker-compose.gpu.yml 覆盖
```

- `docker-compose.yml`：容器内以 `configs/docker.yaml` 运行，数据卷 `aoi-storage` /
  `aoi-database` 分别挂到 `/data/storage`、`/data/database`，端口 `127.0.0.1:8017`。
- `docker-compose.gpu.yml`：GPU 部署（需 Linux + nvidia-container-toolkit），改用 cu121 torch。
- 镜像内以非 root 用户（uid 10001）运行，`/api/health` 为探活豁免路径。
- 桌面端（PySide6）请在宿主机原生运行，不在容器内。

## 四、快速上手：十分钟完整流程

以本机自采数据集 `d:\CGAIC\data_local\gold_finger`（金手指组件）为例。主线：
**建数据源 → 建工单挂源 → 准备模型 → 评估激活 → 产线检测 → 反馈 → 固化学习快照 → 候选构建/验收/批准/激活 → 恢复检测**。

### 步骤 0：新建数据源（数据管理页）

1. 导航 →「数据管理」→ 右上【新建数据源】。
2. 弹窗填写：名称、模态（图片/视频）、源类型（本地目录 / RTSP 实时流 / 视频文件）、
   **标注档位**（仅正常图 / 图像级标注 / 缺陷位置标注）、勾选「数据已分品类」「提供模板图」、
   预训练正常图（默认 100）/ 预训练异常图（默认 30）/ 检测批次图数（默认 30）。
3. 「导入数据」选 **智能识别适配（推荐）**，填数据集根目录 → 按钮变为【创建并导入】→ 点它。
4. 弹出「数据集识别与确认」窗：核对格式、图片数、掩码数（标注"不入库"）与品类勾选表，
   点【确认导入】。导入完成后系统**把识别结论回写数据源声明（只升不降）**。

### 步骤 1：新建工单（工作台）

1. 导航 →「工作台」→ 右上【新建工单】。
2. 填工单名称（如「3号线 SMT 质检」），勾选刚建的数据源（≥1），按需开「人工复判」。
3. 点【创建工单】→ 后端自动体检并校正数据条件，顶栏工单下拉自动选中新工单，
   产线状态徽标显示黄色「已暂停」（**新建工单一律暂停态，不自动开检**）。

### 步骤 2：准备模型（模型管理）

1. 导航 →「模型管理」→ 左侧树展开数据源 → 选目标**品类**节点。
2. 点【准备模型】→ 弹窗自动数据体检（预训练组统计、数据条件判定；该品类已有模型时追加
   训练数据来源核验）→ 选运行模式（快速模式单图 <200ms）→ 开始准备。
3. 进度条分阶段推进（读取样本 → 特征提取 → 槽位拟合 → 校准打分 → 融合权重计算 →
   登记快照落盘激活），完成后提示「准备完成，已生成新版本 v1」，树节点显示「v1 · 已投产」。

### 步骤 3：评估验收（评估看板）

1. 导航 →「评估看板」，品类下拉选本品类 →【运行评估】→ 等待记录落库 → 查看指标。
2. 回到「模型管理」→「版本历史」→ 选中版本 →【激活选中版本】
   （激活前会**自动验证**新版本不劣于当前版本，劣化则阻止激活并弹对比报告）。

### 步骤 4：产线检测（实时监控）

1. 导航 →「实时监控」→ 点【恢复产线】（**没有单独的"启动"按钮**，首次开检也是点它）。
2. 检测组按批自动消费，画面滚动显示原图/热力图/叠加图、综合异常分大圆表、判定条带、
   各项评分依据。顶栏产线徽标变绿「运行中」。

### 步骤 5：错检反馈（人工介入）

在监控页当前检测结果上：【标记误检】（正常被判缺陷）/【标记漏检】（缺陷被判正常）→
弹出反馈对话框填操作员、缺陷类型 → 提交；【确认正确】直接确认。
若工单开了人工复判，到「标注反馈」页逐条【判正常】/【判缺陷】复核。

### 步骤 6：固化学习快照（闭环关键）

1. 监控页点【暂停产线】（如需降低操作风险）。
2. 点【固化学习快照】→ 调用 consolidate 固化已有内存学习状态；它不自动消费所有候选反馈，
   不保证重训、生成/激活新模型或带来效果提升。
3. 固化后的自动恢复是独立策略，可能将 stopped 状态也改回 running；恢复产线不代表模型已成功更新。
   按需手动点【恢复产线】继续检测。候选构建、验收、批准和激活是独立治理步骤，不能将本页按钮或评估记录当作已完成全部发布审批。

### 步骤 7：复盘

- 【学习效果】页看**翻案率**（学习前判错、学习后判对的占比）与**误判率趋势**（应持续下降）；
  第二 Tab「离线回放验证」可预演学习能力、看消融贡献。
- 【存档统计】页按工单查看统计并【导出 CSV】。

## 五、各页面详解（11 个页面）

### 5.0 工作台（开机首屏）

- **入口**：左侧导航首项「工作台」，启动后默认进入。
- **能做什么**：以工单为统计基础的总览——KPI、待办、工单运营、能力开关状态。
- **关键控件**：
  - KPI 行：检测数 / 不良数 / 不良率 / 待复核；当前工单全部已落库记录统计（未选工单时为全局口径并注明）。
  - 待办卡片：待复核队列 / 不完备预警 / 待巩固反馈，点击直达对应处理页。
  - 工单运营表：列出工单及数据条件；**单击行切换顶栏当前工单**，**双击「数据条件」列弹工单编辑**
    （三档＋两开关＋体检）。
  - 能力开关状态条：Webhook 告警 / PLC 触发 / 自动归档 / API 鉴权 / API 文档（只读透出，修改去设置页）。
- **按钮含义**：【新建工单】新建；【刷新】重拉；【编辑所选工单】编辑；【存档所选工单】转历史；
  【删除所选工单】级联删除；【去设置中心】跳「系统设置」。
- **注意**：统计口径为**已落库检测记录**，不等于相机采集帧数；「接收→落库率」暂无数据源时显示
  「不可用」而非 0（鼠标悬停口径标签可见完整口径说明）。

### 5.1 数据管理

- **入口**：「数据管理」。
- **能做什么**：新建数据源、导入数据（智能识别适配/文件夹/标准数据集/上传）、四维数据树浏览、
  图像标注、批次管理、数据流队列编排。（含三个选项卡：图像 / 视频 / 伪异常）
- **关键控件**：
  - 筛选栏：模态 / 数据源 / 品类 / 批次。
  - 左侧**四维数据树**：数据源 → 品类 → 批次 → 划分 → 标签，点击节点过滤右侧表格。
  - 图像表格：序号 / 缩略图 / ID / 品类 / 批次 / 来源 / 划分 / 标签 / 缺陷类型 / 导入时间
    （列宽按视口自适应、整表无需横向滚动；**图片全路径**改在「序号」单元格 tooltip 里悬停查看）；
    分页按钮【第一页/上一页/下一页/最后一页】。
  - **数据流队列（当前工单）**：暂停产线后可编排，错检批次可【回队（重新检测）】/【取消回队】。
- **按钮/右键菜单含义**：【新建数据源】建源并导入；右键图像 →【标注…】改 label/split/缺陷类型；
  【删除该图像…】可勾选同时删磁盘文件；右键批次 →【导出清单（CSV）】/【删除批次…】/【批次详情与数据谱系…】；
  工具栏【孤儿文件清理】扫描并清理 storage 内无 DB 引用的文件。
- **注意**：掩码图（`ground_truth/` 目录或 `*_mask` 后缀）**只计数不入库**，仅作定位与伪异常移植源；
  模板图（`_tpl`/`_template` 后缀、`templ_` 前缀、`template` 目录）进模板库，不计入正常图；
  导入按内容哈希指纹去重、重跑幂等。

### 5.2 数据增强

- **入口**：「数据增强」。
- **能做什么**：配置伪异常合成、图像预处理、训练增强（**保存后下一次「准备模型」时生效**）。
- **关键控件**：左=基底图（normal 图）树；中=三类配置卡片；右=伪异常合成预览。
  - 伪异常合成方式：`真实缺陷移植`（按缺陷位置标注抠缺陷贴入正常图，需已有带位置标注的缺陷图）/
    `CutPaste 切块贴回` / `色斑`。
  - 图像预处理：灰度 / CLAHE / 中值去噪（训练与检测两侧同口径，改动后需重新准备模型）。
  - 训练增强：翻转 / 旋转 / 亮度，仅增加正常样本外观多样性。
- **按钮含义**：【刷新基底图】重拉基底图；【保存配置】写回；【重新读取】放弃修改重读；
  【预览合成】生成预览（不产生图片文件）。
- **注意**：本页不涉及学习率/轮数等训练参数；伪异常合成在准备模型时自动执行，**不生成图片文件**。

### 5.3 模型管理

- **入口**：「模型管理」。
- **能做什么**：按「数据源 → 品类」组织模型状态，准备模型、查看上线阶段、管理版本历史。
- **关键控件**：左侧树 数据源 → 品类（节点显示「当前版本 · 上线阶段」）；
  品类上线状态机主线：**数据未导入 → 可训练 → 已训练未验收 → 已验收未激活 → 已投产**。
- **按钮含义**：
  - 【准备模型】/【重新准备模型】冷启动（可选「重新准备（覆盖已有版本，生成新版本号）」，旧版本保留可回滚）。
  - 【固化学习快照】调用 consolidate 固化已有内存学习状态；候选构建、验收、批准、激活彼此独立，不自动消费所有候选反馈，也不保证重训或效果提升。
  - 【学习效果】携带当前品类跳「学习效果」页。
  - 【导出当前版本】导出激活版本 zip；【导入快照】选 zip 导入（可改品类名跨品类复用，导入后为「未激活」）。
  - 【▸ 版本历史】展开：每行【A/B 对比】；顶部【激活选中版本】/【回滚】。
- **注意**：【激活选中版本】触发**激活前自动验证**（ActivationGateDialog）——新版本在验证图上明显
  劣于当前版本时被阻止，可确认强制激活；通过后产线热切换，不需重启。

### 5.4 特征工程

- **入口**：「特征工程」。
- **能做什么**：只读展示**生产特征事实**，并把实验性变更限制在**候选配置**（draft）内，
  不直接改动生产。
- **关键控件**：左=当前生产特征表（特征组 / 维度 / 启用 / 参数 / 来源）与生产 revision/提取器信息；
  右=候选分析与治理（特征档案、候选说明输入、候选 revision 表）。
- **按钮含义**：【生成当前档案】生成当前生产特征档案（主按钮）；【登记候选配置】登记 draft 候选；
  【排队表示重建】排队执行表示重建。
- **注意**：生产事实只读，候选配置隔离、**不自动激活**。

### 5.5 评估看板

- **入口**：「评估看板」。
- **能做什么**：精度评估、延迟基准、噪声鲁棒性、A/B 版本对比、学习曲线回放、贡献档案。
- **关键控件**：左=新建评估表单（类型 / 品类 / split / 样本上限 / 名称）+ 进度；右=评估记录表格。
  - 勾选两行可【对比选中（两行）】弹双系列柱状图；选中 benchmark 行时下方显示延迟分布柱状图
    （含 200ms 预算参考线）；**双击「噪声鲁棒性」记录**查看分档衰减曲线。
- **按钮含义**：【运行评估】执行；【全选】/【删除所选】/【刷新】。
- **注意**：评估项与业务预算达标线（G2 误报率上限、G2 召回下限、灰区占比上限等）联动，
  超限标红/标黄。

### 5.6 实时监控

- **入口**：「实时监控」。
- **能做什么**：产线检测流的实时监视与操作员干预。
- **关键控件**：
  - 左栏：试检旁路面板（【上传图片试检】/【从图库选图试检…】）＋ 数据流队列（【刷新队列】/
    【回队（重新检测）】/【取消回队】）。旁路试检**不进产线流、不影响统计**；多品类工单试检会弹窗选品类。
  - 中央：原图 / 热力图 / 叠加图 图层切换 + 判定条带 + 分数曲线（EMA 平滑）+ 【适应窗口】。
  - 右侧：综合异常分大圆表（刻度线=判定阈值，判缺陷时弧线与判定文字变红）、三态判定、
    「各项评分依据」（**黄色高亮 = 本次判定主要依据模块**）、延迟对比、缺陷框数。
- **按钮含义**：产线运行组【暂停产线】（临时挂起可恢复）/【恢复产线】/【停止产线】（彻底停流，弹窗确认）/
  【固化学习快照】/【导出报告CSV】；反馈组【标记误检】/【标记漏检】/【确认正确】/【图像解释】；
  产线未就绪时提供【去准备未就绪品类】直达「模型管理」。
- **注意**：产线默认暂停，新建工单一律暂停态；连续异常由后端滑窗聚合，命中时页面顶部出现红色
  告警横幅（建议停线检查信号）。

### 5.7 标注反馈

- **入口**：「标注反馈」。
- **能做什么**：反馈摘要（工单口径）+ 各品类在线学习状态 + 反馈记录 / 待复核 / 错检追溯 / 开放告警样本。
- **关键控件**：
  - 上：左 KPI 2×2（反馈数 / 错检占比 / 待复核 / 已复核）；右各品类在线学习状态
    （当前版本 / 未巩固反馈数 / 【内部状态】）。
  - 下 Tab：
    - **反馈记录**：按类型/品类筛选的反馈流水（双击行追溯）。
    - **待复核**：灰区帧与人工复判帧队列，含系统判定列；【判正常】（快捷键 Enter）/【判缺陷】（快捷键 D）；
      【系统推荐复核…】主动选样（挑最不确定 × 最有代表性样本）；可在预览图上**框选缺陷区**再判缺陷，
      框选直接喂缺陷拦截通道（"1-2 张带框缺陷即拦同类"）。
    - **错检追溯**：被判错（误检/漏检/新缺陷）的检测清单，双击行查看单帧追溯。
    - **开放告警样本**：开放集哨兵命中的样本队列。
- **注意**：**固化统一在监控页「固化学习快照」执行**，本页「内部状态」仅查看引擎内部状态（不改变生产模型）；
  仅产线路径检测进待复核队列，试检旁路不进。

### 5.8 学习效果

- **入口**：「学习效果」。
- **能做什么**：以「学习证据三层」组织——线上学习证据 / 离线回放验证 / 槽位健康与更新审计。
- **三个 Tab**：
  - **线上学习证据**（默认）：翻案曲线（灰=学习前判定分，蓝=当前引擎重判定分，绿点=已翻案）、
    误判率趋势（按日，复核口径）、融合权重随反馈演化、滚动判对率。
  - **离线回放验证**：预设档位（快速验证/标准/深度）——【开始回放】；【生成贡献档案】输出单变量/
    冗余度/消融 + 融合对照。
  - **槽位健康与更新审计**：槽位能力与状态（校准分=正常分布分位，**不是缺陷概率**）、
    更新准入审计（每轮快照ID/操作/漂移/前后误报率与灰区率/结论）。
  - 底部治理入口：【提交候选】/【生成特征档案】/【表示重建】/【难例准入试算】。
- **注意**：滚动判对率存在**选择偏差**（操作员专挑可疑图反馈），应结合误判率趋势解读。

### 5.9 存档统计

- **入口**：「存档统计」（原「统计报表」）。
- **能做什么**：以工单为基础的历史管理 + 复核后口径统计。
- **关键控件**：左侧工单档案列表（进行中 / 已存档两组）；右侧统计（KPI：检测数 / 复核覆盖率 /
  真实不良率 / 误报率 / 检出率 / 推理耗时 / 检测处理耗时（保存前） + 口径行 + 误判率趋势 + 缺陷帕累托 +
  批次对比 + 产线健康 + 推理耗时趋势）。主指标检出率=TP/(TP+FN)，误报率=FP/(FP+TN)；缺分母显示「未知」。
  保留【标记漏检】作为反馈动作。
- **按钮含义**：【存档】（数据保留转历史）/【还原】/【删除】（级联清检测与反馈）/【导出 CSV】/【刷新】。
- **注意**：未选工单时右侧为空态提示；全部数据为纯 DB 聚合、**零模型前向**；操作日志在「系统设置」页。

### 5.10 系统设置

- **入口**：「系统设置」（导航末项，分组标题「系统」下）。
- **能做什么**：白名单参数热修改、系统自检与一键清理、操作日志（审计）、新建品类向导。
- **关键控件/按钮**：
  - 顶部：【新建品类向导】（打开六步引导对话框）/【刷新】/【恢复默认】（把「业务预算与保留期」
    各项填回默认，需再点保存）/【保存修改】。
  - 表单区：§3.2 的 10 个分组（数字框/勾选框/文本框/下拉），只回传改动项写回 yaml 免重启；
    `security` 段密钥只写不读；被冻结项（GT 与业务阈值）锁定不可改。
  - **系统自检**：【运行自检】检查数据残留/引用悬空/页面一致性；【一键清理】修复可修复项（级联删除
    孤儿/悬空记录、删除裂图登记行、释放卡死认领、重算今日统计）。
  - **操作日志（审计）**：动作过滤下拉（可选可输）+【刷新日志】+【导出 CSV】。
- **新建品类向导**：填工单名/复判/备注 →【提交工单】；下方六步引导（① 建工单 ② 定数据 ③ 准备模型
  ④ 冷启动训练 ⑤ 评估验收 ⑥ 投产），每步带「去「××」执行」直达按钮。
- **注意**：非白名单高危项（引擎槽位参数、安全密钥）不接受界面修改，仍需手改配置文件；每次保存记
  `config_update` 操作日志。

## 六、典型案例

### 案例 A：新品类上线，缺陷样本很少

1. 【数据管理】新建数据源并导入正常图（建议 ≥50-100 张；不足可用「数据增强」合成伪异常/预处理扩充）。
2. 【工作台】新建工单挂接该数据源 →
3. 【模型管理】选品类【准备模型】（体检会按数据条件自动判定建模方式）。
4. 【评估看板】跑精度评估看检出率/误报率；不达标则调整数据或增强配比重备。
5. 【实时监控】点【恢复产线】接入产线试运行。

### 案例 B：换了视野（FOV），正常品频繁误报

1. 监控中对误报帧点【标记误检】——反馈先进入候选隔离状态，不即时更新生产模型。
2. 按需在「标注反馈」完成复核；候选构建、验收、批准、激活分别执行，效果以评估结果为准。
3. 【暂停产线】→【固化学习快照】只固化已有内存学习状态；固化后的自动恢复是独立策略，不代表模型成功更新。

### 案例 C：漏检了一种细微划痕

1. 对漏检帧点【标记漏检】，填缺陷类型后提交。
2. 在「标注反馈」→「待复核」中可框选缺陷区再判缺陷（框选让缺陷拦截通道精确定位）。
3. 积累若干条后【固化学习快照】只固化已有内存学习状态；再按「模型管理」与「评估看板」流程完成候选构建、验收、批准、激活，不能预先保证召回提升。
4. 到「学习效果」页查看翻案率与误判率趋势，效果以评估结果为准。

### 案例 D：验收测试

1. 【评估看板】按页面实际请求执行延迟基准（当前为 20 次，另 3 次预热）→ 查看可用的 mean/p50/max；P95 在评估详情或工单导出查看，主卡片不宣称已有。
2. 精度评估默认 20 次请求（以实际请求为准；test 或 valid 划分）→ 检出率/误报率/混淆矩阵；鲁棒性默认 12 次请求。
3. 【学习效果】离线回放 → 记录学习曲线与贡献档案。
4. 【存档统计】导出报表 CSV 作为举证材料。

## 七、性能与指标口径

> **诚实声明**：本章数据以实机为准。旧版文档记载的 108–483ms、零拷贝 131ms 等为早期、
> 不同硬件与不同口径下的历史记录，**不代表本机当前表现**，仅作参考。

### 7.1 本机实测环境（2026-10-14）

| 项 | 值 |
|---|---|
| Python | 3.11（`C:\Program Files\Python311\python.exe`） |
| PyTorch | 2.5.1+cu121 |
| 显卡 | NVIDIA GeForce GTX 1660 SUPER |
| 算力（顶栏徽标） | 11.8 TOPS · 耗时 1.09×（吞吐与耗时系数为估算值；1.09× = 比赛题基准 RTX 2060 慢约 9%） |
| 显存 | 6.0 GB |
| CUDA 计算能力 | 7.5 |
| SM 数 | 22 |

### 7.2 当前性能现状（务必按此理解）

- **单图纯推理未达 200ms 延迟红线**：本机在上述硬件下，对单张图片做纯推理计时，
  **尚未达到 200ms 预算**。精确的 mean / p50 / p95 / max 需按标准口径（预热 + 固定张数）
  在本机复测后填入，本文此处标注为**待实测**。
- **赛题硬件指标未复测**：赛题口径为 2060 GPU、2500² 大图 <200ms，**本机未在 2060 实机上复测**，
  无法给出该硬件下的达标结论，以实机为准。
- 因此，本手册建议以「评估看板 → 延迟基准」在本机实测的输出作为验收依据，而非引用历史数字。

### 7.3 指标口径（避免误读）

| 指标 | 口径 |
|---|---|
| 综合异常分 | 0~1 融合分；大圆表刻度线 = 判定阈值，指针超过即判缺陷 |
| `latency_ms` | 引擎段耗时（解码 + 推理 + 热力图等） |
| `latency_e2e_ms` | 检测处理保存前耗时，不包含采集网络与落库耗时 |
| 延迟基准 | 评估页面按实际请求执行；精度默认 20 次，延迟 20 次另 3 次预热，鲁棒性 12 次，以实际请求为准，不按配置项 `30 / 5` 宣称 |
| 检出率 / 误报率 / 复核覆盖率 | 检出率=TP/(TP+FN)，误报率=FP/(FP+TN)；缺分母显示「未知」；P95 可在评估详情/工单导出查看，主卡片不宣称已有 |
| 学习增益 | 离线回放：final AUROC − initial AUROC（锚定集很小时有 ±0.5 级统计抖动，属小样本噪声） |

> 生产反馈先形成候选学习状态，不即时更新生产模型；【固化学习快照】调用 consolidate 固化已有内存学习状态。
> 候选构建、验收、批准、激活为独立步骤，效果以实际评估为准；准备模型、回放、A/B 对比等为一次性/后台操作，
> 时长视数据与硬件而定，不作为实时红线。

## 九、常见问题 FAQ

**Q：检测很慢怎么办？**
确认后端是否用上 GPU（顶栏「算力」徽标 tooltip 可见计算设备）；用「评估看板 → 延迟基准」在本机
实测得到真实耗时。本机当前纯推理未达 200ms 红线（见 §七），如需提速请以实机压测结果为准。

**Q：顶栏「耗时 1.09×」是什么意思？**
它是**耗时系数**：以赛题基准硬件 RTX 2060 的耗时为 1.0×，本机耗时约为它的 1.09 倍
（即比基准慢约 9%）——用于一眼判断本机算力够不够；>1 慢、<1 快，不是实时利用率。
鼠标悬停徽标可看到 INT8 吞吐、FP32 峰值、显存、CUDA 计算能力、SM 数与估算用主频；
其中吞吐与系数为**估算值，非厂商标称算力**。CPU 环境会显示「未启用 GPU 加速」。

**Q：激活新版本后效果变差？**
「模型管理 → 版本历史」【回滚】一键回到次新版本；下次先用 A/B 对比验证再激活。激活前系统也会
自动验证，明显劣化会被阻止。

**Q：反馈提交了，模型什么时候生效？**
【标记误检/标记漏检/确认正确】提交后形成候选学习状态；生产反馈的 `candidate_queued/consumed=False`
表示仅候选隔离，不即时更新生产模型。点击【固化学习快照】只调用 consolidate 固化已有内存学习状态，
不自动消费所有候选反馈，不保证重训、激活或效果提升。候选构建、验收、批准、激活需分别完成。

**Q：固化学习快照后模型会自动更新吗？**
不会作此保证。固化学习快照只固化已有内存学习状态；候选构建、验收、批准、激活彼此独立，
不自动消费所有候选反馈，也不保证重训、激活或效果提升。需要更新生产模型时，按模型管理与评估看板流程分别完成验收、批准和激活。

**Q：gray（待复核）是什么意思？**
分数落在正常阈值与异常阈值之间的灰区，系统不强行二分类，标记为待复核并进入队列。人工判定后
作为候选学习状态，是校准与后续验收的重要学习信号。

**Q：数据安全吗？**
图像、视频、检测记录、反馈、版本快照均保存在本地 `storage/` 与 SQLite 中；DINOv2 权重随包
离线加载（缺权重时回退缓存/在线）。生产模式可开启 API Key 鉴权并关闭接口文档。

**Q：验收该看哪些指标？**
以本机「评估看板 → 延迟基准」与「精度评估」的实测输出为准，辅以「学习效果」的翻案率/增益与
「存档统计」的导出 CSV。**不要引用历史文档中的延迟数字**。

## 十、产线部署

### 10.1 API 鉴权（`security` 段）

`security.api_key` 默认空（关闭，开发用）。**产线必须通过环境变量注入密钥**：

```bash
# Windows PowerShell
$env:AOI_API_KEY="换成足够长的随机串"
python server.py

# Docker
set AOI_API_KEY=<强随机密钥>
docker compose up -d
```

**生产模式强制约束**（`AOI_PRODUCTION=1`，Docker 部署默认开启）：
- 未设置 `AOI_API_KEY` 时后端**拒绝启动**；
- API 文档（`/docs`、`/redoc`、`/openapi.json`）自动关闭；
- CORS 默认仅允许 `127.0.0.1` / `localhost`，跨域需用 `AOI_CORS_ORIGINS` 显式配置；
- 所有 REST 与 WebSocket 请求均需 `X-API-Key` 头。
密钥比较使用恒定时间比较防时序侧信道；桌面端 UI 自动读取（环境变量优先，其次同机 configs）。
`/api/file` 带路径白名单，仅放行 storage 目录内与已登记入库的图片/热力图。

### 10.2 多角色权限

用 `security.keys` 给不同岗位发不同密钥（角色 operator < engineer < admin）：

```yaml
security:
  keys:
    "产线操作员的key": operator     # 检测/反馈/查询
    "工艺工程师的key": engineer     # + 模型准备/扫描、自学习巩固、删图、孤儿清理
    "质量负责人的key": admin        # + 激活/回滚、删数据集批次
```

角色不足的请求返回 403 并注明所需角色；`keys` 非空即视为开启鉴权，单 `api_key` 命中者视为 admin。

**UI 角色化**：顶栏「角色」徽标展示当前角色（由 API Key 决定，**界面无切换入口**）。
**operator 仅保留 工作台 / 实时监控 / 标注反馈 / 存档统计 四项导航**；engineer/admin 全量可见。
被角色裁剪的页面即使被程序化跳转也会被拒绝。

### 10.3 对位偏移预警

模型准备时系统自动锚定首张训练正常图为对位参考。检测每帧估算相对参考的平移量，超过阈值
（`alignment.warn_px`，默认 4.0）时：响应带 `align_warn` 与 `align_offset`，监控页出现橙色
「对位偏移」徽标，并推送 webhook `align_warn` 事件。用于治具松动/传送带漂移的早期提醒，
不影响正常检测判定。

### 10.4 服务日志轮转

服务端日志落盘 `storage/logs/server.log`，单文件超 `logging.max_mb`（默认 10MB）自动轮转，
保留 `logging.backups`（默认 5）份历史（重启后生效）。

### 10.5 PLC 触发拍照检测

```yaml
plc:
  trigger_dir: "D:/aoi_trigger"   # 光电信号触发相机后的落图目录
```

对接流程：PLC 光电信号 → 相机拍照落图到 `trigger_dir` → 上位机/MES 调
`POST /api/detect/trigger`（form 参数 category）→ FIFO 取最早一张同步检测，节拍内返回判定结果 →
已检图自动移入 `trigger_dir/processed/`。每次触发记 `plc_trigger` 审计日志。
启用口径：`trigger_dir` 非空即启用。

### 10.6 缺陷自动归档

`archive.enabled: true`（默认开）时，判定命中 `archive.decisions`（默认 `anomaly` + `gray`）的帧
**不经人工反馈**自动拷贝到 `storage/archive/{品类}/{日期}/` 并登记入数据页（split=archive），
用于证据留存、质量复盘与训练回流。

### 10.7 产线日报与审计导出

- `GET /api/stats/export?days=30&category=<品类>` → 产线日报 CSV（BOM 头，Excel 直开）
- `GET /api/logs/export?action=<动作>` → 审计日志 CSV
- 桌面端「存档统计」页【导出 CSV】、系统设置页【导出 CSV】提供同样能力。

### 10.8 无头部署（无显示器产线服务器）

后端不依赖桌面 UI，可纯 API 运行：

```bash
docker compose up -d            # 或 python server.py
curl -H "X-API-Key: <key>" http://<server>:8017/api/health
```

全部操作（建源/导入/准备/检测/反馈/导出）均可由上位机经 REST 完成；UI 仅用于配置与复盘，
可装在任意能访问服务器的工位电脑上。
