# AOI_sys 用户视角操作流 Review

> 版本：v1.0（2026-08-26）· 视角：工业用户（部署工程师 / 产线操作员 / 质检管理员）
> 触发：对照 demo5《用户操作流说明》《用户操作流_外部认识》两份文档，反思 AOI_sys "功能都对、但跟操作流对不上"的系统性偏差。
> 结论先行：**系统功能覆盖已完整（M1-M15 对账全绿），但 UI 按"功能模块"组织，而用户按"时间顺序的工作流"思考。缺的不是功能，是"旅程编排"——首启引导、流程化导航、配置可视化、数据谱系。**

---

## 1. 问题定性：两种心智模型的错位

### 1.1 用户的心智模型（demo5 操作流定义的顺序）

```
① 部署准备 → ② 定数据：预训练用什么数据、持续学习数据从哪来、反馈模式怎么配
→ ③ 定功能：我要用哪些能力（视频？PLC？模板？通知？）
→ ④ 冷启动训练 → ⑤ 评估验收（达标才上线）
→ ⑥ 日常检测 → ⑦ 反馈学习（灰区复核/推荐复核/无法确认）
→ ⑧ 追溯举证（被质疑时查证据、导出）
```

这是一条**有因果链的时间轴**：每一步的输出是下一步的输入，每一步有明确的"准入条件"和"完成判据"。

### 1.2 系统的实际组织（8 个平铺功能页）

```
实时监控 │ 数据管理 │ 伪异常与增强 │ 标注反馈 │ 模型管理 │ 学习曲线 │ 评估看板 │ 统计报表
```

- 8 个页面**地位平等、无顺序、无依赖关系表达**；
- 首屏默认落在「实时监控」——一个**还没数据、没模型**的新用户，第一眼看到的是一个空转的检测台；
- 每个页面内部功能完备（M14/M15 已把 demo5 设计契约和操作流动作全部落进 UI），但**页与页之间的"接力"全靠用户自己知道**。

**一句话：系统把"工具箱"备齐了，但没有"工艺流程图"。工业用户打开系统，回答不了三个问题：我现在处于哪个阶段？下一步该做什么？做对了没有？**

## 2. 逐阶段对账

| 操作流阶段 | 用户期望 | 系统现状 | 差距 |
|---|---|---|---|
| ① 部署准备 | 打开就知道环境是否就绪（后端/设备/权重/配置） | 顶栏只有"后端已连接/CPU/GPU"；引擎配置、预训练权重、角色 keys 是否就绪无展示 | ⚠️ 中 |
| ② 定数据（预训练集 + 持续学习数据流 + 反馈模式） | 一个"数据规划"步骤：选/建品类 → 导入训练批次 → 声明后续数据怎么来（人工送检/PLC/视频）→ 配反馈模式 | 数据管理页能导入、有批次树、有分层徽章（M14d），但**"这批数据是给训练的还是给持续学习的"、"反馈数据回流到哪"无声明无展示**；反馈模式（即学开关/巩固策略/灰区阈值）只在 yaml | ❌ 大 |
| ③ 定功能（所需功能设定） | 部署级功能开关向导：视频/PLC/webhook/归档/多角色/告警阈值 | 全部在 `configs/default.yaml`（notify/plc/archive/security/logging 等 8 个段），UI 无任何设置入口 | ❌ 大 |
| ④ 冷启动训练 | 数据够了→引导去准备；准备时知道"还差什么" | precheck 体检在「模型管理→准备模型」对话框内，**用户得先自己知道要去模型页**；数据不足时无跨页引导（没有"差 20 张正常图，去导入→"按钮） | ⚠️ 中 |
| ⑤ 评估验收 | 训练完→自然引导到评估→达标才鼓励上线 | 准备完成后无"去评估"引导；评估不达标无"去伪异常补数据"引导 | ⚠️ 中 |
| ⑥ 日常检测 | 操作员首屏，状态一目了然 | ✅ 监控页本身成熟（三态/热力图/归因/对位/开放集徽标）；但它不该是**新系统的第一屏** | ⚠️ 排序问题 |
| ⑦ 反馈学习 | 待办驱动：今天要复核几条、推荐几条、有没有预警 | 反馈页有队列/推荐/横幅（M14c/M15b），但**没有"我的待办"聚合视图**——操作员要自己记得去哪个 Tab 看 | ⚠️ 中 |
| ⑧ 追溯举证 | 被质疑时一条链查到底：这张图→当时判定→依据→后来学没学会 | ✅ 追溯 Tab + TraceDialog + CSV 导出（M15d）；链路全但入口深（反馈页第三个 Tab） | ⚠️ 小 |

## 3. 核心不足清单（按严重度排序）

### R1 ❌ 无"系统阶段状态机"——用户不知道自己处在流程哪一环

新装系统和投产系统中的「实时监控」长得一样。用户无法区分：
- 数据还没导（阶段②没完成）
- 数据有了但模型没备（阶段④没完成）
- 模型备了但没评估验收（阶段⑤没完成）
- 已投产（阶段⑥）

**改进**：引入品类级"上线 readiness 状态机"：`未建品类 → 数据准备中 → 可训练 → 已训练未验收 → 已验收已激活（投产）`，在首屏和模型页显著展示。判据全部已有数据（precheck counts / 快照版本表 / 评估记录 / activate 状态），只需聚合透出。

### R2 ❌ 无首启向导（Onboarding）——"定数据、定功能"没有落点

操作流的第②③步（确定预训练数据集、持续学习数据流、反馈模式、所需功能）在系统里**没有对应的 UI 实体**。这是"对不上"感受的最大来源。

**改进**：首次启动（或新建品类时）弹出分步向导：
1. 品类名称 → 2. 训练数据从哪来（导入文件夹/MVTec/已有批次）→ 3. 上线后数据怎么来（人工送检/PLC 触发/视频流）→ 4. 反馈模式（谁来复核、灰区是否必审、是否自动归档）→ 5. 需要哪些能力（视频/通知/模板 L3）→ 6. 汇总确认 → 一键执行（导入+precheck+准备）。
向导产出物 = 品类配置档案（落库），后续可随时在设置里改。

### R3 ❌ 无设置中心——所有"模式配置"藏在 yaml

`default.yaml` 现有 system/pipeline/pseudo_anomaly/self_learning/evaluation/notify/security/logging/archive/plc 共 10 个配置段，工业实操中**阈值调整、反馈策略、通知地址、归档开关、角色 keys** 都是运维期高频动作，改 yaml + 重启不符合产线标准。

**改进**：新增「系统设置」页（admin 可见），分组表单化：检测阈值（tau/灰区）、反馈学习（即学开关/巩固提醒）、通知 webhook、PLC 触发目录、归档、角色 keys、日志。写回 yaml + 热生效（标注哪些项需重启）。

### R4 ⚠️ 导航顺序与流程相反

导航首项是「实时监控」，但流程上它是倒数第二步。数据（第2位）在伪异常（第3位）之前正确，但模型准备（第5位）在伪异常之后、评估（第7位）在模型之后隔了学习曲线——**新用户从左到右点一遍，恰好不是正确顺序**。

**改进**：两种方案——
- 轻量：导航按流程重排为 数据管理 → 伪异常 → 模型管理 → 评估看板 → 实时监控 → 标注反馈 → 学习曲线 → 统计报表，并分组加分隔（"准备期 / 投产期 / 复盘期"）；
- 彻底：加「工作台」首页（见 R5），导航保留现状（老手直达），首页承担流程引导（新手沿流程走）。**推荐后者**，不破坏已有肌肉记忆。

### R5 ⚠️ 无工作台首页——"今天该干什么"没有答案

操作员开机第一问："有没有要我处理的？" 系统里答案分散在：复核 KPI（反馈页）、推荐清单（要点按钮才知道）、不完备横幅（反馈页）、连续异常告警（webhook 里）、未巩固反馈（状态表）。

**改进**：新增「工作台」首页（operator 也可见的首屏）：
- 阶段状态条（R1 状态机，当前品类处于哪一环，下一步按钮直达）；
- 今日待办卡：待复核 N 条（点击直达）/ 系统推荐 M 条 / 不完备预警 / 连续异常告警；
- 今日运营快照：检测量/不良率/平均延迟/反馈数；
- 投产品类健康一览（当前版本/今日判对率/open 占比）。

### R6 ⚠️ 数据谱系断链——"这个模型是哪些数据训的"查不到

批次树（M8）和模型版本表各自完整，但**关联不可见**：
- 模型版本表只有 n_normal/n_defect 数字，没有"来自哪些批次"；
- 批次详情看不到"被哪个模型版本用过"；
- 反馈回流图进了"反馈回流"系统批次，但从模型侧看不到"v3 = v2 + 这 12 张反馈图"的谱系。

用户原话（M8 时期）："可别一堆不知来源的图堆在一起"——批次治理解决了"图的来源"，但**图的"去向"（喂给了哪个模型）仍是黑盒**。

**改进**：prepare/consolidate 时把使用的批次 id 列表记入 ModelVersion.meta；批次详情加"参与版本"；模型版本行加"数据谱系"展开（训练批次 + 各版本间反馈增量）。

### R7 ⚠️ 准备完成后的"下一步引导"缺失

prepare 完成 → 对话框关掉，用户自由发挥。正确链路应是：准备完成 →（建议）跑评估验收 → 达标 →（建议）激活并去监控试检 → 提示"误报了就打反馈"。每环都有现成页面，缺的是**串联按钮**（"去评估 →""去监控 →""去反馈 →"）。

**改进**：在准备完成结果、评估结果、激活成功三处加下一步引导按钮（纯 UI 串联，零后端改动）。

### R8 ⚠️ L0-L3 分层术语对操作员不友好

"场景分层 L0/L1a/L1b/L2/L3"是工程师语言。操作员/质检员视角的问题其实是："我有多少标注？"（只有正常图 / 有OK-NG标签 / 有缺陷框）。

**改进**：准备对话框在分层选项旁加一句人话翻译（现有"数据条件"列已部分做到），并把 precheck 建议语改为问题导向："检测到您只有正常图 → 建议零样本模式（L0）"。向导（R2）里则完全不出现 L 编号，只用问题勾选，内部映射到分层。

### R9 ⚠️ 配置类能力的"已启用状态"不可见

webhook 配没配、PLC 触发开没开、归档开没开、角色鉴权开没开——除了看 yaml 无处可查。运维排查时"我以为配了"类事故无法自检。

**改进**：设置中心（R3）落地后，每项带当前生效值只读展示 + 来源标注（yaml/env/默认）。轻量替代：系统信息端点扩展 `features` 段，工作台首页显示能力开关状态条。

### R10 ⚠️ 术语与入口深度

追溯链路（M7 的翻案曲线、TraceDialog）是交付亮点，但埋在反馈页第三个 Tab；评估页的鲁棒性/延迟基准分散。被客户质疑时"快速找到证据"的路径应该一键可达。

**改进**：监控页每条检测记录右键加"追溯此帧"直达 TraceDialog（跳过 反馈页→追溯Tab→找行 三级跳转）；工作台待办里"不完备预警"点击直达对应品类的追溯视图。

## 4. 改进方案总表（建议优先级）

| 编号 | 项 | 优先级 | 工作量 | 依赖 |
|---|---|---|---|---|
| R5 | 工作台首页（待办聚合 + 状态条 + 运营快照） | **P0** | 中 | R1 |
| R1 | 品类上线 readiness 状态机 | **P0** | 小 | 无（数据全在 DB） |
| R7 | 下一步引导按钮（准备→评估→激活→监控→反馈） | **P0** | 小 | 无（纯 UI） |
| R2 | 首启/新建品类向导（定数据+定功能） | P1 | 大 | R3 部分 |
| R3 | 系统设置中心（yaml 可视化） | P1 | 大 | 无 |
| R4 | 导航流程化分组（准备期/投产期/复盘期） | P1 | 小 | 无 |
| R6 | 数据谱系（批次↔版本双向可见） | P1 | 中 | DB meta 扩展 |
| R9 | 能力开关状态透出 | P2 | 小 | 无 |
| R8 | 分层术语人话化 | P2 | 小 | 无 |
| R10 | 追溯一键直达 | P2 | 小 | 无 |

**P0 三件套（工作台 + 状态机 + 引导按钮）即可消除"对不上"的主要体感**：用户打开系统第一眼看到"我在哪、该干啥、点哪去"，而不是一个空的检测台。

## 5. 不建议做的

- **不做向导强制化**：向导只在新品类/首启出现，老手可以全程跳过直达各页——工业系统忌"挡住熟手"。
- **不重做导航结构**：现有 8 页功能完整且已形成文档/手册，重排分组即可，不推翻。
- **不把配置全搬入 UI**：阈值/反馈/通知/角色等高频项进设置中心；引擎槽位级参数（coreset_size、epoch 等）保持 yaml——那是算法工程师的地盘，给操作员看见反而危险。
- **不引入账号系统**：M11c 的角色 key + M15c 的 UI 裁剪已够产线分级，完整登录/权限框架对本场景是过度工程。

## 6. 结论

AOI_sys 经过 M1-M15 对账，**功能层面对 demo5 设计契约和用户操作流的覆盖已经完整**（每一条操作动作都有对应 UI 入口）。当前"对不上"的体感来自**编排层缺失**：系统按功能模块平铺，用户按时间流程思考。补齐 P0 三件套（工作台首页 / 品类状态机 / 流程引导按钮）即可让系统从"工具箱"升级为"有工艺流程的生产系统"，且全部基于现有数据与页面，无需引擎改动。
