# 实测任务产物目录

任务定义见 `..\协同.md` 的“实测任务（TEST-xx）”一节。每个任务对应一个子文件夹，产物只能放进对应的文件夹。

## 每个任务文件夹必须包含的文件

| 文件 | 内容 |
|---|---|
| `result.md` | 结论（PASS / FAIL / BLOCKED）、关键数值、是否满足验收条件、已知偏差 |
| `env.json` | 机器、GPU 和驱动、CUDA/torch 版本、代码树（stable/dev）及 git 状态或文件哈希、快照/模型版本、settings 关键项、执行时间 |
| `cmd.txt` | 实际执行的命令，要能原样复跑 |
| `raw/` | 原始工件，例如逐图耗时 CSV、nvidia-smi 采样、日志、截图、EvalRun JSON。不接受只有汇总、没有原始数据的结果 |

## 规则

1. 测量只在稳定版 `stable_AOI_tree` 或隔离的 TEMP 副本上进行，不改生产 DB 或快照，不改开发版源码。
2. 样本用少量随机抽取，抽样方式和种子写进 `env.json`。遇到要求“全量”的情况先报告，不要直接跑。
3. 估算不能写成实测。拿不到的条件（例如原生 2500 图、授权视频、业务数值）一律标为 BLOCKED，并写明缺什么，不要拿替代口径凑数。
4. 涉及业务数值（FPR/召回预算、保留期等）的任务，agent 只出草案，最终取值由用户决定。
5. 完成后在 `协同.md` 中把该任务状态改为“待验收”，并附上文件夹路径。开发对话验收后回写“已验收 / 退回”，同时更新台账和权威清单。
6. 产物缺少 `env.json`、`cmd.txt` 或 `raw/` 中任一项，直接退回。
