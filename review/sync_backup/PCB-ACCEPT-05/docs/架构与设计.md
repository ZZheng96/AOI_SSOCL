# PCB_Ins v2 融合架构与设计

> 2026-08-28 立项 · 阶段 P0-P3（先跑通双检闭环）已完成
> 定位：融合 PCB_Ins（传统算法 PCB 检测）+ AOI_sys（特征学习通用检测）的工业级 PCB 检测系统。
> 用户从 PCB_Ins v2 进入，无感 AOI_sys 存在，但同一张图同时享有两套检测能力。

---

## 1. 系统定位

| 维度 | 说明 |
|---|---|
| 检测范式 | 双检并行：传统算法（模板差分，检具体缺陷类型）+ 特征学习（品类模型，检通用外观异常） |
| 入口 | 桌面 UI（后续阶段）+ REST API（现可用） |
| 服务形态 | FastAPI 单机内嵌（守护线程）/ 独立 server.py，端口 8022 |
| 模板 vs 品类模型 | **两个正交概念**：模板=金样板+检测项+ROI+参数（差分参考）；品类模型=特征库快照（特征参考）。AOI_sys 的 L3 场景也复用模板做 tpl 槽位差分 |

## 2. 架构分层

```
┌────────────────────────────────────────────────────┐
│ 服务层 app/api（FastAPI）                            │
│   /api/templates*   模板 CRUD/发布/绑定品类模型       │
│   /api/detect/*     dual / traditional / feature     │
│   /api/models/*     品类模型准备/版本管理             │
├────────────────────────────────────────────────────┤
│ 引擎层                                               │
│  ├─ 传统引擎 app/detect + app/inspect/service.py     │
│  │   门禁(gate) → 预处理 → 逐检测项（模板差分）        │
│  └─ 特征引擎 = 树干 AOI_Core（子进程 :8017）          │
│      app/engines/feature_client.py 仅 HTTP 调用       │
├────────────────────────────────────────────────────┤
│ 数据层                                               │
│  ├─ 模板库 templates/{id}/template.json（配方）       │
│  ├─ 品类模型/反馈库：仅在 AOI_Core（树枝不落模型）    │
│  ├─ 参数/标定 storage/recipes + storage/template_calib│
│  └─ 算法仓库 alg_repo/<name>（系统内预留，SMT 已入）   │
└────────────────────────────────────────────────────┘
```

## 3. 单图双检数据流

```
测试图
 ├─ [传统] run_gate 尺寸门禁 → 逐检测项（adapter 调 alg_repo 算法）→ DetectSummary
 └─ [特征] FeatureClient.predict_image_path(category) → HTTP AOI_Core → DetectionResult
 ↓
fuse_dual：engine_mode 决定组合
  dual      → 传统 NG 或 特征 anomaly → NG；均 OK → OK；gray 单标
  traditional/feature → 单引擎
 ↓
DualSummary{overall, traditional, feature, boxes, gray, elapsed}
```

实测（SMT 焊点示例，448px fast 工作点）：**单图双检 326-328ms**，满足 1s 红线预算。

## 6. 关键发现与修复（重要，后续参考）

1. **PCB_Ins 原版 scheduler 的 prefer_frozen 参数丢失 bug**（v2 已修）：
   `_resolve_params` 的 prefer_frozen 分支用 `_migrate()` 过滤参数，会把 `param_specs` 未声明的
   深层参数（SMT 的 `template_mode` / `mask_h_low` / `silk_*`）丢弃，导致模板冻结参数与实际
   判定不一致、特定图漏检。修复：模板冻结参数直接生效，不做 specs 过滤。
2. **PCB_Ins 原版 smt_adapter 缺 default_config 为底**（v2 已修）：cfg 只放 detect 标志 + 冻结
   参数，缺大量默认键（auto_resize 开关等）行为异常。修复：以 `default_config()` 为底。
3. **pad 取整方式 1px 敏感**（v2 已修）：算法对 pad 边界极敏感，`round(81.77)=82` 与
   `floor=81` 导致同一张 NG 图判定完全不同。修复：`_smt_pads` 统一 floor，与算法作者
   test_images 的 labelme pad.json 转换方式一致。
4. **红线数据域要求**：demo5 `guard_bundle` 要求 `init_normal` 路径含 `train` 目录段。
   API 层负责把用户图整理到 `storage/train/{category}/normal|defect/`（v2 已实现于
   `/api/models/prepare`），不要求用户按赛题目录组织。

## 14. 系统不足评估（2026-08-30）

对比 reference5 PCB_Ins、pcbdetect、UI算法/Java AOI 上位机的不足结论与改进优先级（供后续阶段决策）：

### 14.1 vs reference5 PCB_Ins（功能超集，资产缺口）
- 测试资产未迁移：PCB_Ins 的 input/roi（37 张）、template_calib（7 组标定）、标准板图未搬入
- 旧模板 ID 体系不通用（templ_* 系列不能直接复用）
- detect_page 调试页未对 13 项新算法逐项验证调参链路
- recipes 参数仅 SMT 四类迁入，新算法默认参数未沉淀

### 14.2 vs pcbdetect（工程治理层差距）
- 无常驻 Worker + 优先级队列；无进程隔离/崩溃重建/优雅停机
- 无共享内存零拷贝（图像走磁盘+HTTP）
- 无 submitFov 快返回 + 流式推送（一次性 POST 同步等待）
- 算法池无超时/重试；模板无快照热切换

### 14.3 vs Java AOI 上位机（工业现场层差距最大）
- **硬件/产线**：无相机/光源/轨道/读码器对接；无板级流程状态机（进板→Mark→Barcode→逐 FOV→出板）；无 TOP/BOTTOM 双面；无 3D 检测
- **数据/业务**：无板级 inspect/defect 明细表（缺陷从 dual_json 提取）；无双坐标体系（pxPerMM）；无标定工具；无不良过滤/锁定/告警；无权限/审计
- **业务端**：无四端解耦（编程/执行/复判/配置）；无 CAD 导入/拼板/FOV；无 MES 对接；图片存储无管理

### 14.4 改进优先级
- P0（检测正确性）：对位/Mark 体系（复用金手指 peizhun）、板级数据模型（inspect/defect）、缺陷明细落表
- P1（工程骨架，借鉴 pcbdetect）：常驻 Worker + 优先级队列、算法超时重试、结果流式推送
- P2（工业现场，借鉴 Java AOI）：双坐标+标定工具、不良过滤/告警/权限、MES 接口抽象、CAD/拼板/FOV
- 取舍：硬件层取决于产线形态；v2 当前聚焦算法闭环是合理阶段

### 16.5 重要发现与修复（本任务核心 bug）
- **PySide6 `QPainter.drawPixmap` 崩溃**：`drawPixmap(ox, oy, w, h)` 在 PySide6 中无此
  重载（第 5 参必须是 pixmap），paintEvent 抛 TypeError 且 painter 未释放 →
  `QBackingStore::endPaint() called with active painter` → 进程 abort（exit code
  3221225477）。症状："点击应用到模板后进程消失"。修复：补第 5 参 `self._pixmap`。
  **教训：Qt 重绘/槽函数里任何 Python 异常都会静默杀掉进程（无 traceback）**，
  新写 paintEvent 后必须先用真实窗口触发重绘验证，不能只看语法。
- **PySide6 槽函数异常 → abort**：Python 异常穿过 Qt 事件循环边界默认 std::terminate。
  已对调参应用入口加 try/except 兜底（打印 traceback + 提示框），避免整机闪退。
  建议后续给 main.py 安装全局异常钩子（sys.excepthook + qInstallMessageHandler）。
- **HSV 参数归属**：solder_blue_* 等颜色参数挂"共用参数"层而非具体缺陷算法，调参
  对话框的 discover 必须同时扫 shared_param_id，否则注册不到对象。
