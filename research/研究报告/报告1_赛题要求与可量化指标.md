# 报告一：赛题要求解析与可量化指标

> 赛题：可自学习的AOI实时在线AI质检（第八届中国研究生人工智能创新大赛 · 华为赛题一）
> 来源：赛题文档《可自学习的AOI实时在线AI质检.md》及附件

---

## 一、题目背景与总体目标

### 1.1 行业痛点

在制造业产品缺陷检测中，传统方案依赖**计算机视觉算法 + 人工检测**。每出现一种新缺陷，都需要在**极少样本（1-2 张）**下重新开发算法拦截，成本高、周期长、泛化差。

### 1.2 赛题目标

开发一套 **AI 驱动的实时质检系统**，基于 AOI（Automated Optical Inspection，自动光学检测）技术：

- 在组装过程中**即时监测**组件状态（屏幕、电池、中框等）
- 实现不良事件的**早期拦截**
- 处理**视频或图片**数据
- 识别异常模式并**动态优化模型**

### 1.3 核心定位

本赛题不是单纯的"分类/检测"竞赛，而是一个**端到端的工业质检系统设计题**，强调实时性、少样本冷启动、持续学习三大工程能力。

---

## 二、四大核心技术要求

### 要求 1：实时视频/图片异常检测

| 维度 | 具体要求 |
|------|----------|
| 检测对象 | 尺寸偏差、缺件少件、逻辑错误（如顺序错误）、色彩变化、常见外观缺陷 |
| 输入模态 | 必须同时覆盖**视频输入**与**图片输入**两种场景 |
| 输入规格 | 2500 × 2500 像素图片 |
| 硬件约束 | RTX 2060 及以下 GPU |
| **硬性指标** | 模型运行时间 **< 200 ms** |
| **挑战目标** | CPU 上运行时间 **< 2 s** |

> ⚠️ 关键解读：2500×2500 是相当大的输入（625 万像素），在 2060 级别 GPU 上做到 <200ms 推理，意味着必须采用**轻量化模型 + 高效特征提取**策略，不能直接套用大模型。

### 要求 2：少样本或无样本启动与泛化

| 维度 | 具体要求 |
|------|----------|
| 痛点 | 工业场景异常样本获取难度高 |
| 启动条件 | few-shot（少样本）或 zero-shot（无样本）下快速部署 |
| 建议技术 | ① 迁移学习（从相关任务预训练）；② 合成数据生成（如 GAN 模拟缺陷）；③ 在线学习适应新环境 |

### 要求 3：用户反馈驱动的优化

| 维度 | 具体要求 |
|------|----------|
| 触发条件 | 系统误检或漏检时，操作员提供实时反馈（如标记漏检） |
| 系统行为 | 回溯检测逻辑，动态调整模型参数 |
| 建议技术 | 强化学习 或 主动学习（Active Learning） |

### 要求 4：可解释性

| 维度 | 具体要求 |
|------|----------|
| 交付物 | 算法模型的可解释性文档 |
| 内容 | 系统阐述方案选型依据，附数据/图片等论据 |

## 三、评测协议（关键！）

### 3.1 测试集运行流程

赛题给出了一个非常具体的评测协议，这是设计的**核心约束**：

```
┌─────────────────────────────────────────────────────────────┐
│  阶段 1：迁移学习（测试集运行前）                                │
│  ├── 100 张带标注的【无缺陷】图片或视频                          │
│  └── 30 张【有缺陷】图片或视频                                   │
│         ↓ 用于迁移学习/微调模型                                  │
│                                                              │
│  阶段 2：测试集评估                                              │
│  └── 1000+ 张图片用于测试                                        │
└─────────────────────────────────────────────────────────────┘
```

**关键解读**：
- 训练阶段**只有 100 正 + 30 异**的标注样本 → 这是典型的**少样本监督异常检测**设定
- 测试集 1000+ 张，规模远大于训练样本 → 考验泛化能力
- 30 张异常样本远少于 100 张正常样本 → **类别极度不平衡**

### 3.2 评分构成

```
总分 = 竞赛得分 × 60% + 专家评分 × 40%
```

#### 竞赛得分（60%）细分

| 子项 | 权重（占竞赛得分） | 权重（占总分） | 说明 |
|------|-------------------|---------------|------|
| 方案完整度 | 50% | 30% | 方案设计的完整性、合理性 |
| 答案准确率 | 20% | 12% | 在非公开测试集上的检测准确率 |
| 检测时间 | 30% | 18% | 推理速度，越快得分越高 |

#### 专家评分（40%）

由评委组对方案的新颖性、合理性等进行打分。

### 3.3 提交物清单

| 提交物 | 用途 |
|--------|------|
| ① 模型代码 | 用于非公开测试集评估 |
| ② 模型使用说明文件 | 报告模型方案 + 公开测试集上的结果 |
| ③ 可解释性文档 | 阐述方案选型依据 |
| ④ 项目文档 | 按大赛模版撰写 |

> 鼓励使用**小模型**——这一点与"检测时间占 30%"的评分项高度一致。

## 四、可量化指标汇总表

将所有要求转化为可量化的验收指标：

### 4.1 性能指标

| 指标编号 | 指标名称 | 量化标准 | 约束条件 | 优先级 |
|---------|---------|---------|---------|--------|
| P-01 | GPU 推理延迟 | < 200 ms | 2500×2500 输入，RTX 2060 及以下 | ⭐⭐⭐ 硬性 |
| P-02 | CPU 推理延迟 | < 2 s | 2500×2500 输入 | ⭐⭐ 挑战目标 |
| P-03 | 检测准确率 | 越高越好 | 1000+ 测试集 | ⭐⭐⭐ 占分 12% |
| P-04 | 检测速度排名 | 越快越好 | 相对其他参赛者 | ⭐⭐⭐ 占分 18% |

### 4.2 数据与训练指标

| 指标编号 | 指标名称 | 量化标准 | 说明 |
|---------|---------|---------|------|
| D-01 | 正常样本用量 | ≤ 100 张 | 迁移学习阶段 |
| D-02 | 异常样本用量 | ≤ 30 张 | 迁移学习阶段，极度少样本 |
| D-03 | 测试集规模 | 1000+ 张 | 评估泛化能力 |
| D-04 | 冷启动能力 | zero/few-shot 可部署 | 无样本或极少样本下启动 |

### 4.3 功能指标

| 指标编号 | 指标名称 | 量化标准 | 说明 |
|---------|---------|---------|------|
| F-01 | 输入模态覆盖 | 图片 + 视频 | 两种模态均需支持 |
| F-02 | 缺陷类型覆盖 | ≥ 5 类 | 尺寸偏差/缺件少件/逻辑错误/色彩变化/外观缺陷 |
| F-03 | 反馈闭环 | 支持在线更新 | 误检/漏检后可动态调整 |
| F-04 | 可解释性 | 提供决策依据 | 输出异常区域定位/原因 |

### 4.4 评分权重指标

| 维度 | 子项 | 占总分 | 备注 |
|------|------|--------|------|
| 竞赛得分 60% | 方案完整度 | 30% | **最大单项**，文档与方案设计至关重要 |
| | 检测时间 | 18% | 速度直接影响得分 |
| | 答案准确率 | 12% | 准确率权重低于速度和方案 |
| 专家评分 40% | 新颖性 + 合理性 | 40% | 评委主观打分 |

## 五、关键约束与设计启示

### 5.1 三大约束的"不可能三角"

```
        准确率 (12%)
           /\
          /  \
         /    \
        /      \
       /________\
  速度 (18%) —— 方案完整度 (30%)
```

**核心洞察**：
- 准确率权重（12%）**低于**速度权重（18%）→ 不能为了精度牺牲速度
- 方案完整度权重最高（30%）→ **文档与系统设计是得分大头**
- 专家评分 40% → **创新性和合理性**同样重要

### 5.2 少样本设定的本质

训练阶段 100 正 + 30 异 的设定，意味着：

| 传统监督学习 | 本赛题设定 |
|------------|-----------|
| 大量标注样本 | 极少标注（130 张） |
| 类别平衡 | 100:30 不平衡 |
| 封闭集（已知所有类别） | **开放集**（测试集可能出现未见缺陷） |

→ 这正是参考文献 AHL 论文研究的 **OSAD（Open-Set Supervised Anomaly Detection）** 问题！

### 5.3 设计启示清单

1. **模型必须轻量**：2500×2500 在 2060 上 <200ms，建议参数量 < 50M，优先考虑 EfficientAD 类架构
2. **特征提取要高效**：可考虑预训练特征 + 轻量检测头，避免端到端训练大模型
3. **少样本是核心**：30 张异常样本 → 必须用迁移学习/合成数据/开放集方法
4. **速度优先于精度**：在速度和精度间权衡时，倾向速度（18% vs 12%）
5. **文档要详尽**：方案完整度 30% + 专家 40% = 70% 是"软实力"分，文档质量决定成败
6. **支持视频**：需设计时序处理能力（关键帧抽取 / 轻量时序模型）
7. **反馈闭环**：设计主动学习管线，支持人工标注回流

## 六、风险与注意事项

| 风险点 | 说明 | 应对 |
|--------|------|------|
| 测试集非公开 | 无法提前验证，只能用公开数据集模拟 | 用 DAGM/MVTec 严格遵循 100+30 协议验证 |
| 输入尺寸大 | 2500×2500 远大于常见 256/512 | 需分块/滑窗或高效下采样策略 |
| 硬件限制 | 2060 显存 6GB | 控制 batch size，优化显存占用 |
| 视频模态 | 时序处理增加复杂度 | 抽帧 + 图片检测，或轻量 3D 卷积 |
| 评分主观性 | 专家评分 40% | 方案要有创新点和故事性 |

---

## 七、总结

本赛题是一个**工程导向的系统设计题**，核心矛盾在于：

> **在极少样本（100+30）和严格硬件约束（2060/<200ms）下，实现对未知缺陷的高准确率检测，并提供可解释、可进化的完整系统。**

量化指标的优先级排序为：**方案完整度（30%）> 专家评分（40%含新颖性）> 检测速度（18%）> 准确率（12%）**。

这意味着：一个**设计精良、有创新点、文档完善、速度够快**的方案，比一个单纯追求精度榜一名的方案更可能获胜。
